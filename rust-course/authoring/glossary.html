Precise language, plain explanations

Glossary

Search the course for a term to find its project context. Definitions describe the concept; each lesson states the exact contract used by its code.

ABI

Application binary interface: the machine-level agreement for calling a function across a compiled boundary.

actor

An identity used to decide which operations are authorized; a domain actor is distinct from a background task.

allocation

Reserving a region of memory through an allocator. Its physical placement is not determined solely by a Rust type name.

AST

Abstract syntax tree: structured data representing the meaning and nesting of parsed syntax.

async

Code that returns a future whose execution can suspend while waiting, allowing other work to progress.

atomic

An operation observed indivisibly for the relevant memory location or transaction contract; the word needs its scope stated.

authentication

Establishing an identity. It is separate from deciding what that identity may do.

authorization

Checking whether the current identity may perform a particular action on a particular resource.

backpressure

A way for a bounded consumer to slow or reject producers rather than accumulate unlimited work.

borrow

Temporary access to a value owned elsewhere, checked against rules for aliasing, mutation and validity.

cancellation

A request to stop work; the contract must state when it is observed, what is rolled back, and what can already have happened.

capacity

An explicit upper resource limit, such as queued items, active tasks or initialized array slots.

checksum

A computed value used to detect some accidental corruption; an ordinary checksum is not a cryptographic authenticity proof.

closure

A callable value that can capture values from its surrounding scope, with ownership appropriate to its use.

coherence

Rules ensuring that trait implementation selection is consistent across crates.

compaction

Rewriting persistent state into a smaller equivalent representation while preserving a declared recovery contract.

consensus

Agreement among participants under a specified failure model; a demonstration of replication is not automatically consensus.

crate

A Rust compilation unit, either a library or an executable. A Cargo package may contain several targets.

deadline

The latest permitted completion time for a whole operation or specified phase; distinguish it from repeated per-attempt timeouts.

deadlock

A cycle or blocked dependency in which participants cannot make progress, even if memory accesses are safe.

deduplication

Recognizing a repeated operation by stable identity so that the intended effect is not applied twice within the stated scope.

DOM

Document Object Model: the browser object tree representing a document and its interactive elements.

drop

The end of an owned value’s lifetime, when its destructor releases resources according to its type’s contract.

durability

A persistence promise across specified failures. Writing, flushing and synchronizing provide different evidence.

edition

A selected set of Rust language compatibility rules for one crate, separate from the compiler release.

enum

A type whose value is one of a defined set of variants, optionally carrying associated data.

FFI

Foreign function interface: calling or exposing functions across language boundaries with explicit ABI and safety contracts.

framing

Defining where messages begin and end in a byte stream such as TCP.

future

A value representing asynchronous work that advances when polled and may report Pending before completing.

generic

Code parameterized by a type, lifetime or const value so one implementation can express several concrete cases.

heap

A conceptual name for allocator-managed storage; optimizer behavior and actual placement require separate reasoning.

hydration

Attaching client-side interactive behavior to HTML produced by server rendering.

idempotency

A contract under which repeating an identified operation has the same intended effect as applying it once.

invariant

A property that must remain true across every accepted state transition.

isolation

Rules controlling how concurrent transactions observe and affect one another.

iterator

A stateful producer of a sequence of values, commonly advanced lazily by a consumer.

lease

Time-bounded permission to act, whose expiry, clock assumptions and fencing rules must be specified.

lifetime

A relationship describing how long a reference remains valid; annotations do not keep dead owners alive.

linearization

Choosing a conceptual instant when an operation takes effect for a specified concurrent history.

lockfile

A record of resolved dependency versions used to reproduce a build; it does not guarantee absence of vulnerabilities.

mise

The course’s tool-version manager; mise.toml pins Rust and mise exec selects it for commands.

monomorphization

Compiler generation of concrete code for generic type instantiations, with possible code-size and optimization effects.

move

Transfer of ownership, after which the source binding cannot be used as the former owner unless the type is Copy.

MSRV

Minimum supported Rust version: a compatibility claim that requires its own testing scope.

mutex

A synchronization primitive allowing one holder at a time to access protected state.

newtype

A local wrapper type that gives an existing representation a distinct domain meaning and API boundary.

no_std

A crate mode using core instead of the full standard library; it does not by itself provide a firmware runtime.

ownership

Rust’s model for responsibility over values, their access and resource release.

panic

Abnormal control flow for violated assumptions or unrecoverable situations; ordinary input failures generally belong in Result.

pinning

A contract preventing certain values from being moved through a pointer, needed by some address-sensitive state.

polling

Asking an operation to make progress; browser periodic polling and Rust Future::poll are different mechanisms.

RAII

Resource acquisition is initialization: owned values acquire resources and release them in Drop.

replay

Re-applying recorded events in a defined order to reconstruct or study state.

schema

A contract describing data shape and constraints, whether for a database, a file or an API.

semaphore

A resource counter limiting the number of concurrent holders; a permit represents one share of that budget.

slice

A borrowed view of contiguous elements, carrying a pointer and length under its validity contract.

SLO

Service-level objective: a measurable target for a defined user-visible behavior over a stated window.

stack

A conceptual model for call-local storage and frames, not a guarantee that every local Rust value occupies a physical stack slot.

struct

A type grouping named fields under one representation and API.

TCP

An ordered reliable byte-stream transport between endpoints; it does not preserve application message boundaries.

TLS

A protocol providing authenticated encrypted transport under its certificate and endpoint trust assumptions.

trait

A named interface or set of capabilities that a type can implement.

transaction

A grouped state operation with declared atomicity and isolation semantics; it is not automatically serializable.

UTF-8

A variable-length encoding of Unicode scalar values. Byte offsets are not interchangeable with character positions.

WASM

WebAssembly: a portable executable format used here inside the browser’s capability and event-loop model.

zero-copy

A claim that specified data copies are avoided across a named boundary; it does not mean zero allocation or zero work.

Protocol failure laboratory

This is an intentional runtime test failure, not an intentional compile error. Rust's type system permits a protocol parser that consumes too few bytes. Your job is to demonstrate why it fails and correct the boundary.

Specification

Consume exactly the declared payload length, reject lengths outside1..1024 before allocation, and reject invalid UTF-8. An incomplete payload must return UnexpectedEof. First predict the broken test's actual string.

Run

Working directory: the course root. Place disposable binaries in the shared verification cache, outside the portable content.

mkdir -p ../.course-cache/exercises
mise exec -- rustc --edition 2024 --test exercises/services/partial-read-broken.rs -o ../.course-cache/exercises/partial-read-broken
../.course-cache/exercises/partial-read-broken

Expected: compilation succeeds; test exits nonzero because it decodes only “h”. Do not count this expected failure as a broken reference project.

Hint1

Read the return contract of std::io::Read::read. Is a short successful read an error?

Hint2

Separate the length budget from the operation that fills the buffer. A loop must handle end-of-file correctly.

Worked solution

The solution source checks the budget and calls read_exact. It preserves the full payload and rejects a truncated stream. Compile it with the same command using the solution filename; its two tests should pass. Explain why merely retrying once is still insufficient.

Investigation record

Observation: the returned text has one ASCII byte. Guess: encoding error. Distinguishing experiment: the custom reader intentionally returns one byte per call, even for ASCII. That disproves encoding as the cause. The fix fills the declared frame before decoding. Its limit: framing length still comes from a separate validated header; read_exact does not invent a protocol or a deadline.

Mastery

Implement a second reader that alternates one-byte and two-byte fragments. Your decoder must not depend on a specific fragmentation pattern. Ask for review with the exact fixture and a trace of bytes consumed.

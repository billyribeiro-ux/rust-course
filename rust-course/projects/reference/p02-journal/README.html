Use a scratch path for add/done/remove so the checked-in fixture remains unchanged. Missing files represent an empty journal; permission errors do not. A 1 MiB file limit and 10000-task limit bound ingestion. Single-writer temporary-file rename reduces partial writes but provides neither multi-process locking nor a full crash-durable transaction. Removing the largest ID permits later ID reuse; IDs identify the current file, not a global history.

Run `mise exec -- cargo test -p task-journal` for unit, integration, and documentation tests. Read `src/lib.rs` before `src/main.rs`: the library defines behavior; the binary owns argument parsing and exit status.

Engineering decisions and evidence are taught in the HTML course lesson and in `decisions.html`; these include current invariants, chosen design, concrete habits, alternatives, actual verification, and evolution thresholds.

Output errors and evidence

Normal output uses fallible writeln! and an explicit flush. Closed output pipes return process failure instead of panicking. If stderr itself fails, the final diagnostic is best effort and failure remains visible through the exit status. The actual OS-pipe follow-up records normal and failed-output checks; independent review remains pending.

An add operation saves before acknowledging its ID. Failure to print that acknowledgement does not roll back a successful save. Inspect the journal before retrying an uncertain add; the regression confirms the saved task survives the failed output.

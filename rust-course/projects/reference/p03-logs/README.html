Bounded log search and summarization

Working directory: the course's projects/ folder. All dependencies are in the standard library.

mise exec -- cargo run -p log-detective -- reference/p03-logs/fixtures/sample.log
mise exec -- cargo run -p log-detective -- --contains api reference/p03-logs/fixtures/sample.log
mise exec -- cargo run -p log-detective -- --contains unavailable --max-bytes 10737418240 /path/to/large.log
mise exec -- cargo run -p log-detective -- --help
mise exec -- cargo test -p log-detective --locked

The third command is a usage template: replace the path with your own input. Its explicit budget is 10 GiB, not a promise that the local verification generated a 10 GiB file.

Without --contains, stdout contains exactly:

lines=5 valid=4 malformed=1 oversized=0 info=2 warnings=1 errors=1

The api search emits these two valid records to stdout:

100 INFO api ready
102 ERROR api upstream unavailable

Its stderr summary contains the same totals plus matched=2. cargo run may also print Cargo's own build messages on stderr. For machine consumers, invoke the built binary directly. Zero matches is a successful scan. Routine errors exit with status 1; help exits with status 0. Options precede the path. Use - for stdin and -- before a path beginning with a dash.

Supported format and search

Each record is an unsigned timestamp, uppercase INFO/WARN/ERROR level, ASCII service identifier, and nonempty message. Single spaces separate the first fields. CRLF is accepted. Messages may contain Unicode but not control characters. Search is a case-sensitive literal substring of the entire valid record, including fields. There are no regular expressions, case folding, Unicode normalization or secret redaction. For example, precomposed café differs from cafe followed by a combining accent. A query must be 1–4096 UTF-8 bytes and contain no controls.

Matching lines are emitted immediately with LF endings. They are not byte-for-byte raw copies: a CRLF becomes LF, and a final unterminated line receives LF. Malformed UTF-8, malformed grammar and oversized lines are counted but never emitted. The summary includes all input records, not only matches.

Resource and failure contract

The default line limit is 4096 bytes before LF, counting CR if present. The default total-byte budget is 67,108,864 bytes (64 MiB). --max-bytes N accepts positive decimal u64 values so a much larger local file can be processed without retaining it. Every consumed byte counts, including delimiters and discarded oversized data. Reader prefetch may read ahead into its bounded buffer before exhaustion is detected. The library also accepts a 1–1,048,576-byte line limit; the CLI keeps the 4096-byte policy.

Memory retained by the algorithm scales with the line bound, fixed counters and bounded query, not file length or service-name count. The file CLI additionally uses an 8192-byte BufReader. Vec capacity, allocator overhead and operating-system buffering are additional memory. A supplied library reader or output writer can itself retain data; choose bounded implementations. The streaming output may already contain a prefix if a later read, budget, write or flush fails. Such failure produces no successful summary and exits nonzero. Treat output as incomplete until the exit status is known. The byte budget provides neither a time deadline for slow input nor an atomic output file.

Read the library, the CLI, engineering decisions and the exact follow-up evidence. The generated-reader test processes 67,109,888 bytes from one 1 KiB record and a 257-byte reader; it is not a peak-memory benchmark. Independent review remains pending.

Core lab engineering decisions and evidence

These are small standalone boundaries, not new production applications. Recommended code is safe Rust, uses the standard library, states its accepted inputs and failure outcomes, and keeps mutable representations private where that protects an invariant. Deliberate learner mutations are separately labeled and exercised only in temporary copies.

Collections

The report accepts at most 64 input labels, eight distinct keys and sixteen ASCII lowercase bytes per label. A HashMap answers keyed-count questions; a sorted owned vector provides a stable external order and independent output lifetime. A borrowed slice avoids requiring array or vector ownership for read-only extrema. BTreeMap or a small linear representation are reasonable alternatives; no comparative performance claim is made. An unbounded stream would require a new retention and overflow policy, not removal of the existing caps.

Conversions

Percent privately stores only 0..=100. TryFrom is the sole general numeric admission path; From expresses lossless extraction. FromStr validates spelling and delegates the range rule. Result collection preserves the first failure, and selection preserves order and duplicates. A local helper is simpler for a one-use rule; a validated type is useful once several functions should require the same invariant. Fractional percentages would justify an explicit scale or another numeric model. The current constructor's narrowing cast is preceded by a range proof.

Interior mutability

Two retained synchronous handles share one buffer through Rc. Cell fits the independent Boolean flag; RefCell supplies temporary checked vector access. The buffer caps four messages of 64 bytes each. Runtime borrow conflicts are explicit Results, and the record path calls no external callback while mutably borrowed. Plain exclusive ownership is preferable if independently retained handles are unnecessary. Cross-thread or async requirements demand a new synchronization and lifecycle contract; substituting Arc alone is insufficient. Snapshots copy bounded data to release dynamic borrows before reentrant work. Weak observer handles deliberately do not extend buffer lifetime, and upgrading returns an optional strong owner. The buffer stores no callbacks or back-references, so its current ownership graph has no cycle; a future callback registry must specify which links own their targets.

Actual verification and limits

Author tests cover empty and boundary collections, deterministic ordering, output ownership, numeric and grammar boundaries, failure precedence, preserved filtering semantics, shared state, disabled/invalid distinctions, capacity, reentrant conflicts, borrow release during unwind, and weak-observer expiry after the final strong owner drops. Executable documentation tests the public percentage constructor, rejects its private tuple representation, and rejects transferring the Rc-backed handle into another thread. Separate checks run strict Clippy, each executable, all three reconstructed standalone packages, refusal of existing destinations, a narrowing-before-validation failure, and a borrow_mut panic mutation. The HashMap-order exercise is a documented-contract review, not an assertion that every unsorted run must visibly differ.

These checks do not establish every possible callback behavior, a performance advantage, crash persistence, browser operation or learner competence. Independent review remains pending. Return to run and reconstruction instructions.

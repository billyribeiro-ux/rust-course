Engineering decisions and evidence

Requirements and invariants

Resolve defaults < file < environment < command line, reject unknown or duplicate keys within one layer, then validate effective values. Constructed ports are nonzero, timeouts and connection counts are bounded, hosts are IP addresses, and ordinary formatting/errors do not expose tokens. An explicitly empty token differs from an absent token.

Chosen design and concrete habits

Raw Layer and validated Config are separate types. Layer::environment takes injected pairs for parallel-safe tests instead of mutating process environment. Private fields and NonZeroU16 protect accepted state. Secret implements redacted Debug; errors identify keys and rules without echoing input. Normal parsing and IO failures use Result from the first recommended checkpoint, including documentation examples.

Meaningful alternative and evolution threshold

Validating each raw layer before merge is defensible when stale invalid configuration must be rejected even if overridden; it is a different policy and needs different tests. A schema library becomes useful for nested structures and source-location diagnostics. Required credentials, zeroization, or a real secret provider require explicit new guarantees; this redaction wrapper does not encrypt or erase memory.

Actual checks and remaining uncertainty

Native precedence, boundary, redaction, controlled-child-environment CLI, and documentation tests passed in verification/native-tests.log and passed again in verification/patch001-foundations-tests.log after the patch audit. Tested output paths omit synthetic token markers. The CLI skips non-Unicode environment pairs, and future hand-written logging can still expose values deliberately. Independent review remains pending.

Output errors and evidence

Normal output uses fallible writeln! and an explicit flush. Closed output pipes return process failure instead of panicking. If stderr itself fails, the final diagnostic is best effort and failure remains visible through the exit status. The actual OS-pipe follow-up records normal and failed-output checks; independent review remains pending.

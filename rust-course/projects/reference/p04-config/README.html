Validated layered configuration

From `rust-course/projects`:

mise exec -- cargo run -p typed-config -- --file reference/p04-config/fixtures/app.conf --set port=9100

Expected:

Config debug output includes port 9100 and a redacted optional token.

Precedence: defaults < file < APP_* environment < --set. Unknown and duplicate keys in a layer fail; semantic validation happens after merging, so a corrected higher-precedence value may replace an invalid lower one. Tokens are redacted from Debug and errors; they are not encrypted or zeroized. The CLI reads at most 16385 bytes to detect the 16 KiB file limit. Do not put actual tokens in shell history.

Run `mise exec -- cargo test -p typed-config` for unit, integration, and documentation tests. Read `src/lib.rs` before `src/main.rs`: the library defines behavior; the binary owns argument parsing and exit status.

Engineering decisions and evidence are taught in the HTML course lesson and in `decisions.html`; these include current invariants, chosen design, concrete habits, alternatives, actual verification, and evolution thresholds.

Output errors and evidence

Normal output uses fallible writeln! and an explicit flush. Closed output pipes return process failure instead of panicking. If stderr itself fails, the final diagnostic is best effort and failure remains visible through the exit status. The actual OS-pipe follow-up records normal and failed-output checks; independent review remains pending.

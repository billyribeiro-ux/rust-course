Checked calculator and approximate length converter

Working directory: rust-course/projects.

mise exec -- cargo run -p workshop-calculator -- 12m + 3m
mise exec -- cargo run -p workshop-calculator -- convert 1.5m cm
mise exec -- cargo run -p workshop-calculator --example roundoff

The first two commands print 15m and approximately 150cm. The roundoff example prints the result of adding 0.1 and 0.2 with 17 decimal places and compares it to 0.3.

Two explicit numeric contracts

Arithmetic uses i64 and checked operations. Addition and subtraction require identical units; multiplication requires a scalar; division accepts a scalar divisor or identical units. Division truncates toward zero. Composite units and fractional arithmetic remain outside this operation's contract.

The convert subcommand accepts a signed fractional or scientific-notation number immediately followed by mm, cm, m, or km, plus a separate target unit. Its validated Length uses finite f64. Numeric input is capped at 128 bytes including the unit. NaN, infinity, unsupported units, overflow, and a nonzero input rounding to zero during parsing or scaling are errors. Explicit zero, negative zero, and finite nonzero subnormal values are allowed. Values and ratios can round, so results are labeled approximate; this is not an exact decimal or money calculator.

The program exits two for bad argument count or non-Unicode textual arguments, one for parse, domain or output errors, and zero on success. If a usage diagnostic itself cannot be written, the output failure also returns one. Diagnostics use stderr. Output failure can leave a partial stdout result, so check the exit status before trusting it. Existing arithmetic invocations keep their original behavior.

Read and verify

Read src/lib.rs for checked integer arithmetic, src/conversion.rs for the separate conversion model, and src/main.rs for routing, output, and exit status. Run mise exec -- cargo test -p workshop-calculator. The course's 00-calculator and 00-conversions lessons explain the two checkpoints. Engineering decisions and evidence records invariants, design choices, meaningful alternatives, checks, and limitations.

Output errors and evidence

Normal output uses fallible writeln! and an explicit flush. Closed output pipes return process failure instead of panicking. If stderr itself fails, the final diagnostic is best effort and failure remains visible through the exit status. The actual OS-pipe follow-up records normal and failed-output checks; independent review remains pending.

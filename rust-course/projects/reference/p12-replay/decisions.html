Deterministic synthetic event replay: engineering decisions

Author self-review completed; independent review pending. These decisions explain the reference's current scope, not a sequence of poor habits to undo later.

Current scope and invariants

The next sequence is exact, live order count is capped, fixed-point prices are validated, and rejected events preserve the entire replay state. All fallible accounting is checked before a placement is committed.

Chosen design and concrete Rust habits

Newtypes separate event and order IDs; a private Price representation prevents invalid ticks entering through safe constructors. Replay accounting stays private behind read-only getters, so callers cannot bypass transition validation by assigning metrics. Integer arithmetic expresses the chosen scale exactly. A BTreeMap gives stable iteration, generators stream events, and full-state comparisons accompany digest checks.

Reasonable alternative and tradeoff

A hash map can offer different lookup costs, but deterministic output would need a separate ordering step and measurement on a representative workload. A mature decimal type is appropriate when varying scales or richer decimal operations become requirements. Neither abstraction is needed to express this fixed four-place bounded exercise clearly.

Meaningful tests

Exact decimal grammar and limits; full-state deterministic replay; duplicate and sequence rejection; capacity and absent cancellation; injected accounting overflow; bounded generated live state.

Evidence limits

The supplied generator keeps only two live orders. A digest can collide and omits internal details; it is not an equivalence proof. Local benchmark samples include generation and exclude final digest/destruction. No universal timing claims are made.

When requirements justify evolution

Revisit representation and benchmark workload when active-state size, persistence, out-of-order arrival or domain rules expand. This is a state-transition exercise, not a matching engine. Add an amendment only after specifying its accounting and identity semantics.

CLI boundary follow-up

The generator CLI accepts no argument/default count or exactly one usize count. It rejects extra arguments and non-UTF-8 count text before replay; process tests preserve the valid three-event result while detecting the previous ignored-extra-argument behavior. No speed claim follows from this correction.

Before/after process evidence and documentation. Independent review remains pending.

Stdout failures propagate as ordinary I/O errors through locked Write handles. Final diagnostics use best-effort stderr writes and cannot panic on a closed pipe. P08 acquires the synchronous stdout lock only after its async tasks are drained. P06 recovery has already happened before a best-effort warning is emitted; output failure cannot roll back recovery. The regression suite closes real pipe read ends before child execution.

Synthetic tick file adapter

The separate tick_replay binary reads the exact five-column synthetic schema through bounded lines and batches. IDs must start at one and advance exactly; timestamps may tie but never go backwards. At most 64 symbols and 1000000 rows are admitted. Prices remain integer ticks, volume is checked u64, and notional is checked u128. All prospective fields are computed before committing one event. A synchronous staged pipeline avoids concurrency machinery that the current requirement does not justify. Successful reports sort symbols using BTreeMap; invalid files produce no successful partial summary. This adds actual file ingestion without changing the original generated-order benchmark or pretending its measurements cover parsing.

Expression language

From `rust-course/projects`:

mise exec -- cargo run -p expression-language -- "2 + 3 * 4"

Expected:

14

Grammar supports nonnegative i64 literals, unary minus, parentheses, + - * /. There is no unary plus, decimal, variable or assignment. A negative literal is unary negation of a positive literal; therefore -9223372036854775808 cannot be written directly (compute -9223372036854775807 - 1 instead). Limits: 4096 source bytes, 512 tokens, 64 parser nesting levels, and 64 AST depth. Error spans are UTF-8 byte ranges. Finite exhaustive arithmetic properties are not random fuzzing or a proof for all inputs.

Run `mise exec -- cargo test -p expression-language` for unit, integration, and documentation tests. Read `src/lib.rs` before `src/main.rs`: the library defines behavior; the binary owns argument parsing and exit status.

Engineering decisions and evidence are taught in the HTML course lesson and in `decisions.html`; these include current invariants, chosen design, concrete habits, alternatives, actual verification, and evolution thresholds.

Output errors and evidence

Normal output uses fallible writeln! and an explicit flush. Closed output pipes return process failure instead of panicking. If stderr itself fails, the final diagnostic is best effort and failure remains visible through the exit status. The actual OS-pipe follow-up records normal and failed-output checks; independent review remains pending.

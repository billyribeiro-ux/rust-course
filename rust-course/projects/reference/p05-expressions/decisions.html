Engineering decisions and evidence

Requirements and invariants

The grammar specifies precedence, left associativity, unary minus, whole-input consumption, and UTF-8 byte spans. Arithmetic is checked. Source bytes, token count, parser nesting, and AST depth are bounded separately. Private Expr construction preserves the depth invariant used by recursive evaluation and destruction.

Chosen design and concrete habits

Lexing, parsing, and evaluation have distinct failure boundaries. The parser stores operator spans so runtime errors identify the responsible operation. Evaluation propagates typed errors with ? and uses checked operations for every arithmetic case. The lexer character expect documents a remaining nonempty valid-boundary invariant; no user syntax failure relies on panic. Doctests propagate errors rather than teaching routine unwrap.

Meaningful alternative and evolution threshold

An arena or explicit evaluation stack becomes useful for languages that must accept much deeper trees. A parser library can help when grammar recovery, many operators, or complex declarations become requirements. Direct i64 minimum literal support needs a magnitude design; it cannot be added honestly by changing one display rule. New constructors or deserializers must preserve resource invariants.

Actual checks and remaining uncertainty

Native precedence, associativity, Unicode spans, malformed input, arithmetic errors, limits, fixed corpus, documentation, and finite exhaustive small-integer properties passed in verification/native-tests.log and passed again in verification/patch001-foundations-tests.log after the patch audit. These properties use a bounded independent arithmetic oracle and are not randomized fuzzing or universal proofs. Independent review remains pending.

Output errors and evidence

Normal output uses fallible writeln! and an explicit flush. Closed output pipes return process failure instead of panicking. If stderr itself fails, the final diagnostic is best effort and failure remains visible through the exit status. The actual OS-pipe follow-up records normal and failed-output checks; independent review remains pending.

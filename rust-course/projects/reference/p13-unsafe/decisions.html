Audited fixed-capacity storage: engineering decisions

Author self-review completed; independent review pending. These decisions explain the reference's current scope, not a sequence of poor habits to undo later.

Current scope and invariants

len never exceeds capacity; precisely the prefix below len contains owned initialized values. Borrowed slices expose only that prefix with self-tied lifetimes and appropriate exclusivity. A moved-out value is excluded from later cleanup.

Chosen design and concrete Rust habits

A safe Vec-based model comes first. The compact unsafe representation uses private MaybeUninit storage, capacity checks before writes, initialization before length publication, and length removal before move-out. clear publishes empty state before user Drop code. Every unsafe expression has a local justification.

Reasonable alternative and tradeoff

A Vec or an established fixed-capacity collection is the preferred general application choice when its contract meets requirements. This custom wrapper is appropriate only for studying a small auditable boundary; no speed advantage or universal soundness proof is claimed. Adding more operations increases the audit surface and should be justified by an actual requirement.

Meaningful tests

Zero capacity; bounds and ownership on full push; deterministic comparison with safe baseline; exactly-once non-Copy destruction; ZST counts and destructors; over-alignment; one caught destructor panic with reuse.

Evidence limits

Passing native tests or Miri is evidence for executed cases, not a universal soundness proof. A second panic while unwinding can abort. Independent review remains pending; author self-review cannot grant acceptance.

When requirements justify evolution

Use an established collection for production needs unless stack storage or another measured requirement justifies ownership of an unsafe implementation. Any new removal, iteration, interior-mutability or raw-pointer feature requires a renewed invariant review.

Local asynchronous health monitor: engineering decisions

Author self-review completed; independent review pending. These decisions explain the reference's current scope, not a sequence of poor habits to undo later.

Current scope and invariants

Only literal loopback endpoints are admitted. Input count, task count, attempts, status-line storage and deadlines are bounded. Every spawned task stays owned until joined or aborted and drained.

Chosen design and concrete Rust habits

Tokio socket I/O yields while waiting; JoinSet bounds task creation directly. Per-attempt and total deadlines cover different scopes, and a watch channel carries shutdown state. Results retain input indices so scheduling does not change report order. Controlled local listeners make failure tests reproducible.

Reasonable alternative and tradeoff

A maintained HTTP client is the appropriate choice when TLS, redirects, connection pooling, complete framing or real HTTP interoperability is required. The tiny status-line parser is a deliberately scoped transport exercise. A semaphore is useful for shared permits but would not by itself bound the number of spawned waiting tasks.

Meaningful tests

503 then healthy retry; malformed response; stalled read deadline; concurrency-one cap and input order; shutdown after a known acceptance signal; remote-address rejection.

Evidence limits

Cancellation stops local future work, not requests already sent. Aborted rows do not retain task-local attempt counts. Deadlines are cooperative rather than real-time guarantees. No TLS, redirects or response-body parser is implemented.

When requirements justify evolution

Replace the transport parser as soon as requirements exceed one bounded local status line. Add jitter, rate policy and observability only when operating requirements specify them. Accurate attempt counts for forcibly aborted tasks require explicit progress reporting.

Executed evidence

The coordinated native workspace suite was run through mise and passed for the reference baseline. See native test output and patch review record for changes and affected verification. Optional Miri and browser inspection are reported separately; neither is implied by native test success.

CLI boundary follow-up

The CLI parses all zero/demo or 1..128 loopback endpoint arguments before starting network work. Checked native-to-UTF-8 conversion prevents routine malformed arguments from panicking. A process test supplies a valid endpoint followed by an invalid one and checks that the listener received no connection; additional cases reject malformed, remote and excessive endpoint inputs.

Stdout failures propagate as ordinary I/O errors through locked Write handles. Final diagnostics use best-effort stderr writes and cannot panic on a closed pipe. P08 acquires the synchronous stdout lock only after its async tasks are drained. P06 recovery has already happened before a best-effort warning is emitted; output failure cannot roll back recovery. The regression suite closes real pipe read ends before child execution.

This crate intentionally contains todo!() and failing tests. Do not count it as a passing reference.

Work in your learner copy

If this is still the original scaffold, first run python3 scripts/start-project.py p01 from the course root (the folder containing index.html and mise.toml). It creates learner-work/p01-calculator and refuses to overwrite existing work. Open that new folder in your editor. If the helper says it already exists, keep your work and either use the existing copy or choose an unused --name.

From the course root, test your copy with:

mise exec -- cargo test --manifest-path learner-work/p01-calculator/Cargo.toml

Or, in a terminal whose current directory is your learner copy (the folder containing this README, Cargo.toml and src), run:

mise exec -- cargo test

This starter is a library, so cargo test is its entry point; it does not yet provide a cargo run executable. Its initial four failing tests are expected because calculate is deliberately unfinished. Implement one contract at a time and inspect the first failure, rather than treating the expected failure as a broken Rust installation. Compare with projects/reference/p01-calculator under the course root only after writing a prediction and a failing example. The reference has additional domain, IO, and boundary tests beyond this starter.

The scaffold contract uses fallible Results from the first checkpoint. todo!() marks intentionally unimplemented learner work, not recommended error handling. Do not replace routine failure with unwrap; use the typed errors and explicit invariants demonstrated by the reference. Engineering decisions are in the corresponding HTML lesson.

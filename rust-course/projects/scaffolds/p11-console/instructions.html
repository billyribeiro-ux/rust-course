Console learner checkpoint

This first checkpoint has local reactive input only. Compile with the wasm32-unknown-unknown target. Use the Stage 6 build instructions to create JavaScript glue. Before adding network code, verify the label, keyboard focus and live filter text.

From the course folder, create a learner copy, then build and serve that exact directory:

python3 scripts/start-project.py p11
mise exec -- python3 scripts/build-ui.py --project learner-work/p11-console
python3 scripts/console-server.py --project learner-work/p11-console

The helper requires wasm-bindgen CLI 0.2.129 and the wasm32-unknown-unknown Rust target; Stage 6 gives their mise setup commands. The loader imports console_learner.js from this project’s generated pkg folder. A failed import produces visible build guidance. No generated package is included in the portable archive.

Engineering decisions and evidence

One local String owns the filter; the component holds reactive handles. Semantic input and label are used from the start. No tasks, network client or shared lock are needed for this scope. Add async requests only when implementing the next endpoint, with a deadline, explicit error state and at most one pending request. The reference contains these boundaries. WASM compile evidence is recorded separately from browser interaction, which remains pending.

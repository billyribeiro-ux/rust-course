Bounded tokenization before precedence parsing

Tokenize at most 1024 UTF-8 source bytes into at most 64 tokens: nonnegative decimal i64 literals, plus, star and ASCII whitespace. Keep byte spans; reject unknown symbols and out-of-range literals. This stage does not parse precedence, unary signs or parentheses, or evaluate expressions.

Engineering decisions at this checkpoint

The lexer uses enums for token categories and original byte offsets for diagnostics, with explicit source and token budgets. ASCII digits are consumed without allocating another numeric string; the retained token vector has a bounded count. An on-demand token iterator is a reasonable alternative for much larger inputs, but would add parser-state coordination unnecessary at this scope. Tests establish Unicode scalar spans, integer range, token/source bounds and the distinction between tokenization and grammatical acceptance. The invariant expect is documented at the nonempty UTF-8 boundary.

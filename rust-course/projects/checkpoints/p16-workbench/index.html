p16-workbench: reconstructible checkpoints

These are immutable source milestones, not task lists or a hidden final implementation. Materialize each into a new working directory. Existing learner work is never overwritten. Build output is shared through your Cargo target directory and is not copied with a checkpoint.

Reconstruct and verify

Working directory: the course root containing index.html. Python3.11 or newer is needed for the standard-library TOML parser.

python3 scripts/start-checkpoint.py p16 01-order-domain
mise exec -- cargo test --locked --manifest-path learner-work/checkpoints/p16-workbench/01-order-domain/Cargo.toml

The helper resolves inherited Cargo fields, copies local path dependencies where needed, and starts from the shared lockfile. Use --destination PATH for another fresh directory. Never reuse a modified working directory as a reconstruction destination.

Milestone contract

A single synthetic symbol uses integer cents and whole shares. Quotes require increasing sequence numbers; orders retain stable logical IDs and an original accepted price. Purchases and sales use checked arithmetic, prohibit negative cash/shares, retain at most64 orders, and reject without partial state changes. No files, HTTP, watchlists, replay jobs, chart, or actual trading exists.

Engineering decisions

The order map is authority for idempotency and original fill price. Duplicate comparison happens before consulting the current quote or capacity, so an exact retry preserves its first result even after a price change or when admission is full. All fallible domain checks precede the mutation boundary. The tests compare the entire engine before and after a rejection, not merely a status value. This milestone owns one symbol to isolate arithmetic and event identity. The final engine extends the same obligations to bounded multiple-symbol state, journal commits and operational interfaces; it does not weaken them for convenience.

How to use the sequence

  1. Reconstruct00-scaffold for the smallest runnable premise. Predict its tests and explain its explicit scope.
  2. Reconstruct01-order-domain separately. Read its complete src/lib.rs, run tests, and make one change that exercises its contract.
  3. Reconstruct final in a third directory. Compare source and tests; identify each new resource, state transition, and failure boundary.

For any selected ID, replace the second argument of the reconstruction command. The final snapshot references immutable reference source rather than duplicating a second large tree. The manifest records all IDs and sources. The corresponding lesson is 09-domain.

Practice and evidence

Do not infer later features from a passing early test. Before reading final, write the next milestone's acceptance criteria and name a plausible implementation defect that the current tests would miss. Then identify the reference test that addresses it, or add your own experiment in the learner copy. Record command, expected result, observed result, and remaining uncertainty.

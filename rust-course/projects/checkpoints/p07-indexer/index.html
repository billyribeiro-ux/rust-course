01-streaming: Stream a bounded reader before adding workers

Fixed-size reads preserve word state and unterminated final lines; at most budget plus one bytes are consumed; ordinary IO failures propagate.

Reconstruct and verify

From the portable course root, run:

python3 scripts/start-checkpoint.py p07 01-streaming
mise exec -- cargo test --locked --manifest-path learner-work/checkpoints/p07-indexer/01-streaming/Cargo.toml
mise exec -- cargo run --locked --manifest-path learner-work/checkpoints/p07-indexer/01-streaming/Cargo.toml

The demo prints:

bytes=16 lines=2 words=3

The helper refuses to overwrite an existing destination; use --destination with a new directory for another investigation. The course mise configuration gives these copies the same shared native target, so source snapshots do not imply a separate build cache per stage.

Transition to final

The complete milestone isolates counting semantics without threads, cancellation, or path discovery. Keep its one-byte reader and IO-failure regressions when adding the final worker pool. The final reference adds bounded job/result queues, capped paths and files, cancellation, stable output ordering, and joined workers; it does not redefine ASCII word boundaries.

python3 scripts/start-checkpoint.py p07 final
mise exec -- cargo test --locked --manifest-path learner-work/checkpoints/p07-indexer/final/Cargo.toml

Compare the two independent copies with diff -u on their source files. Explain which new requirement justifies each additional mechanism. The final copy includes concretized manifest values and any required local dependency sources; it can be checked separately from the reference workspace.

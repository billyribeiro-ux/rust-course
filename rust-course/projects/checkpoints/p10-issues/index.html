p10-issues: reconstructible checkpoints

These are immutable source milestones, not task lists or a hidden final implementation. Materialize each into a new working directory. Existing learner work is never overwritten. Build output is shared through your Cargo target directory and is not copied with a checkpoint.

Reconstruct and verify

Working directory: the course root containing index.html. Python3.11 or newer is needed for the standard-library TOML parser.

python3 scripts/start-checkpoint.py p10 01-http-validation
mise exec -- cargo test --locked --manifest-path learner-work/checkpoints/p10-issues/01-http-validation/Cargo.toml

The helper resolves inherited Cargo fields, copies local path dependencies where needed, and starts from the shared lockfile. Use --destination PATH for another fresh directory. Never reuse a modified working directory as a reconstruction destination.

Milestone contract

An in-process Axum service exposes POST /issues/validate; the writer fixture receives a normalized title, a reader receives403, unknown identity401, invalid title422, invalid JSON400, and oversized body413. Four admitted requests, a one-second deadline, and4096-byte bodies are bounded. Nothing is persisted and this endpoint never creates an issue.

Engineering decisions

The endpoint name explicitly says validate. Calling it create while silently dropping data would teach a misleading contract. Public role fixtures teach server permission placement; they are not real authentication. Extraction precedes the in-handler identity check, so malformed JSON may be rejected before401. The middleware holds its owned permit for the request lifetime. No synchronous lock or database pool is required for a stateless boundary. A persistent create operation is introduced only with PostgreSQL and an explicit transaction contract in the final source. A parts-only actor extractor is a reasonable later alternative when actor mapping is shared across routes.

How to use the sequence

  1. Reconstruct00-scaffold for the smallest runnable premise. Predict its tests and explain its explicit scope.
  2. Reconstruct01-http-validation separately. Read its complete src/lib.rs, run tests, and make one change that exercises its contract.
  3. Reconstruct final in a third directory. Compare source and tests; identify each new resource, state transition, and failure boundary.

For any selected ID, replace the second argument of the reconstruction command. The final snapshot references immutable reference source rather than duplicating a second large tree. The manifest records all IDs and sources. The corresponding lesson is 05-http.

Practice and evidence

Do not infer later features from a passing early test. Before reading final, write the next milestone's acceptance criteria and name a plausible implementation defect that the current tests would miss. Then identify the reference test that addresses it, or add your own experiment in the learner copy. Record command, expected result, observed result, and remaining uncertainty.

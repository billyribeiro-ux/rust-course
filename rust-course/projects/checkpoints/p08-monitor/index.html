01-budget: Establish retry and deadline policy without clocks

A retry requires an available attempt, nonzero per-attempt cap, and positive time after elapsed time and backoff; arithmetic cannot wrap.

Reconstruct and verify

From the portable course root, run:

python3 scripts/start-checkpoint.py p08 01-budget
mise exec -- cargo test --locked --manifest-path learner-work/checkpoints/p08-monitor/01-budget/Cargo.toml
mise exec -- cargo run --locked --manifest-path learner-work/checkpoints/p08-monitor/01-budget/Cargo.toml

The demo prints:

next_attempt_budget_ms=60

The helper refuses to overwrite an existing destination; use --destination with a new directory for another investigation. The course mise configuration gives these copies the same shared native target, so source snapshots do not imply a separate build cache per stage.

Transition to final

This milestone makes time-budget decisions deterministic and fast to test. It does not perform network IO or claim real-time deadlines. The final Tokio monitor applies an outer endpoint deadline to connection, retries and backoff, plus a per-attempt timeout and cancellation. Compare that enclosing timeout with this arithmetic model; a connection-only timeout would omit later work.

python3 scripts/start-checkpoint.py p08 final
mise exec -- cargo test --locked --manifest-path learner-work/checkpoints/p08-monitor/final/Cargo.toml

Compare the two independent copies with diff -u on their source files. Explain which new requirement justifies each additional mechanism. The final copy includes concretized manifest values and any required local dependency sources; it can be checked separately from the reference workspace.

Milestone contract

A synchronous byte-stream codec accepts UTF-8 frames of1..1024 bytes without control characters; distinguishes clean EOF from truncated input; bounds allocation before reading payload. No TCP listener, Tokio task, broadcast, or shutdown behavior exists in this milestone.

Engineering decisions

The frame boundary is a protocol invariant, so byte length and control-character rules match the final server. read_exact handles partial reads while a one-byte first read distinguishes clean EOF. A fragmented-reader fixture exercises behavior a contiguous byte slice alone would miss. Memory per decoded frame is bounded by1024 bytes; this does not bound total connection count because there are no connections here. The synchronous Read interface makes byte sequencing easy to inspect before introducing async cancellation. An async codec is the next step when a task must wait for network data without blocking an executor.

How to use the sequence

  1. Reconstruct00-scaffold for the smallest runnable premise. Predict its tests and explain its explicit scope.
  2. Reconstruct01-framing separately. Read its complete src/lib.rs, run tests, and make one change that exercises its contract.
  3. Reconstruct final in a third directory. Compare source and tests; identify each new resource, state transition, and failure boundary.

For any selected ID, replace the second argument of the reconstruction command. The final snapshot references immutable reference source rather than duplicating a second large tree. The manifest records all IDs and sources. The corresponding lesson is 05-protocols.

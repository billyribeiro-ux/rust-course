Reader notes: preserve conflicting text

A stale lesson page previously rewrote its full progress snapshot, potentially removing newer notes saved in another tab. The writer now compares the currently stored text with the snapshot it last loaded or saved. If another completed write changed it, this page refuses the overwrite and keeps its edits in memory. Export reveals current-page JSON and the conflicting saved text separately. Preserve both, reload, then copy only the intended lesson text; importing an old full backup deliberately replaces matching entries.

Eight pure data tests and syntax results cover long Unicode notes, invalid backups, first/repeated saves, stale writes, deletion and malformed replacement. They do not exercise a browser. Its default cache is .local/native-target. Use --target-dir to select an existing shared verification cache. Database fixture failures are test assertions; the URL is never printed by the Rust guard, because a mistaken URL might include a password.

Chat shutdown: observe state, retain ownership

A newly created watch receiver considers its initial value seen. Waiting for changed() without inspecting the value can therefore miss an already requested stop. The server now reads the current Boolean before waiting, continues after false notifications and shuts down when true or when all senders disappear. The main function selects a retained pinned server future against Ctrl-C in one task, signals stop, then awaits task cleanup. Accept errors also pass through connection-task cleanup.

The targeted lifecycle checks and latest baseline log distinguish observed test results. Two new regressions cover initial true, false notifications, and sender closure, using real loopback frames where needed. The deadlines are hang detectors rather than operational latency guarantees.

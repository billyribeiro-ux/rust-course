P03: actual streaming search and explicit large-input budgets

Author self-review, October 9, 2026. Independent review remains pending. This follow-up repairs missing requested behavior: the earlier reference summarized streams but accepted no search query and exposed no CLI override for its 64 MiB budget.

Implemented contract

The library shares its bounded scanner between analyze and search. A search matches a nonempty, bounded UTF-8 literal against the complete valid record, case-sensitively, and emits matching records immediately with normalized LF endings. It does not retain matches or create a service-name map. Malformed and oversized records remain visible in counters but never enter output. The existing summary includes all valid records; matched is a separate count.

The CLI accepts --contains and a positive --max-bytes budget. With no query, its original stdout summary is unchanged. With a query, stdout contains matches and stderr contains the summary. It validates textual options while preserving native paths, uses an 8192-byte file buffer, flushes match output before reporting success and exits nonzero on expected errors. A failed stream may have emitted a prefix; no successful report accompanies that failure.

Evidence

Exact commands and output and machine-readable results record Rust 1.99.0 via mise, reference formatting, all-target checking, strict Clippy and 18 passing native/documentation tests. Six deliberately incomplete scaffold acceptance tests were compiled with --no-run; they are not recorded as passing implementations. The initial strict Clippy run found a collapsible condition; its behavior-preserving suggestion was reviewed and the checks rerun.

The generated-reader test emits 65,537 records, each 1024 bytes: 67,109,888 bytes in total, above the default 64 MiB work budget. Only one 1 KiB repeated source record is stored, and reader requests are bounded to 257 bytes. All records are counted and matched with a larger explicit budget. This demonstrates processing beyond the default budget without a whole-input fixture. It is structural and behavioral evidence, not a measurement of peak RSS or an assertion that the input exceeded this machine's physical RAM.

Other tests exercise bytewise UTF-8 splits, CRLF and final unterminated records, visually similar but distinct Unicode sequences, no matches, invalid records, exact/exhausted budgets, partial output writes, a read failure after a successful emitted prefix, Interrupted retry, non-Unicode native paths, and CLI exit/output behavior.

Primary documentation and limits

The versioned web pages were unavailable through the browsing tool. The corresponding installed official Rust 1.99.0 documentation was read directly for BufRead, str::contains and Write::write_all; source-file hashes are recorded in the JSON evidence.

The tool does not implement regex matching, Unicode normalization, case folding, redaction, a slow-input deadline or atomic output publication. Reader/writer storage and allocator overhead add memory. Browser usability and independent acceptance are separate gates. Whole-course source inclusion synchronization is checked during integration, not asserted by this scoped native report.

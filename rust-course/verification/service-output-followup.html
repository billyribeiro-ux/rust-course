Service output and shutdown boundaries

October 9, 2026 · Rust 1.99.0 through mise · Author-team review. Independent review remains pending.

Corrected habits at their actual use sites

P09, P10, P13, P14, P15 and P16 entry points now treat required output as fallible I/O. A write or flush error is returned; it is not converted into a printing-macro panic. Startup banners precede P14 and P16 worker spawning. P13's two fixed-capacity pushes and P15's one fixed proposal use documented expect invariants; arbitrary runtime inputs retain their fallible APIs.

P10 and P14 discard the payload of missing/non-Unicode database-URL errors before reporting a fixed configuration message. This matters because a non-Unicode environment error can contain the full credential-bearing operating-system value.

The HTTP entry points retain their shutdown sender and one pinned server future. Ctrl-C requests graceful shutdown and awaits that same future; a signal-registration error also requests shutdown. After any server exit, P14/P16 explicitly stop and join their workers before returning saved errors. P10/P14 close their pools after serving before propagating the saved server error. P09 similarly retains its server future rather than detaching a signal watcher.

P14 worker logs use best-effort writes: a failed diagnostic is not allowed to panic the worker or change the meaning of a database commit. This deliberately permits lost observations. Query durable job/effect state for reconciliation; these logs are not a durable audit. Synchronous writes can still block on a slow sink, so this local example makes no hard logging/shutdown deadline claim.

What this evidence does not establish

These checks do not connect the P10/P14 database-backed services. P14's best-effort worker logging policy is source-reviewed and compiled here; a database worker continuing after its output sink closes needs a separate owned-database execution. The fresh isolated PostgreSQL integration evidence checks database transitions separately. Likewise, the owned SIGINT checks do not inject every server accept failure or establish a universal shutdown bound. The larger workbench runtime audit covers different domain, overload and restart contracts.

P13's unsafe library source was unchanged; this main-only output correction does not require or claim a new Miri campaign. Browser behavior and independent instructional acceptance remain unverified. Passing a build or these process checks is not proof of application security or production readiness.

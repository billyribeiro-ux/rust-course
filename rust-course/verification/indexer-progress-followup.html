Construction gap and correction

The earlier indexer reported only after the run finished, although the requested project and coverage matrix called for progress. The correction adds index_with_progress while preserving index as a no-output wrapper. An initial callback, one callback per returned Entry, and one final callback run synchronously on the coordinator. Snapshots are constant-sized; there is no added progress queue or detached task. Per-file completion order can vary; final content ordering remains deterministic.

The observer separates received results from successfully indexed files. At completion, submitted minus received accounts for accepted jobs without a result; total minus submitted accounts for unsubmitted jobs. The CLI writes these observations to stderr and keeps sorted output on stdout. A failed progress write requests cancellation; the coordinator still drains and joins before returning an error instead of a success report.

Evidence and boundaries

Full command output, including the initial lint failure · Commands, results, source hashes and primary-document hashes · Project guide · Engineering decisions

Per-file observations are not a timed heartbeat, a byte-completion estimate or a throughput measurement. A slow callback applies backpressure; a blocked ordinary file read cannot be forcibly cancelled through this API. Callback code must not wait for the same run to finish. The CLI does not install a Ctrl-C handler. Existing benchmark measurements call the no-progress wrapper and do not measure terminal-output overhead; no performance numbers were regenerated for this change.

The installed Rust 1.99.0 primary documentation for FnMut, scoped thread joining, bounded channels, and Write was read; exact local-file hashes are recorded. Browser interaction and independent instructional acceptance are separate pending work.

			48 text  beside your terminal. The following investigation models its complete loop; later lessons remove some of the prompts so you choose the next experiment yourself. Step 1 — state expected and actual behavior precisely. Expected: three calculator arguments produce 15m. Actual for the missing-separator command: Cargo reports an unexpected argument; no quantity is printed. Avoid writing only “Rust is broken.” That phrase hides both the action and the observable difference. Step 2 — reproduce with exact context. Record the working directory rust-course/projects, the full command, the output, and the output of mise exec -- rustc --version. The intended version begins with rustc 1.99.1. If yours differs, that is an observation, not permission to assume it caused the argument error. Record the active Cargo version too. Reproduction is a controlled description, not a collection of screenshots with missing context. Step 3 — locate the boundary. The message names Cargo's command syntax, so investigate Cargo-to-binary argument forwarding. Step 4 — read evidence rather than only the last line. Cargo help describes the separator before executable arguments. The reference binary expects exactly three arguments after its own executable name. These facts narrow the search before any source edit. Step 5 — separate competing hypotheses. Hypothesis A: the toolchain cannot compile the project. Hypothesis B: arguments are being interpreted by Cargo. A remains plausible until a normal run builds; B predicts that inserting one separator will change which program responds. We have not yet proved either hypothesis merely by naming it. Step 6 — make one distinguishing experiment. Add only the double dash and keep package, directory, operands, and tool version constant. Expected experimental result: the normal command builds or reuses its build and prints 15m. This disproves A as the explanation for this reproduction, while supporting B. It does not prove that the installation can never fail for another package. Step 7 — apply the smallest sound fix. Correct the documented invocation; do not rewrite argument parsing to accommodate an argument list that never arrived. Step 8 — regress and state limits. Run the good addition, an incompatible-unit case, and the package tests. These checks cover routing into the binary and some calculator contracts, not arbitrary shell quoting or operating-system behavior. Step 9 — capture the result. Write a short note: “Missing Cargo separator; observed Cargo argument rejection; changed only --; calculator then produced 15m; recorded Rust 1.99.1; package tests still need to be run or their actual result attached.” Distinguish an expected example from a command you actually executed. This habit makes your later debugging notes usable evidence.

			54 text use std::{
    io::{self, Write},
    process::ExitCode,
};
fn run() -> io::Result<ExitCode> {
    let args = std::env::args_os()
        .skip(1)
        .map(|value| value.into_string())
        .collect::<Result<Vec<_>, _>>();
    let mut stdout = io::stdout().lock();
    let mut stderr = io::stderr().lock();
    let Ok(args) = args else {
        writeln!(stderr, "calculator: arguments must be valid UTF-8 text")?;
        return Ok(ExitCode::from(2));
    };
    let [left, op, right] = args.as_slice() else {
        writeln!(
            stderr,
            "usage: workshop-calculator <integer[m|s]> <+|-|*|/> <integer[m|s]>"
        )?;
        writeln!(
            stderr,
            "       workshop-calculator convert <finite-number><mm|cm|m|km> <mm|cm|m|km>"
        )?;
        return Ok(ExitCode::from(2));
    };
    if left == "convert" {
        return match workshop_calculator::conversion::convert(op, right) {
            Ok(length) => {
                writeln!(
                    stdout,
                    "approximately {}{}",
                    length.value(),
                    length.unit().symbol()
                )?;
                stdout.flush()?;
                Ok(ExitCode::SUCCESS)
            }
            Err(error) => {
                writeln!(stderr, "conversion: {error}")?;
                Ok(ExitCode::FAILURE)
            }
        };
    }
    match workshop_calculator::calculate(left, op, right) {
        Ok(value) => {
            writeln!(stdout, "{value}")?;
            stdout.flush()?;
            Ok(ExitCode::SUCCESS)
        }
        Err(error) => {
            writeln!(stderr, "calculator: {error}")?;
            Ok(ExitCode::FAILURE)
        }
    }
}
fn main() -> ExitCode {
    match run() {
        Ok(code) => code,
        Err(error) => {
            // Diagnostic output is best effort; its failure cannot restore stdout.
            let _ = writeln!(io::stderr().lock(), "calculator output: {error}");
            ExitCode::FAILURE
        }
    }
}

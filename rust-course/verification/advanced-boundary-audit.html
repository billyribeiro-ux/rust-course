P05-resource-boundaries

Classification: evidence gap closed; no implementation defect

Before: Existing over-limit tests asserted only is_err, so they could not identify which guard fired or establish accepted exact boundaries.

Change: Two tests isolate exact source/token ceilings and distinguish parser recursion from constructed AST depth.

Observed: 4096 bytes accepted; 4097 rejected with whole-input source-limit span. A valid 512-token balanced expression evaluates to -128; token 513 is rejected at 512..513. Sixty-three parenthesis pairs plus the top-level call use 64 recursion levels and produce AST depth 1; the next pair fails with nesting limit at 64..65. A flat 64-leaf sum produces AST depth 64 and value 64; leaf 65 fails with AST-depth error at 127..128.

Curriculum note: The phrase recursion limit 64 counts the initial call, not 64 nested pairs. Resource rejection is not a claim that the arithmetic expression is mathematically invalid. Existing finite integer properties correctly identify their bounded independent arithmetic oracle; no universal-proof or random-fuzz claim was found.

P09-codec-boundaries

Classification: evidence gap closed; no implementation defect

Before: Fragmented and invalid frames were tested, but an exact-limit multibyte payload adjacent to a second frame and retention across partial-prefix polling were not isolated.

Change: Two memory-only async tests, without listeners, wall-clock sleeps or shortened service deadlines.

Observed: A 1024-byte payload containing 512 two-byte characters followed immediately by another frame decodes as two exact messages. A 1025-byte writer input fails before any output mutation; its reader prefix fails without requiring a body. A decoder polled after only two header bytes resumes from the same saved future and yields é after the remaining bytes arrive.

Curriculum note: The pinned future test establishes the ownership pattern in isolation; it is not a slow-socket or end-to-end shutdown test. Source review confirms the final service retains the same reader future, disconnects on a broadcast receive error, owns connection tasks in JoinSet, and releases permits with task lifetime. Existing prose correctly separates channel lag from application disconnects and socket-buffer behavior. Capacity 32 is already a power of two, consistent with Tokio rounding.

P13-contract-language

Classification: concrete explanatory ambiguity and evidence overclaim corrected

Before: The model said prefix from zero through len, which could be read inclusively. The assessment asked to prove through tests that safe access could not expose the suffix. Source links used unversioned standard-library URLs.

Change: 07-unsafe now explicitly says half-open 0..len with len excluded; P13 assessment distinguishes demonstrated test boundaries from the invariant argument. Both unsafe lessons use Rust 1.99.0 std URLs and include allocation-byte-extent reasoning supported by installed primary docs.

Observed: All four unsafe expressions were reviewed against initialization, alignment, length, allocation extent, aliasing, lifetime and cleanup obligations. The byte-extent argument follows from one live array object and private len <= N; no extra debug assertion is needed. No production change or additional dynamic run was justified.

Curriculum note: Native/optimized/Miri results concern executed cases; they do not constitute independent acceptance or universal soundness. Assessment explicitly advises against arbitrary native execution of undefined behavior.

P15-commit-hole

Classification: evidence gap closed; no implementation defect

Before: Finite schedule tests covered partitions/restarts/loss and conflicts but did not isolate a later acknowledgment arriving before an earlier index, with repeated same-node acknowledgments.

Change: One test reorders legitimate queued acknowledgments after delivering two leader appends to follower one.

Observed: Delivering the index-1 acknowledgment three times leaves committed at zero and the acknowledging set exactly {0,1}. Delivering index-0 acknowledgment then advances the contiguous committed prefix to two while follower two remains empty. Prefix safety is checked after each delivered acknowledgment.

Curriculum note: This supports unique-node accounting and contiguous commitment in the fixed-leader model. Public state/queue mutation and invalid node indices are explicitly outside the reference adversarial-input contract; the proposed assessment driver must validate them. No claim of Raft, malicious-node safety, real disk durability or exhaustive model checking was found.

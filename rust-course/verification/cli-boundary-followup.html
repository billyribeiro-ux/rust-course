CLI boundary follow-up

Verified 2026-10-09 using Rust 1.99.0 through mise. Author self-review complete; independent review pending.

Corrected defects

  • P06 parsed ordinary String arguments, then opened the store before validating the command. A typo could create a file or repair an incomplete suffix. The CLI now retains a native PathBuf and validates all command/text/bounds/arity requirements before open.
  • P08 and P12 used args(), which panics during iteration for a non-UTF-8 native argument. Both now use args_os with checked text conversion. P08 validates the full bounded endpoint list before network work.
  • P12 read only its first count argument and silently ignored extras. Its count mode now requires exactly zero or one argument.

Executed evidence

The six original real-process regressions failed before correction. The final scoped all-target suite passed 53 test entries, including eleven new main-CLI process tests and eleven tick-adapter tests; strict Clippy and rustfmt checks passed. One existing P06 entry is a subprocess helper that performs work only in the explicitly invoked child. No database, browser or benchmark run is implied.

The first corrected test run uncovered a mistaken test assumption: this macOS filesystem rejects an invalid UTF-8 directory name with EILSEQ. The final test checks either supported native-byte I/O or a normal error without panic. The success branch was not exercised on this host. A separate valid Unicode directory and file round-trip passed. Rejected commands preserve original torn-file bytes, create no lock/data file, and a malformed endpoint after a valid one sends no monitor connection.

Closed output pipes

P06/P08/P12 now use locked Write handles and propagate stdout errors. Final diagnostics are best-effort writes, preserving the original exit result even when stderr is also closed. P06's already-completed recovery cannot be rolled back by a failed warning. The new process tests close an actual anonymous pipe's reading end before spawning; they do not rely on timing a consumer. The separate tick binary follows the same policy and has its own tests.

Teaching and checkpoints

Lessons 03-recovery, 04-monitor and 07-replay add the actual process boundary, investigation and tests. Their project decision pages document the corrected contract. Final checkpoints reconstruct current reference source; early no-argument checkpoints remain valid and unchanged.

Primary evidence

Read the installed Rust 1.99.0 rust-docs pages for args_os, args and OsStr::to_str. Public versioned-page retrieval was unavailable in the web tool; exact installed-page hashes are recorded. A native argument's representation and the filesystem's accepted names are distinct boundaries.

Review limits

Unix argument cases are platform gated; Windows execution and browser inspection are not part of this audit. A finite test suite does not prove durability or universal correctness. Source inclusion checks follow the coordinated course render. Independent review remains pending.

Synthetic tick file replay: construction and evidence

Verified 2026-10-09 with mise Rust 1.99.0. Author self-review complete; independent review pending.

What was added

P12 now has an actual bounded synthetic tick-file adapter as the separate tick_replay executable, a five-row fixture, a narrow documented CSV contract, and deterministic count/volume/notional/first/last/low/high aggregates. The prior generated place/cancel replay remains the default executable. Its benchmark and reported measurements keep their original workload.

The input has an exact header and five fields. IDs begin at one and advance exactly; duplicates, gaps and out-of-order events fail. Timestamps may tie but never move backwards. Prices use the existing four-place integer representation. A 256-byte line limit, 1024-tick maximum batch, 1000000-event maximum and 64-symbol maximum bound retained domain state. The producer and consumer execute synchronously; no task or channel claims are implied.

Executed verification

The final scoped P06/P08/P12 all-target suite passed 53 test entries. P12 adds eleven tick-specific tests: seven library investigations and four real-process CLI groups. These cover exact fixture values and batch-equivalent output, grammar/price limits, header and line endings, empty input policy, event and symbol budgets, duplicate/gap/backwards timestamp rejection, unchanged aggregate state after rejection, overflow injection, I/O failure, infinite newline-free input, 20000 lazily generated rows, argument boundaries and actual closed stdout/stderr pipes.

A fresh final checkpoint reconstructed into an owned temporary directory passed all 26 P12 test entries with --locked. Its tick command produced ALFA volume 7/notional 6992500 and BETA volume 5/notional 2505000; the preserved default command still processed three generated order events. Temporary reconstruction source was removed after the commands completed; compatible compiled output remained in the shared verification cache. No learner directory was touched.

Strict all-target Clippy and rustfmt checks passed. Exact command/result log · Schema, limits, source digests and commands.

Primary sources and limits

Version-matched installed rust-docs were read for Read::take, BufRead::read_until, Write and anonymous pipes; installed-document hashes are recorded.

There is no RSS or CSV throughput measurement, no parallel speedup claim, and no sorting, deduplication or quoted-CSV support. A malformed file can reveal different first errors at different batch sizes because parsing and application have separate stages; every failed replay yields no successful summary. Tests support the declared synthetic scope and do not establish a production feed system. Browser review and independent review remain separate.

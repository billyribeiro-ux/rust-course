Capstone runtime acceptance audit

Verified 2026-10-09 against the compiled p16-workbench binary. The audit passed 11 acceptance groups across 252 real HTTP requests. It created only temporary synthetic journals and owned loopback child processes. No browser or user database was accessed. All child processes were stopped before temporary data was removed.

Reproduce

From the course folder, build the current source using its pinned toolchain. Pass the resulting binary path explicitly; it may live outside the portable course folder because build caches are excluded.

mise exec -- cargo build --manifest-path projects/Cargo.toml -p p16-workbench
python3 verification/final-runtime-audit.py --binary PATH_TO_TARGET/debug/p16-workbench

The exact verification invocation and binary SHA-256 are stored in the machine-readable result; the log lists outcomes. The harness source records requests and owns cleanup.

Interpret the evidence

The crash test paused only its own server after an observed complete journal prefix, killed that process, then restarted it with the same journal. A partially completed replay resumed its persisted cursor and finished; the cancelled job stayed cancelled. This demonstrates process restart behavior for that prefix. It does not establish power-loss durability, directory-entry persistence, or torn-write repair. A separate corrupt-position fixture was rejected without silent repair.

Sixteen incomplete bodies occupied request admission and caused the next request to receive429. One incomplete body reached the real five-second deadline and received408. Both cases were checked for unchanged domain state. Accepted orders use integer cents and checked quantities; duplicate logical commands produced no second effect and changed content under an existing ID produced409.

The harness verifies polling/history boundaries rather than a WebSocket stream. Browser display, retained-order UI behavior, and the same-origin proxy have separate evidence maintained by the main course verification. Existing Rust tests cover injected append failure, poisoned-store503, history expiry, numerical/domain invariants, and API rejection before mutation. PostgreSQL transaction/migration/authorization and durable scheduler tests are recorded separately in the services verification logs.

Remaining scope

Public demo credentials are fixtures, not deployable authentication. TLS and browser security policy are taught in the browser-boundary lesson, whose six runnable service tests do not claim to execute a TLS handshake or a browser. The capstone has one supported journal writer, retained-data budgets, and explicit fail-closed corruption behavior. It makes no production reliability, consensus, or trading claims. This is author-side technical verification; independent review remains pending.

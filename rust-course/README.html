Prerequisites and your working directory

These commands use a macOS or Linux style terminal. Install mise, Python 3.11 or newer, and Git before starting the full learner workflow. The course configuration pins Rust; it does not install mise, Python or Git. Python 3.11 is the minimum because the checkpoint helper uses the standard-library tomllib parser. The static reader itself has fewer requirements. Rust compilation also needs your platform's native linker and development tools; consult the platform prerequisites in the Rust installation guide without replacing the course's mise-managed version selection.

mise --version
python3 --version
git --version

If a command is missing, install that prerequisite and reopen the terminal before continuing. For every block on this page, begin in the course root: the folder containing index.html, mise.toml, scripts and projects. Open that folder in your editor and start its terminal there. The folder may have any name; do not add another cd rust-course when you are already inside it. Confirm with pwd and ls. The commands below keep that working directory.

Open the course with mise

Keep this folder intact. From a terminal in the portable course folder, inspect mise.toml, trust it, install its pinned Rust toolchain and start the local reader. Mise also reads applicable ancestor and user configuration; mise install may include other tools already configured there:

mise trust
mise install
mise exec -- rustc --version
mise run course

Open http://127.0.0.1:8000/. The static server binds only to loopback. Keep its terminal running and use a second terminal in the course root for learner commands. Stop your own server with Ctrl-C when finished. Use python3 scripts/serve.py --port 8001 if port 8000 is already occupied. Directly opening index.html also supports reading, navigation and search. Clipboard and local storage restrictions vary under file URLs; a visible status explains the fallback.

Make a learner copy

python3 scripts/start-project.py p01
mise exec -- cargo test --manifest-path learner-work/p01-calculator/Cargo.toml

Open learner-work/p01-calculator/README.html and edit only that copy. The helper prints the exact destination name; use that name in the manifest path if it differs. It refuses to overwrite an existing directory. Some scaffolds intentionally fail acceptance tests until you implement the task; others are small complete checkpoints to extend. Read each scaffold's instructions before interpreting its test results. Reference projects remain separate.

Build references

From the course root, these commands check the supplied references, not your learner copy:

mise exec -- cargo test --manifest-path projects/Cargo.toml --workspace --locked
mise exec -- cargo fmt --manifest-path projects/Cargo.toml --all --check
mise exec -- cargo clippy --manifest-path projects/Cargo.toml --workspace --all-targets --locked -- -D warnings

The shared workspace includes the sixteen-project path's native crates plus focused specialization helpers. The Leptos UI is a separate WASM workspace and has its own pinned lockfile. Stage 6 gives exact build commands; its generated package is rebuilt, not included in the portable archive. PostgreSQL lessons use isolated databases, and ignore-marked integration tests must be run explicitly. See the evidence index for commands actually executed.

Keep disk usage understandable

The course mise configuration sends compatible learner and native builds to one .local/native-target. The UI build script uses a separate .local/wasm-target. Native debug builds retain full debug information and incremental compilation by default. Avoid one target directory per lesson or checkpoint. Cargo can also redirect intermediate build artifacts with build.build-dir, independently of --target-dir. Direct learner commands may inherit that setting from your user or ancestor Cargo configuration, or CARGO_BUILD_BUILD_DIR. Inspect those settings when measuring disk use; a small course target does not prove that all intermediate artifacts live there. Moving a cache does not reclaim the old copy.

An optional small profile is available with mise exec -- cargo test --profile small from projects. It uses reduced debug detail and disables incremental compilation. This can save space but can make debugging less informative and repeated builds slower. Switching profiles creates another set of artifacts; it is not free cleanup.

Use du -sh .local projects assets lessons verification to inspect categories. Read and stop relevant processes before deleting a disposable target. Never delete journals, database volumes, learner work, Git history or unrelated caches to meet a disk target. Moving output elsewhere does not reclaim storage. The construction evidence records both source/content and verification caches separately.

Back up notes and source

Use Export in the toolbar to save progress and lesson notes as JSON. Import validates the format and merges saved entries; matching keys use the imported note. Export before importing a file if you want to retain both versions. Completion checkboxes are self-report only. Save learner source with Git or your own backup system; note export does not back up Rust files or databases.

Edit notes in one course tab at a time. A page keeps a snapshot of saved progress. Before saving, it checks whether another tab has already changed or removed that snapshot. If so, it refuses to overwrite it and keeps your current text on this page. Use Export before reloading: it exposes both this page's JSON and the saved text observed at the conflict. Preserve both, reload to read the newer saved notes, then copy your unsaved lesson text into the appropriate field. Do not blindly import an older full backup: matching imported entries replace newer notes. This check detects an intervening completed write; it is not a transaction or a guarantee against simultaneous cross-tab edits. The Web Storage specification does not promise locking across tabs.

Verify the portable archive

From the course folder, run python3 scripts/pack.py, then python3 scripts/verify-archive.py. The verifier compares every archived file with the current portable source, rejects excluded content, checks ZIP integrity, and validates local links and source inclusions in a fresh temporary extraction. It writes the exact checksum and result beside the archive. It does not claim browser verification or rerun compiler checks. Only its own temporary extraction is removed.

Managed-machine tool policy

Do not use rustup, global package installers, or direct mise install/use/lock commands to repair the environment. The resumed October 17 checks successfully select Rust 1.99.1 and Node 26.12.0.

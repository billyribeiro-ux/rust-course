Partial failure, idempotency, and the outbox

Reason about work that can happen even when its acknowledgment is lost.

Purpose: retry without accidental duplication

A report job reaches a worker, the worker writes its result, and the acknowledgment disappears. The caller sees a timeout. Should it retry? The important fact is not that the timeout occurred; it is that the caller cannot tell whether the work happened. Distributed engineering starts with this gap between reality and observation. Rust's memory safety cannot remove it.

Plain-English model

At-least-once delivery allows repeated delivery while aiming to avoid permanent loss under stated recovery assumptions. At-most-once avoids repeated attempts but may lose work. Neither phrase alone defines how an external action behaves. Idempotency means repeating an operation with the same logical identity produces the same intended effect rather than an additional effect. It is a property of the operation and its storage boundary, not a property supplied automatically by HTTP or a queue.

Our scheduler assigns a bounded textual job ID. Submitting the same ID and same payload is accepted as a retry. Reusing the ID with a different payload is a conflict. A unique database key makes simultaneous duplicate submissions meet at a single storage constraint. A local in-memory “seen IDs” set would forget history after restart. A payload hash can be useful, but the project stores and compares the bounded payload directly so the teaching model does not need to invent a hashing protocol.

Prediction: where is the atomic boundary?

A worker sends an email, then writes “done” to PostgreSQL. It crashes between those actions. On restart, the job is delivered again. Does a unique jobs table row guarantee the recipient sees only one email?

Answer

No. The external mail system and our database did not share a transaction. The recipient may receive two messages. A downstream idempotency contract, a deduplicating effect store, or a business rule tolerating duplicates is required. Merely naming a job “exactly once” changes nothing.

Small runnable evidence

The scheduler's integration test enqueues the same job twice, rejects a conflicting payload, expires a lease, redelivers it, rejects a stale completion, and commits one database effect. It uses an explicit logical timestamp, so the failure schedule is deterministic rather than dependent on sleeping. First read the test and predict each returned boolean.

#[tokio::test]
#[ignore = "requires isolated COURSE_SCHEDULER_TEST_DATABASE_URL"]
async fn crash_redelivery_fencing_dedup_cancellation() {
    use p14_scheduler::*;
    let _fixture_guard = DATABASE_TEST_LOCK.lock().await;
    let pool = support::isolated_pool(
        "COURSE_SCHEDULER_TEST_DATABASE_URL",
        "rust_course_test_scheduler",
    )
    .await;
    sqlx::migrate!().run(&pool).await.unwrap();
    sqlx::raw_sql("TRUNCATE job_effects,jobs")
        .execute(&pool)
        .await
        .unwrap();
    assert!(enqueue(&pool, "a", "report").await.unwrap());
    assert!(!enqueue(&pool, "a", "report").await.unwrap());
    assert!(enqueue(&pool, "a", "other").await.is_err());
    let stale = claim(&pool, 0).await.unwrap().unwrap();
    assert!(claim(&pool, 1).await.unwrap().is_none());
    // Worker disappears; the simulated clock advances past its lease.
    let fresh = claim(&pool, LEASE_MS).await.unwrap().unwrap();
    assert!(fresh.token > stale.token);
    assert!(!complete(&pool, &stale, LEASE_MS + 1).await.unwrap());
    assert!(complete(&pool, &fresh, LEASE_MS + 1).await.unwrap());
    assert!(!complete(&pool, &fresh, LEASE_MS + 2).await.unwrap());
    let count: i64 = sqlx::query_scalar("SELECT count(*) FROM job_effects")
        .fetch_one(&pool)
        .await
        .unwrap();
    assert_eq!(count, 1);
    enqueue(&pool, "b", "cancel").await.unwrap();
    let b = claim(&pool, 10_000).await.unwrap().unwrap();
    assert!(cancel(&pool, "b").await.unwrap());
    assert!(!complete(&pool, &b, 10_001).await.unwrap());
    enqueue(&pool, "c", "retry").await.unwrap();
    let c = claim(&pool, 20_000).await.unwrap().unwrap();
    assert!(fail(&pool, &c, 20_001).await.unwrap());
    assert!(claim(&pool, 20_002).await.unwrap().is_none());
    assert_eq!(claim(&pool, 22_001).await.unwrap().unwrap().attempts, 2);
    enqueue(&pool, "d", "concurrent claim").await.unwrap();
    let (a, b) = tokio::join!(claim(&pool, 0), claim(&pool, 0));
    assert_eq!(
        usize::from(a.unwrap().is_some()) + usize::from(b.unwrap().is_some()),
        1
    );
    // Fill only this explicitly disposable database to the retained-job budget.
    sqlx::query(
        "INSERT INTO jobs(id,payload) SELECT 'budget-'||n,'fixture' FROM generate_series(1,10000-(SELECT count(*) FROM jobs)) n",
    )
    .execute(&pool)
    .await
    .unwrap();
    assert!(
        matches!(enqueue(&pool,"over-budget","fixture").await,Err(sqlx::Error::Protocol(message)) if message=="queue budget reached")
    );
    assert!(!enqueue(&pool, "a", "report").await.unwrap());
    pool.close().await;
}

#[tokio::test]
#[ignore = "requires isolated COURSE_SCHEDULER_TEST_DATABASE_URL"]
async fn lease_fields_cannot_rewrite_durable_payload_or_retry_count() {
    use p14_scheduler::*;
    let _fixture_guard = DATABASE_TEST_LOCK.lock().await;
    let pool = support::isolated_pool(
        "COURSE_SCHEDULER_TEST_DATABASE_URL",
        "rust_course_test_scheduler",
    )
    .await;
    sqlx::migrate!().run(&pool).await.unwrap();
    // The shared fixture mutex excludes the other database test during table reset.
    sqlx::raw_sql("TRUNCATE job_effects,jobs")
        .execute(&pool)
        .await
        .unwrap();
    enqueue(&pool, "immutable", "durable payload")
        .await
        .unwrap();
    let mut lease = claim(&pool, 0).await.unwrap().unwrap();
    lease.payload = "caller substitution".into();
    assert!(complete(&pool, &lease, 1).await.unwrap());
    let effect: String =
        sqlx::query_scalar("SELECT payload FROM job_effects WHERE job_id='immutable'")
            .fetch_one(&pool)
            .await
            .unwrap();
    assert_eq!(effect, "durable payload");
    enqueue(&pool, "retry-authority", "retry input")
        .await
        .unwrap();
    let mut lease = claim(&pool, 10_000).await.unwrap().unwrap();
    assert_eq!(lease.attempts, 1);
    lease.attempts = 3;
    assert!(fail(&pool, &lease, 10_001).await.unwrap());
    assert!(claim(&pool, 12_000).await.unwrap().is_none());
    let second = claim(&pool, 12_001).await.unwrap().unwrap();
    assert_eq!(second.attempts, 2);
    // Expiry without a reclaim also removes authority; cancellation revokes a current token.
    assert!(!complete(&pool, &second, 17_001).await.unwrap());
    assert!(!fail(&pool, &second, 17_001).await.unwrap());
    let third = claim(&pool, 17_001).await.unwrap().unwrap();
    assert_eq!(third.attempts, 3);
    assert!(claim(&pool, 22_001).await.unwrap().is_none());
    let status: String = sqlx::query_scalar("SELECT status FROM jobs WHERE id='retry-authority'")
        .fetch_one(&pool)
        .await
        .unwrap();
    assert_eq!(status, "dead");
    // Inject an effect constraint failure after authority validation. The transaction
    // must leave both effect and completion uncommitted. Remove only this test constraint.
    enqueue(&pool, "atomic-effect", "fail-transaction")
        .await
        .unwrap();
    let lease = claim(&pool, 30_000).await.unwrap().unwrap();
    sqlx::raw_sql("ALTER TABLE job_effects ADD CONSTRAINT course_injected_failure CHECK(payload <> 'fail-transaction')")
        .execute(&pool).await.unwrap();
    let outcome = complete(&pool, &lease, 30_001).await;
    sqlx::raw_sql("ALTER TABLE job_effects DROP CONSTRAINT course_injected_failure")
        .execute(&pool)
        .await
        .unwrap();
    assert!(outcome.is_err());
    let status: String = sqlx::query_scalar("SELECT status FROM jobs WHERE id='atomic-effect'")
        .fetch_one(&pool)
        .await
        .unwrap();
    let effects: i64 =
        sqlx::query_scalar("SELECT count(*) FROM job_effects WHERE job_id='atomic-effect'")
            .fetch_one(&pool)
            .await
            .unwrap();
    assert_eq!(status, "running");
    assert_eq!(effects, 0);
    assert!(complete(&pool, &lease, 30_002).await.unwrap());
    pool.close().await;
}

#[tokio::test]
#[ignore = "requires isolated COURSE_SCHEDULER_TEST_DATABASE_URL"]
async fn completion_samples_clock_after_waiting_for_its_row_lock() {
    use p14_scheduler::*;
    use std::sync::{
        Arc,
        atomic::{AtomicI64, Ordering},
    };
    let _fixture_guard = DATABASE_TEST_LOCK.lock().await;
    let pool = support::isolated_pool(
        "COURSE_SCHEDULER_TEST_DATABASE_URL",
        "rust_course_test_scheduler",
    )
    .await;
    sqlx::migrate!().run(&pool).await.unwrap();
    sqlx::raw_sql("TRUNCATE job_effects,jobs")
        .execute(&pool)
        .await
        .unwrap();
    enqueue(&pool, "delayed-lock", "clock fixture")
        .await
        .unwrap();
    let lease = claim(&pool, 0).await.unwrap().unwrap();
    let mut blocker = pool.begin().await.unwrap();
    sqlx::query("SELECT id FROM jobs WHERE id='delayed-lock' FOR UPDATE")
        .fetch_one(&mut *blocker)
        .await
        .unwrap();
    let logical_clock = Arc::new(AtomicI64::new(1));
    let worker_clock = Arc::clone(&logical_clock);
    let worker_pool = pool.clone();
    let worker = tokio::spawn(async move {
        complete_with_clock(&worker_pool, &lease, move || {
            Ok(worker_clock.load(Ordering::SeqCst))
        })
        .await
    });
    // Observe the actual PostgreSQL lock wait, not a guessed sleep duration.
    let observed_wait = tokio::time::timeout(std::time::Duration::from_secs(2), async {
        loop {
            let waiting: bool = sqlx::query_scalar("SELECT EXISTS(SELECT 1 FROM pg_locks l JOIN pg_stat_activity a USING(pid) WHERE NOT l.granted AND l.pid<>pg_backend_pid() AND a.datname=current_database())")
                .fetch_one(&pool).await.unwrap();
            if waiting { break; }
            tokio::task::yield_now().await;
        }
    }).await;
    // Advance past expiry while the worker demonstrably cannot yet lock the row.
    logical_clock.store(LEASE_MS, Ordering::SeqCst);
    blocker.rollback().await.unwrap();
    let applied = worker.await.unwrap().unwrap();
    assert!(
        observed_wait.is_ok(),
        "worker did not reach the controlled row-lock wait"
    );
    assert!(
        !applied,
        "pre-wait time must not authorize an expired lease"
    );
    let effects: i64 = sqlx::query_scalar("SELECT count(*) FROM job_effects")
        .fetch_one(&pool)
        .await
        .unwrap();
    assert_eq!(effects, 0);
    pool.close().await;
}

Guided implementation

Implement enqueue before the worker. The function starts an admission transaction and acquires a transaction-scoped advisory lock. It first looks up the logical ID and compares any stored payload, returning false only for an exact retry. Otherwise it checks the retained-row budget, inserts the unique ID and payload, and commits. The lock serializes the count-and-insert decision across callers; the unique key remains a durable invariant. The caller can then distinguish newly accepted work from an already known command without creating another durable row. Add tests for empty IDs, oversized IDs, and a conflicting payload before introducing concurrent workers.

Next inspect complete. It locks the job, verifies status, lease token, and lease expiry at the authority decision, reads the immutable payload from that locked durable row, inserts into job_effects under a unique job key, and marks the job done in the same transaction. This demonstrates one database-local deduplicated effect. It does not generalize automatically to sending money, publishing to a broker, or invoking an external HTTP endpoint.

The transactional outbox pattern

An outbox is a table of events written in the same transaction as a domain change. A relay later reads unpublished entries and delivers them. If the relay crashes after delivery but before marking an entry delivered, the event can be sent again. Consumers therefore still need idempotency or deduplication. The gain is avoiding the gap where a domain change commits but the intent to publish is lost. The reference scheduler's effect table illustrates transactional coupling; it does not include a production outbox relay. Implementing one is an independent extension with its own acceptance criteria.

Deliberate mistake and independent practice

Replace the database uniqueness rule with a HashSet initialized when the worker starts. Demonstrate that a restart permits a duplicate effect. Then design an outbox entry containing event ID, aggregate ID, payload version, and payload. Specify how long deduplication records must live and what happens when a caller retries after retention expires.

Reference reasoning

Store outbox intent with the domain transaction, retry relay delivery with the same event ID, and have the consumer transaction insert a deduplication record together with its own domain effect. Retention is part of the contract: forgetting an ID reopens the possibility of an old retry becoming a new effect. Long retention has storage and privacy costs.

Review and evidence

A rejected retry design catches every error and retries immediately. A careful design classifies retryable conditions, caps attempts, delays repeated work, and preserves logical identity. The current scheduler demonstrates bounded attempts and a deterministic delay; randomized jitter for large fleets is an extension. Tests establish selected duplicate and stale-worker behaviors in PostgreSQL. They do not prove behavior under every database failover or uncertain external response.

Playbook investigation

Observation: a report exists twice, yet the queue dashboard shows one completed job. A plausible hypothesis is duplicate enqueue. Inspect job IDs and attempt tokens. If both effects share one job ID but came from two lease attempts, duplicate enqueue is disproven. Reproduce a crash after the external effect and before completion. The fix belongs at the effect boundary, not merely at submission. Record what downstream idempotency guarantees are available and which failure window remains if none exist.

Mastery check

Explain why an acknowledgment is evidence of an observed outcome, not the outcome itself. Draw an outbox timeline with a duplicate-delivery crash window. Implement a deduplicated effect with a conflicting-payload rule and defend the retention policy without copying the reference.

//! Deterministic, in-memory lease model. Time is an injected logical tick.
//! No persistence, OS worker, external effects, or clock guarantee is implemented.
use std::collections::{BTreeMap, BTreeSet};
#[derive(Debug, Clone, PartialEq, Eq)]
enum State {
    Queued,
    Running { token: u64, expires: u64 },
    Done,
    Cancelled,
    Failed,
}
#[derive(Debug, Clone, PartialEq, Eq)]
struct Job {
    payload: String,
    state: State,
    attempts: u8,
    token: u64,
}
#[derive(Default, Debug, Clone, PartialEq, Eq)]
pub struct Queue {
    jobs: BTreeMap<String, Job>,
    effects: BTreeSet<String>,
}
impl Queue {
    pub fn enqueue(&mut self, id: &str, payload: &str) -> Result<bool, &'static str> {
        if id.is_empty() || id.len() > 64 || payload.len() > 256 {
            return Err("input budget");
        }
        if let Some(job) = self.jobs.get(id) {
            return if job.payload == payload {
                Ok(false)
            } else {
                Err("identity conflict")
            };
        }
        if self.jobs.len() >= 16 {
            return Err("retained job budget");
        }
        self.jobs.insert(
            id.into(),
            Job {
                payload: payload.into(),
                state: State::Queued,
                attempts: 0,
                token: 0,
            },
        );
        Ok(true)
    }
    pub fn claim(&mut self, id: &str, now: u64) -> Result<u64, &'static str> {
        let job = self.jobs.get_mut(id).ok_or("missing job")?;
        if !matches!(job.state, State::Queued)
            && !matches!(job.state,State::Running{expires,..}if expires<=now)
        {
            return Err("not eligible");
        }
        if job.attempts >= 3 {
            job.state = State::Failed;
            return Err("attempt budget exhausted");
        }
        let expires = now.checked_add(10).ok_or("clock overflow")?;
        let token = job.token.checked_add(1).ok_or("token overflow")?;
        job.token = token;
        job.attempts += 1;
        job.state = State::Running { token, expires };
        Ok(token)
    }
    pub fn complete(&mut self, id: &str, token: u64, now: u64) -> Result<bool, &'static str> {
        let job = self.jobs.get_mut(id).ok_or("missing job")?;
        if !matches!(job.state,State::Running{token:current,expires}if current==token&&now<expires)
        {
            return Err("stale or expired authority");
        }
        let inserted = self.effects.insert(id.into());
        job.state = State::Done;
        Ok(inserted)
    }
    pub fn cancel(&mut self, id: &str) -> Result<(), &'static str> {
        let job = self.jobs.get_mut(id).ok_or("missing job")?;
        if matches!(job.state, State::Done | State::Failed) {
            return Err("already terminal");
        }
        job.state = State::Cancelled;
        Ok(())
    }
    pub fn effects(&self) -> usize {
        self.effects.len()
    }
}
#[cfg(test)]
mod tests {
    use super::*;
    #[test]
    fn expiry_redelivers_and_fences_old_worker() {
        let mut q = Queue::default();
        q.enqueue("a", "work").unwrap();
        let first = q.claim("a", 0).unwrap();
        assert!(q.claim("a", 9).is_err());
        let second = q.claim("a", 10).unwrap();
        assert_ne!(first, second);
        assert!(q.complete("a", first, 11).is_err());
        assert!(q.complete("a", second, 11).unwrap());
        assert!(q.complete("a", second, 12).is_err());
        assert_eq!(q.effects(), 1);
    }
    #[test]
    fn retry_conflict_and_capacity() {
        let mut q = Queue::default();
        for n in 0..16 {
            q.enqueue(&format!("j{n}"), "same").unwrap();
        }
        assert!(!q.enqueue("j0", "same").unwrap());
        assert!(q.enqueue("j0", "changed").is_err());
        assert!(q.enqueue("j17", "same").is_err());
    }
    #[test]
    fn cancellation_revokes_completion() {
        let mut q = Queue::default();
        q.enqueue("a", "work").unwrap();
        let token = q.claim("a", 0).unwrap();
        q.cancel("a").unwrap();
        assert!(q.complete("a", token, 1).is_err());
        assert_eq!(q.effects(), 0);
    }
    #[test]
    fn bad_clock_does_not_partially_claim() {
        let mut q = Queue::default();
        q.enqueue("a", "work").unwrap();
        let before = q.clone();
        assert!(q.claim("a", u64::MAX).is_err());
        assert_eq!(q, before);
        for now in [0, 10, 20] {
            q.claim("a", now).unwrap();
        }
        assert!(q.claim("a", 30).is_err());
        assert_eq!(q.jobs["a"].state, State::Failed);
    }

Authority is not every field in a returned value

Lease is an owned observation returned to a worker. Its public payload and attempts fields are convenient for display, but callers can modify them. Completion must read the payload from the locked database row; retry delay must use the persisted attempt count. A focused test keeps the correct ID and token while substituting a payload and changing attempts from 1 to 3. The reference still writes the original payload and schedules the first-failure delay. Before the correction, the substituted payload became the durable effect. This disproves the tempting claim that checking a token makes every field beside it authoritative.

The same test injects a constraint failure during effect insertion and verifies that no effect appears and the job remains running. Removing the fixture constraint permits completion under the still-current lease. This is evidence for the actual database-local transaction boundary; it does not test an external email or outbox relay. Independent review of the implementation remains pending.

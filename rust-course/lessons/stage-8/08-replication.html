A deterministic replicated-state laboratory

Test narrow safety and liveness properties without claiming production consensus.

Read with a terminal open. Predict before revealing. Verified source versions: version ledger.

Prerequisites and learning objectives
  • Leases, retries, cancellation, and recovery
  • Define safety versus liveness precisely
  • Explore partitions, loss, delay and restart deterministically
  • Identify assumptions missing from a consensus protocol

Key terms: consensus · durability · invariant · mise · panic

Purpose and specification first

Build a deterministic simulator with three nodes and a permanent leader, node0. Only the leader may propose values. It assigns each value its next log index. Followers append only the next missing index and acknowledge an identical duplicate. A conflicting value at an existing index cannot overwrite it. The leader calls a prefix committed after acknowledgments from any two nodes. There is no leader election, membership change, real networking, real disk, malicious-node model, or claim to implement Raft.

Plain-English model: events instead of wall time

A simulator turns uncertain timing into explicit choices. A queue holds message objects. A step delivers or drops one object according to current node and partition state. Delay moves a packet to the end; loss removes it; crash makes a node unavailable while preserving its simulated durable vector. “Durable” here means the model preserves it across the simulator's restart action. It does not mean bytes reached a disk or survived a power failure.

A safety property says something bad never happens. Here, every follower's log must remain a prefix of the fixed leader's log, and existing entries must never change. A liveness property says something good eventually happens under explicit assumptions. Here, after the leader and one follower are online, their link is healed, and resend/delivery continues, proposed entries can reach a two-node acknowledgment count. A permanent partition can prevent progress. No amount of local type checking promises communication eventually succeeds.

Prediction

Partition the leader from both followers, propose42, and drain the queue. Has42 been committed? Heal only the link to follower1, resend, and drain again. Does follower2 need to be online for progress?

Answer

The first committed count is0. The leader's local append alone is not a two-node acknowledgment. After one follower receives and acknowledges the entry, the count becomes1. The second follower may remain isolated. This illustrates a quorum in this model, not a complete theorem about arbitrary leader changes.

Small runnable example

Working directory: rust-course/projects. This project uses only the standard library and the pinned compiler.

projects/reference/p15-replication/src/main.rs
use std::io::{self, Write};

fn main() -> io::Result<()> {
    let mut lab = p15_replication::Lab::default();
    lab.partition(0, 1, true);
    lab.partition(0, 2, true);
    // The fixed fixture has an online leader and an empty 1000-entry log.
    lab.propose(42)
        .expect("one fixed proposal fits the fresh online-leader fixture");
    lab.drain();
    let mut output = io::stdout().lock();
    writeln!(
        output,
        "partition: committed={} prefix_safe={}",
        lab.committed,
        lab.prefix_safe()
    )?;
    lab.partition(0, 1, false);
    lab.resend();
    lab.drain();
    writeln!(
        output,
        "healed: committed={} prefix_safe={}",
        lab.committed,
        lab.prefix_safe()
    )?;
    output.flush()
}

mise exec -- cargo run -p p15-replication
mise exec -- cargo test -p p15-replication

Expected output reports committed0 while partitioned and committed1 after healing, with prefix safety true in both cases. A system can remain safe while unavailable. Availability is not proved by a safety assertion.

Guided construction

Start with Node, Message, Packet, and an empty Lab. Implement leader proposal and an append-only follower rule. Test duplicate append before adding acknowledgments. Then add an acknowledgment set per index and advance the committed prefix only while every earlier index has enough acknowledgments. This last condition matters: receiving acknowledgment for a later position should not skip an uncommitted hole.

projects/reference/p15-replication/src/lib.rs
//! Deterministic fixed-leader replication simulator. NOT Raft; no leader election.
use std::collections::{BTreeSet, VecDeque};
#[derive(Clone, Debug, PartialEq, Eq)]
pub enum Message {
    Append { index: usize, value: i64 },
    Ack { index: usize },
}
#[derive(Clone, Debug)]
pub struct Packet {
    pub from: usize,
    pub to: usize,
    pub body: Message,
}
#[derive(Clone, Debug, Default)]
pub struct Node {
    pub durable: Vec<i64>,
    pub online: bool,
}
#[derive(Debug)]
pub struct Lab {
    pub nodes: [Node; 3],
    pub queue: VecDeque<Packet>,
    pub blocked: BTreeSet<(usize, usize)>,
    acks: Vec<BTreeSet<usize>>,
    pub committed: usize,
}
impl Default for Lab {
    fn default() -> Self {
        Self {
            nodes: std::array::from_fn(|_| Node {
                durable: vec![],
                online: true,
            }),
            queue: VecDeque::new(),
            blocked: BTreeSet::new(),
            acks: vec![],
            committed: 0,
        }
    }
}
impl Lab {
    pub fn propose(&mut self, value: i64) -> Result<usize, &'static str> {
        if !self.nodes[0].online {
            return Err("leader offline");
        }
        if self.nodes[0].durable.len() >= 1000 {
            return Err("log budget");
        }
        let index = self.nodes[0].durable.len();
        self.nodes[0].durable.push(value);
        self.acks.push(BTreeSet::from([0]));
        self.resend();
        Ok(index)
    }
    pub fn resend(&mut self) {
        self.queue.clear();
        for to in 1..3 {
            for (index, &value) in self.nodes[0].durable.iter().enumerate() {
                self.queue.push_back(Packet {
                    from: 0,
                    to,
                    body: Message::Append { index, value },
                });
            }
        }
    }
    pub fn partition(&mut self, a: usize, b: usize, on: bool) {
        for edge in [(a, b), (b, a)] {
            if on {
                self.blocked.insert(edge);
            } else {
                self.blocked.remove(&edge);
            }
        }
    }
    pub fn crash(&mut self, node: usize) {
        self.nodes[node].online = false;
    }
    pub fn restart(&mut self, node: usize) {
        self.nodes[node].online = true;
    }
    pub fn delay(&mut self) {
        if let Some(p) = self.queue.pop_front() {
            self.queue.push_back(p);
        }
    }
    pub fn drop_next(&mut self) {
        self.queue.pop_front();
    }
    pub fn step(&mut self) -> bool {
        let Some(packet) = self.queue.pop_front() else {
            return false;
        };
        if !self.nodes[packet.to].online || self.blocked.contains(&(packet.from, packet.to)) {
            return true;
        }
        match packet.body {
            Message::Append { index, value } => {
                if packet.from != 0 || packet.to == 0 {
                    return true;
                }
                let log = &mut self.nodes[packet.to].durable;
                if index == log.len() {
                    log.push(value);
                }
                if log.get(index) == Some(&value) {
                    self.queue.push_back(Packet {
                        from: packet.to,
                        to: 0,
                        body: Message::Ack { index },
                    });
                }
            }
            Message::Ack { index } => {
                if packet.to != 0 || packet.from == 0 {
                    return true;
                }
                if let Some(acks) = self.acks.get_mut(index) {
                    acks.insert(packet.from);
                }
                while self.committed < self.acks.len() && self.acks[self.committed].len() >= 2 {
                    self.committed += 1;
                }
            }
        }
        true
    }
    pub fn drain(&mut self) {
        while self.step() {}
    }
    pub fn prefix_safe(&self) -> bool {
        self.nodes
            .iter()
            .all(|node| self.nodes[0].durable.starts_with(&node.durable))
    }
}
#[cfg(test)]
mod tests {
    use super::*;
    #[test]
    fn partition_blocks_commit_until_heal() {
        let mut l = Lab::default();
        l.partition(0, 1, true);
        l.partition(0, 2, true);
        l.propose(7).unwrap();
        l.drain();
        assert_eq!(l.committed, 0);
        assert!(l.prefix_safe());
        l.partition(0, 1, false);
        l.resend();
        l.drain();
        assert_eq!(l.committed, 1);
    }
    #[test]
    fn duplicates_restarts_delay_and_loss() {
        for dropped in 0..12 {
            let mut l = Lab::default();
            l.propose(10).unwrap();
            l.propose(20).unwrap();
            for step in 0..12 {
                if step == dropped {
                    l.drop_next();
                }
                if step % 3 == 0 {
                    l.delay();
                }
                l.step();
                assert!(l.prefix_safe());
            }
            l.crash(1);
            l.resend();
            l.drain();
            l.restart(1);
            l.resend();
            l.drain();
            assert!(l.prefix_safe());
            assert_eq!(l.nodes[1].durable, vec![10, 20]);
            assert_eq!(l.committed, 2);
        }
    }
    #[test]
    fn conflicting_append_cannot_replace_prefix() {
        let mut l = Lab::default();
        l.propose(1).unwrap();
        l.drain();
        l.queue.push_back(Packet {
            from: 0,
            to: 1,
            body: Message::Append {
                index: 0,
                value: 999,
            },
        });
        l.drain();
        assert_eq!(l.nodes[1].durable, vec![1]);
    }
    #[test]
    fn later_and_duplicate_acknowledgments_do_not_skip_a_commit_hole() {
        let mut l = Lab::default();
        l.propose(10).unwrap();
        l.propose(20).unwrap();
        // Deliver the two legitimate appends to follower 1, but neither ack yet.
        assert!(l.step());
        assert!(l.step());
        assert_eq!(l.nodes[1].durable, [10, 20]);
        assert_eq!(l.committed, 0);
        let later = l
            .queue
            .iter()
            .position(|packet| packet.from == 1 && packet.body == Message::Ack { index: 1 })
            .unwrap();
        let ack = l.queue.remove(later).unwrap();
        for _ in 0..3 {
            l.queue.push_front(ack.clone());
            assert!(l.step());
            assert_eq!(l.committed, 0);
            assert_eq!(l.acks[1], BTreeSet::from([0, 1]));
            assert!(l.prefix_safe());
        }
        let earlier = l
            .queue
            .iter()
            .position(|packet| packet.from == 1 && packet.body == Message::Ack { index: 0 })
            .unwrap();
        let ack = l.queue.remove(earlier).unwrap();
        l.queue.push_front(ack);
        assert!(l.step());
        assert_eq!(l.committed, 2);
        assert!(l.nodes[2].durable.is_empty()); // Only leader plus one follower.
        assert!(l.prefix_safe());
    }
}

The reference resend action clears queued packets and emits the leader's current history to followers. This is a deterministic recovery shortcut, not a realistic network retransmission layer. It makes repeated healing experiments simple, but you must keep that simplification in any claimed liveness result. A production log would also need bounded replication windows, snapshots, persistent term/index metadata, and a specified recovery algorithm.

Deliberate mistake

Change the follower to append every received value regardless of index. Deliver the same append twice. The follower now has extra history and the prefix property fails. Restore the index rule. Then deliberately accept a conflicting duplicate by overwriting an existing entry. The conflict test exposes another safety violation. Neither bug requires unsafe Rust.

Independent experiments

Enumerate schedules containing two proposals, one dropped packet, one crash, and one restart. State a finite bound on steps and assert safety after every action, not only after drain. Add a new invariant that committed never decreases. Decide what should happen if the leader restarts and forgets acknowledgment sets while retaining its log. Do not add a new leader until you have written a protocol for authority and conflicting history.

Hint 1

Represent actions as data so a failing schedule can be printed and replayed exactly.

Hint 2

A safety check should run after each transition. A final converged state can hide an earlier temporary violation.

Reference reasoning

Use a bounded depth-first enumeration over a small action alphabet, prune impossible node indices, and retain the shortest failing sequence. For leader restart, reconstruct or reacquire acknowledgments and avoid reporting old commitment from unverified volatile state. The reference keeps acknowledgment state in the simulator, so changing that assumption is a genuine model extension.

Review and evidence

A misleading demonstration sends messages in perfect order and calls the result consensus. This lab explicitly perturbs delivery and states what it does not implement. Its tests check a finite family of schedules, duplicate behavior, conflict rejection, and recovery after healing. They do not constitute exhaustive model checking, a proof of linearizability, or validation of real network and disk code. Study the original Raft paper before designing election, terms, voting, or log reconciliation; do not infer those rules from this simplified fixed-leader model.

Playbook investigation

Observation: the leader reports no progress after healing. A tempting guess is that majority replication requires all three nodes. Inspect the queue and acknowledgments. If the lost append was never resent, the missing assumption is continued retransmission, not a three-node quorum. Schedule one explicit resend and see whether two acknowledgments suffice. That experiment disproves the all-nodes hypothesis for this model. If progress still fails, inspect out-of-order indices and dropped acknowledgments separately rather than changing quorum size until the test passes.

Mastery check

Explain the exact safety invariant, liveness assumptions, and simulated durability boundary. Produce a failing schedule for a deliberate bug, then fix it and retain the regression. Identify three additional mechanisms needed before this could reasonably be called a consensus implementation.

When you get stuck

Run mise exec -- cargo test -p p15-replication duplicates_restarts_delay_and_loss -- --nocapture. Print each action with queue and logs only in your learner copy. Compare the first divergence against the prefix invariant. Ask for review with a minimal replayable schedule and the precise property; “it sometimes disagrees” is not enough.

Engineering decisions and evidence

Scope and invariants: three simulated nodes, one permanent leader,1,000 log entries, bounded resend queue, immutable indexed entries, and follower-prefix safety. Simulated restart retains model state; no disk semantics are implied. Why this design: representing delivery decisions as data creates reproducible failures without wall-clock races. Concrete habits: name a precise property; assert it after transitions; preserve failing schedules; state fairness and delivery assumptions separately from safety.

Alternative: use a model checker and a formal specification for broader state exploration; use an established consensus implementation for an actual replicated service. The educational simulator exposes its state for experiments and does not validate arbitrary malicious packets or node indices as an Internet service would. Evidence: finite schedule tests establish the tested schedules only. Evolution threshold: leader change, membership change, persisted term metadata, or Byzantine participants require a new protocol specification and evidence, not a renamed function or an additional happy-path test.

Complete earlier milestone source

This transport milestone has no commitment rule yet. Taking a packet removes it from the queue; retain the value to delay or redeliver it, or discard it to model loss. Check a gap before mutating a follower.

projects/checkpoints/p15-replication/01-append-transport/src/lib.rs
//! Fixed-leader append transport model. No acknowledgments or committed prefix yet.
//! Packet scheduling is explicit data, not a real network or consensus algorithm.
use std::collections::VecDeque;
#[derive(Debug, Clone, Copy)]
pub struct Packet {
    pub to: usize,
    pub index: usize,
    pub value: i64,
}
#[derive(Default)]
pub struct Lab {
    logs: [Vec<i64>; 3],
    pending: VecDeque<Packet>,
}
impl Lab {
    pub fn propose(&mut self, value: i64) -> Result<(), &'static str> {
        if self.logs[0].len() >= 8 || self.pending.len() > 14 {
            return Err("budget");
        }
        let index = self.logs[0].len();
        self.logs[0].push(value);
        for to in [1, 2] {
            self.pending.push_back(Packet { to, index, value });
        }
        Ok(())
    }
    pub fn take(&mut self) -> Option<Packet> {
        self.pending.pop_front()
    }
    pub fn deliver(&mut self, packet: Packet) -> Result<bool, &'static str> {
        if !(1..=2).contains(&packet.to) {
            return Err("invalid follower");
        }
        let log = &mut self.logs[packet.to];
        if packet.index == log.len() {
            if log.len() >= 8 {
                return Err("log budget");
            }
            log.push(packet.value);
            return Ok(true);
        }
        if log.get(packet.index) == Some(&packet.value) {
            Ok(false)
        } else {
            Err("gap or conflict")
        }
    }
    pub fn log(&self, node: usize) -> Option<&[i64]> {
        self.logs.get(node).map(Vec::as_slice)
    }
}
#[cfg(test)]
mod tests {
    use super::*;
    #[test]
    fn duplicate_delivery_has_one_effect() {
        let mut l = Lab::default();
        l.propose(42).unwrap();
        let packet = l.take().unwrap();
        assert!(l.deliver(packet).unwrap());
        assert!(!l.deliver(packet).unwrap());
        assert_eq!(l.log(1), Some(&[42][..]));
    }
    #[test]
    fn delay_can_create_a_gap_without_corrupting_prefix() {
        let mut l = Lab::default();
        l.propose(10).unwrap();
        l.propose(20).unwrap();
        let first = l.take().unwrap();
        let _other = l.take().unwrap();
        let later = l.take().unwrap();
        assert!(l.deliver(later).is_err());
        assert_eq!(l.log(1), Some(&[][..]));
        l.deliver(first).unwrap();
        l.deliver(later).unwrap();
        assert_eq!(l.log(1), Some(&[10, 20][..]));
    }
    #[test]
    fn invalid_target_and_capacity_are_explicit() {
        let mut l = Lab::default();
        assert!(
            l.deliver(Packet {
                to: 99,
                index: 0,
                value: 3
            })
            .is_err()
        );
        for n in 0..8 {
            l.propose(n).unwrap();
        }
        assert!(l.propose(9).is_err());
        assert_eq!(l.log(0).unwrap().len(), 8);
    }
}

A small demonstration still handles its boundaries

The simulator entry point prints through a locked stdout Write implementation and returns an I/O result, so a closed pipe is an ordinary error instead of a panic. Its one expect is a stated programmer invariant: Lab::default creates an online leader with an empty bounded log, and this fixed demonstration proposes only one value. That is not permission to expect success on arbitrary learner-provided schedules; the independent driver must validate and handle its inputs. The closed-output child-process regression checks the actual demonstration executable.

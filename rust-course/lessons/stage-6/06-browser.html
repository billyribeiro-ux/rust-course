The browser is a separate computer

Build an accessible form before introducing a Rust UI framework.

Read with a terminal open. Predict before revealing. Verified source versions: version ledger.

  • Explain HTML, CSS, DOM and browser events
  • Separate client validation from server invariants
  • Inspect a request across a process boundary

Key terms: authorization · DOM · invariant · mise · polling · WASM

Purpose: a trustworthy human boundary

A backend can preserve every database invariant and still be difficult to use. A person needs to know what can be entered, whether a request is pending, whether it failed, and whether a visible value is old. This lesson builds that human boundary before introducing framework machinery. Language knowledge and interface design are different skills; both need deliberate practice.

A plain model: document, presentation, behavior

HTML describes a document and its meaning. A heading identifies a section; a label names a control; a button performs an action. CSS describes presentation such as spacing, colors and layout. The DOM, or Document Object Model, is the browser's object representation of the document. JavaScript can read or update these objects and respond to events. An event is a notification such as a click, key press or form submission.

A webpage is not a screenshot. Its semantic structure matters to screen readers, keyboard users and browser behavior. A styled div does not become a button merely by looking like one. A native button already participates in keyboard interaction, focus and form behavior. Start with elements that express the action, then style them.

Predict before opening the example

When the focused quantity input contains 4 and you press Enter, does the form submit even if you never click the button? What happens if the input contains 101? Write your prediction, including what the browser does before our event handler.

Prediction explained

Enter can submit this simple form. Native constraint validation rejects the out-of-range input before successful submission. The script still validates its numeric domain because browser controls are not a security boundary. A different client can call the backend without this HTML.

Run a small, complete form

From the course folder, run mise run course, then open the quantity form. No Rust compilation is involved in this one exercise. It teaches the browser boundary that the later Rust WASM client must obey.

Read the unfamiliar lines

The viewport meta tag asks the mobile browser to use the device width rather than a wide virtual canvas. The label's for value matches the input's ID. This creates a programmatic name and makes clicking the label focus the input. The required, minimum and maximum attributes provide useful native feedback. They do not replace backend checks.

The submit listener receives an event. preventDefault() prevents this local demonstration from navigating to a new document. Number(...) converts text to a JavaScript number; Number.isInteger rejects fractional units. Assigning textContent treats the resulting message as text. Assigning untrusted input to innerHTML would parse markup and can create an injection boundary. The status region allows assistive technology to announce the updated message without moving focus.

Deliberate mistake: feedback that disappears

Remove preventDefault() in a learner copy. Submit a valid number and observe the URL and status. The browser's default form navigation can reload the document and discard the local message. This is a behavior error, not a Rust type error. Restore the handler or intentionally use a server-rendered form with a real action; both can be sound when the entire interaction is designed.

Guided checkpoint: label, submit, explain

Reconstruct the file in three edits: create the semantic form, add the numeric constraints, then attach the submit handler. Reload after each edit. Your checkpoint passes when a mouse click and Enter both produce the same valid preview, an invalid number has understandable feedback, and Tab visibly reaches each control. At 320 pixels wide, the document must remain readable without sideways scrolling.

Independent practice

Add a second field for a symbol. Decide whether leading/trailing spaces are normalized or rejected, and explain the choice. Make the empty state different from an error state. Test the page with JavaScript disabled and describe the resulting capability rather than pretending it still performs the scripted preview.

Hint 1

Define valid symbol characters and length before choosing an input attribute. Think about case normalization and how the server will apply the same contract.

Hint 2

Use a label and a short help message connected with aria-describedby. Keep error text next to the field and do not rely on red alone.

Worked approach

Accept 1–16 uppercase ASCII letters, trim outside whitespace, and report an error for an empty normalized result or internal spaces. Server validation must still independently enforce the accepted alphabet. An equally reasonable policy rejects lowercase rather than silently normalizing it; the important part is a documented, consistent contract.

Review: a button versus a clickable rectangle

An intentionally incomplete control might attach a click listener to a div while omitting keyboard behavior and an accessible name. That is a mistake to diagnose, not the recommended starting point. A native button expresses the same intention with fewer independent failure points. Use custom controls only when a native element cannot satisfy the requirement, and then implement the full interaction contract. Complexity here is not Big-O; it is the number of behaviors you must maintain.

Playbook investigation: the handler never runs

Observation: clicking Submit with 101 produces no scripted status change. Hypothesis A: the event listener did not attach. Hypothesis B: browser validation prevented submission. A distinguishing experiment uses a valid value, 4, without changing the script. If its status appears, A is weakened. Inspect input.validity.rangeOverflow in developer tools to test B. Disabling all validation would hide the clue; the sound fix is to explain the allowed range and preserve validation at both boundaries.

When you get stuck

Concrete next action

Open browser developer tools, inspect the element's label and validity, then check the console for the first exception. Report the exact input, whether submission or navigation occurred, and the smallest HTML file that reproduces it.

Further hint

Observe the Network panel. If there is no request, do not begin by changing SQL or database permissions.

Evidence and mastery

Browser interaction supports claims about this page in the tested browser. It does not establish universal assistive-technology compatibility. Independently rebuild the form, explain why client-side validation is not authorization, and diagnose a missing label and a reload bug without the solution. Record a prediction you revised.

Engineering decisions and evidence

The current interface contract is a local, simulated service client: semantic controls, explicit loading/error/empty states, bounded sequential polling and server-authoritative mutations. Leptos 0.8.22 is used because reactive Rust state is a learning objective; the course shell itself remains static HTML. Integer-cents formatting avoids floating-point price conversion, UUID identifiers use a maintained implementation, and ambiguous writes are not automatically retried. The WASM compiler check verifies the target-specific APIs; runtime browser behavior remains pending because the saved localhost permission setting blocks the browser tool. The reference source is embedded directly and hashed by the course renderer.

An SSR client would be a reasonable alternative if initial content without WASM became a requirement. A push stream would require measured polling costs plus a bounded reconnect and slow-consumer contract. These are requirement changes, not corrections to an intentionally poor first design. Your checkpoint must include a named state transition, a failure case and the evidence that distinguishes it from a plausible alternative cause.

A bounded local health monitor

Combine capped concurrency, layered deadlines, bounded retries and shutdown into one tested service client.

Read with a terminal open. Predict before revealing. Verified source versions: version ledger.

Prerequisites and learning objectives
  • Futures, waiting and cancellation
  • Bound spawned tasks as well as active socket operations
  • Test retries and deadlines with controlled loopback listeners
  • Preserve input order while tasks finish out of order
  • Terminate spawned work explicitly on shutdown

Key terms: async · cancellation · capacity · deadline · FFI · framing · future · mise

Purpose: make a complete asynchronous tool

The finished P08 monitor performs one round over a finite list of literal loopback socket addresses. Each endpoint receives a bounded number of attempts, a timeout for each attempt and a timeout for the entire endpoint including backoff. The monitor caps how many endpoint tasks exist at once and returns rows in input order. Shutdown cancels outstanding work and waits for task cleanup. This is a teaching HTTP client: it reads a bounded status line, does not implement TLS or redirects, and does not parse general response bodies. Use an established HTTP client when those features become requirements.

Model: three budgets and one owner

The input budget allows at most 128 endpoints. The concurrency budget allows one through 32 endpoint tasks. The time budget limits each attempt and the total retry operation, while the attempt count is bounded independently. These limits protect different resources. A semaphore around the socket call would limit active connections but could still allow an unbounded number of waiting tasks if every endpoint were spawned upfront. P08 instead fills a JoinSet only to capacity, consumes a completion, then admits another endpoint. The monitor function remains the owner responsible for every spawned task.

Predict completion order and display order

Suppose endpoint A pauses before replying, B immediately returns 503 then 200, and C is healthy on its first attempt. With concurrency two, B may finish before A and permit C to start. The report still uses the original input order. Predict which facts should be stable across runs: addresses, final status under a controlled fixture, and bounded attempt counts. Exact durations and scheduling order need not be stable. A peak_in_flight value is instrumentation about admitted tasks, not proof of simultaneous CPU execution or a benchmark of networking performance.

//! A bounded one-round HTTP health monitor for literal loopback socket addresses.
use std::{io, net::SocketAddr, time::Duration};
use tokio::{
    io::{AsyncReadExt, AsyncWriteExt},
    net::TcpStream,
    sync::watch,
    task::JoinSet,
    time::{sleep, timeout},
};

#[derive(Clone, Copy, Debug)]
pub struct Config {
    pub concurrency: usize,
    pub attempts: usize,
    pub attempt_timeout: Duration,
    pub endpoint_timeout: Duration,
    pub backoff: Duration,
}
impl Default for Config {
    fn default() -> Self {
        Self {
            concurrency: 4,
            attempts: 2,
            attempt_timeout: Duration::from_millis(300),
            endpoint_timeout: Duration::from_secs(1),
            backoff: Duration::from_millis(25),
        }
    }
}
#[derive(Clone, Debug, PartialEq, Eq)]
pub enum Status {
    Healthy(u16),
    Unhealthy(u16),
    TimedOut,
    Failed(io::ErrorKind),
    InvalidResponse,
    Cancelled,
}
#[derive(Clone, Debug)]
pub struct ResultRow {
    pub address: SocketAddr,
    pub status: Status,
    pub attempts: usize,
}
#[derive(Debug)]
pub struct Report {
    pub rows: Vec<ResultRow>,
    pub peak_in_flight: usize,
}

async fn cancelled(mut shutdown: watch::Receiver<bool>) {
    loop {
        if *shutdown.borrow() {
            return;
        }
        if shutdown.changed().await.is_err() {
            return;
        }
    }
}

async fn request(address: SocketAddr) -> io::Result<Status> {
    let mut stream = TcpStream::connect(address).await?;
    let request = format!("GET /health HTTP/1.1\r\nHost: {address}\r\nConnection: close\r\n\r\n");
    stream.write_all(request.as_bytes()).await?;
    let mut line = [0u8; 256];
    let mut used = 0;
    while used < line.len() {
        let n = stream.read(&mut line[used..used + 1]).await?;
        if n == 0 {
            return Ok(Status::InvalidResponse);
        }
        used += 1;
        if used >= 2 && &line[used - 2..used] == b"\r\n" {
            let Ok(text) = std::str::from_utf8(&line[..used - 2]) else {
                return Ok(Status::InvalidResponse);
            };
            let mut parts = text.split_ascii_whitespace();
            if !matches!(parts.next(), Some("HTTP/1.1" | "HTTP/1.0")) {
                return Ok(Status::InvalidResponse);
            }
            let Some(code) = parts
                .next()
                .filter(|s| s.len() == 3)
                .and_then(|s| s.parse::<u16>().ok())
            else {
                return Ok(Status::InvalidResponse);
            };
            return Ok(if (200..300).contains(&code) {
                Status::Healthy(code)
            } else if (100..600).contains(&code) {
                Status::Unhealthy(code)
            } else {
                Status::InvalidResponse
            });
        }
    }
    Ok(Status::InvalidResponse)
}

async fn probe(address: SocketAddr, config: Config, shutdown: watch::Receiver<bool>) -> ResultRow {
    let mut attempts = 0;
    let work = async {
        let mut status = Status::TimedOut;
        for attempt in 0..config.attempts {
            if attempt > 0 {
                sleep(config.backoff).await;
            }
            attempts += 1;
            status = match timeout(config.attempt_timeout, request(address)).await {
                Ok(Ok(status)) => status,
                Ok(Err(error)) => Status::Failed(error.kind()),
                Err(_) => Status::TimedOut,
            };
            if matches!(status, Status::Healthy(_)) {
                break;
            }
        }
        status
    };
    let status = tokio::select! {
        biased;
        () = cancelled(shutdown) => Status::Cancelled,
        result = timeout(config.endpoint_timeout, work) => result.unwrap_or(Status::TimedOut),
    };
    ResultRow {
        address,
        status,
        attempts,
    }
}

pub async fn monitor(
    addresses: Vec<SocketAddr>,
    config: Config,
    shutdown: watch::Receiver<bool>,
) -> io::Result<Report> {
    if addresses.len() > 128
        || addresses.iter().any(|a| !a.ip().is_loopback())
        || !(1..=32).contains(&config.concurrency)
        || !(1..=4).contains(&config.attempts)
        || config.attempt_timeout.is_zero()
        || config.attempt_timeout > Duration::from_secs(10)
        || config.endpoint_timeout.is_zero()
        || config.endpoint_timeout > Duration::from_secs(30)
        || config.backoff > Duration::from_secs(1)
    {
        return Err(io::Error::new(
            io::ErrorKind::InvalidInput,
            "literal loopback endpoints and bounded nonzero limits required",
        ));
    }
    let mut tasks = JoinSet::new();
    let mut next = 0;
    let mut peak = 0;
    let mut rows = vec![None; addresses.len()];
    loop {
        if *shutdown.borrow() || shutdown.has_changed().is_err() {
            tasks.abort_all();
            break;
        }
        while next < addresses.len() && tasks.len() < config.concurrency {
            let index = next;
            let address = addresses[index];
            let shutdown = shutdown.clone();
            tasks.spawn(async move { (index, probe(address, config, shutdown).await) });
            next += 1;
        }
        peak = peak.max(tasks.len());
        if tasks.is_empty() {
            break;
        }
        tokio::select! {
            biased;
            () = cancelled(shutdown.clone()) => { tasks.abort_all(); break; }
            result = tasks.join_next() => match result {
                Some(Ok((index, row))) => rows[index] = Some(row),
                Some(Err(error)) => { tasks.abort_all(); while tasks.join_next().await.is_some() {} return Err(io::Error::other(error)); },
                None => break,
            }
        }
    }
    // Await aborted tasks: no detached work remains after this function returns.
    while tasks.join_next().await.is_some() {}
    let rows = addresses
        .into_iter()
        .enumerate()
        .map(|(index, address)| {
            rows[index].take().unwrap_or(ResultRow {
                address,
                status: Status::Cancelled,
                attempts: 0,
            })
        })
        .collect();
    Ok(Report {
        rows,
        peak_in_flight: peak,
    })
}

#[cfg(test)]
mod tests {
    use super::*;
    use tokio::net::TcpListener;
    async fn server(responses: Vec<&'static [u8]>) -> (SocketAddr, tokio::task::JoinHandle<()>) {
        let listener = TcpListener::bind("127.0.0.1:0").await.unwrap();
        let address = listener.local_addr().unwrap();
        let task = tokio::spawn(async move {
            for response in responses {
                let (mut stream, _) = listener.accept().await.unwrap();
                let mut request = [0; 512];
                let _ = stream.read(&mut request).await;
                stream.write_all(response).await.unwrap();
            }
        });
        (address, task)
    }
    #[tokio::test]
    async fn retries_then_recovers() {
        let (address, task) = server(vec![
            b"HTTP/1.1 503 Unavailable\r\n\r\n",
            b"HTTP/1.1 200 OK\r\n\r\n",
        ])
        .await;
        let (_tx, rx) = watch::channel(false);
        let report = monitor(vec![address], Config::default(), rx).await.unwrap();
        assert_eq!(report.rows[0].status, Status::Healthy(200));
        assert_eq!(report.rows[0].attempts, 2);
        task.await.unwrap();
    }
    #[tokio::test]
    async fn malformed_response_is_bounded() {
        let (address, task) = server(vec![b"not-http\r\n"]).await;
        let (_tx, rx) = watch::channel(false);
        let report = monitor(
            vec![address],
            Config {
                attempts: 1,
                ..Config::default()
            },
            rx,
        )
        .await
        .unwrap();
        assert_eq!(report.rows[0].status, Status::InvalidResponse);
        task.await.unwrap();
    }
    #[tokio::test]
    async fn hung_endpoint_has_a_deadline() {
        let listener = TcpListener::bind("127.0.0.1:0").await.unwrap();
        let address = listener.local_addr().unwrap();
        let task = tokio::spawn(async move {
            let (_stream, _) = listener.accept().await.unwrap();
            std::future::pending::<()>().await;
        });
        let (_tx, rx) = watch::channel(false);
        let config = Config {
            attempts: 1,
            attempt_timeout: Duration::from_millis(30),
            ..Config::default()
        };
        let report = timeout(Duration::from_secs(3), monitor(vec![address], config, rx))
            .await
            .unwrap()
            .unwrap();
        assert_eq!(report.rows[0].status, Status::TimedOut);
        task.abort();
        let _ = task.await;
    }
    #[tokio::test]
    async fn concurrency_cap_and_input_order_hold() {
        let (a, one) = server(vec![b"HTTP/1.1 200 OK\r\n\r\n"]).await;
        let (b, two) = server(vec![b"HTTP/1.1 204 No Content\r\n\r\n"]).await;
        let (_tx, rx) = watch::channel(false);
        let report = monitor(
            vec![b, a],
            Config {
                concurrency: 1,
                ..Config::default()
            },
            rx,
        )
        .await
        .unwrap();
        assert_eq!(report.peak_in_flight, 1);
        assert_eq!(report.rows[0].address, b);
        assert_eq!(report.rows[1].address, a);
        one.await.unwrap();
        two.await.unwrap();
    }
    #[tokio::test]
    async fn shutdown_aborts_in_flight_and_unstarted_work() {
        let listener = TcpListener::bind("127.0.0.1:0").await.unwrap();
        let address = listener.local_addr().unwrap();
        let (accepted_tx, accepted_rx) = tokio::sync::oneshot::channel();
        let server = tokio::spawn(async move {
            let (_stream, _) = listener.accept().await.unwrap();
            let _ = accepted_tx.send(());
            std::future::pending::<()>().await;
        });
        let (tx, rx) = watch::channel(false);
        let work = tokio::spawn(monitor(
            vec![address; 3],
            Config {
                concurrency: 1,
                ..Config::default()
            },
            rx,
        ));
        accepted_rx.await.unwrap();
        tx.send(true).unwrap();
        let report = timeout(Duration::from_secs(3), work)
            .await
            .unwrap()
            .unwrap()
            .unwrap();
        assert!(
            report
                .rows
                .iter()
                .all(|row| row.status == Status::Cancelled)
        );
        server.abort();
        let _ = server.await;
    }
    #[tokio::test]
    async fn rejects_remote_addresses() {
        let (_tx, rx) = watch::channel(false);
        assert!(
            monitor(vec!["192.0.2.1:80".parse().unwrap()], Config::default(), rx)
                .await
                .is_err()
        );
    }

monitor validates all addresses before starting, so a non-loopback entry rejects the batch without initiating network work. It allocates bounded result slots, tracks the next input index and fills the task set up to concurrency. Each task returns its index with its row. Completion stores the result in that indexed slot; this decouples display order from scheduling. When shutdown arrives, abort_all requests cancellation, and the subsequent join loop waits for tasks to leave the set. Missing rows become Cancelled. Their attempts field is zero because aborted task-local progress was not returned; do not reinterpret that as proof that no request reached the endpoint.

Retries change load as well as reliability

Retrying a transient failure can recover a healthy result, but it also creates additional work. The reference retries nonhealthy outcomes up to a small limit, sleeping a fixed backoff between attempts. All retry delays count against the total endpoint deadline. A production policy might distinguish retryable statuses, use jitter or coordinate rate limits, but adding those features before specifying the current semantics would obscure the lesson. First test a listener that returns 503 once and then 200. Assert two attempts and a healthy final status. Also test a permanently malformed response with attempts set to one so the expected transport conversation is exact.

Failure injection comes from controlled peers

The tests bind 127.0.0.1:0, letting the operating system choose a free port. One fixture sends a valid status line, another sends malformed bytes, and a hanging fixture accepts a connection without replying. The shutdown test uses a oneshot notification to prove the server accepted the connection before cancellation is issued. That synchronization is stronger evidence than sleeping for an arbitrary interval and hoping the request has started. The outer test timeout prevents an accidental infinite wait from consuming the entire suite; it is not the timeout being tested. Keep those two purposes separate in the test name and explanation.

Playbook investigation: shutdown returned but traffic continued

Observation: a local fixture records another connection after a learner's monitor reported shutdown. Hypothesis A says the fixture's log was buffered. Hypothesis B says spawned tasks were detached when handles were dropped. Hypothesis C says an already-sent request arrived late. These hypotheses require different experiments. Add task-start and task-finish counters owned by the test fixture, trigger shutdown after a known acceptance signal, and await the monitor's return. A nonzero live-task count after return disproves the claim that all work was joined. A zero count with a previously sent request points toward observation timing rather than an active task leak.

The fix must match the evidence: retain task ownership, abort outstanding tasks and drain joins if B is supported. Do not assert that this retracts requests already delivered to the peer. Preserve the counter trace and the acceptance signal in the regression test. For an independent investigation, decide whether your API needs accurate per-endpoint attempts after forced cancellation; if so, design explicit progress reporting rather than inventing a count when the task is aborted.

Guided checkpoint and independent practice

Extend the local fixture to send a status line longer than 256 bytes without a valid terminating line. Assert bounded rejection. Then choose a policy for duplicate endpoints: preserve each input row, deduplicate work while retaining rows, or reject duplicates. The reference preserves them. Write acceptance examples before modifying admission logic. Independently add a local fixture that delays its second response so total endpoint time expires during a retry. Your evidence should show that the total deadline includes backoff and that no detached task survives the returned report.

Engineering decisions and evidence

Current scope and invariants. Only literal loopback endpoints are admitted. Input count, task count, attempts, status-line storage and deadlines are bounded. Every spawned task stays owned until joined or aborted and drained.

Why this is the current recommended shape. Tokio socket I/O yields while waiting; JoinSet bounds task creation directly. Per-attempt and total deadlines cover different scopes, and a watch channel carries shutdown state. Results retain input indices so scheduling does not change report order. Controlled local listeners make failure tests reproducible.

Reasonable alternative and tradeoff. A maintained HTTP client is the appropriate choice when TLS, redirects, connection pooling, complete framing or real HTTP interoperability is required. The tiny status-line parser is a deliberately scoped transport exercise. A semaphore is useful for shared permits but would not by itself bound the number of spawned waiting tasks.

Evidence and limits. Native reference tests were run through mise in the coordinated course verification; inspect the current verification record for exact results. 503 then healthy retry; malformed response; stalled read deadline; concurrency-one cap and input order; shutdown after a known acceptance signal; remote-address rejection. Cancellation stops local future work, not requests already sent. Aborted rows do not retain task-local attempt counts. Deadlines are cooperative rather than real-time guarantees. No TLS, redirects or response-body parser is implemented.

Requirement that would justify evolution. Replace the transport parser as soon as requirements exceed one bounded local status line. Add jitter, rate policy and observability only when operating requirements specify them. Accurate attempt counts for forcibly aborted tasks require explicit progress reporting.

In your review, explain this choice in your own words, preserve the behavioral contract during changes, and name the evidence that would make you choose the alternative. Deliberately broken variants above are diagnostic exercises, never recommended implementation stages.

Validate the complete request before starting work

The command accepts no arguments for its owned local demonstration, or one through 128 literal loopback socket addresses. Every supplied argument must satisfy that contract; an extra malformed endpoint is never ignored. Read the CLI's arguments function before the async run function. It uses args_os, checks UTF-8 explicitly, parses SocketAddr, and checks the loopback and count limits before opening a listener or spawning a signal task.

projects/reference/p08-monitor/src/main.rs
use std::{
    io::{self, Write},
    net::SocketAddr,
    process::ExitCode,
};
use tokio::{
    io::{AsyncReadExt, AsyncWriteExt},
    net::TcpListener,
    sync::watch,
};
fn arguments() -> io::Result<Vec<SocketAddr>> {
    let mut addresses = Vec::new();
    for argument in std::env::args_os().skip(1) {
        if addresses.len() == 128 {
            return Err(io::Error::new(
                io::ErrorKind::InvalidInput,
                "at most 128 endpoints are supported",
            ));
        }
        let text = argument.to_str().ok_or_else(|| {
            io::Error::new(io::ErrorKind::InvalidInput, "endpoint must be valid UTF-8")
        })?;
        let address = text.parse::<SocketAddr>().map_err(|error| {
            io::Error::new(
                io::ErrorKind::InvalidInput,
                format!("expected IP:PORT endpoint: {error}"),
            )
        })?;
        if !address.ip().is_loopback() {
            return Err(io::Error::new(
                io::ErrorKind::InvalidInput,
                "only literal loopback endpoints are supported",
            ));
        }
        addresses.push(address);
    }
    Ok(addresses)
}

async fn run() -> io::Result<()> {
    // Parse every endpoint before creating a listener, signal task or network request.
    let mut addresses = arguments()?;
    let mut demo = None;
    if addresses.is_empty() {
        let listener = TcpListener::bind("127.0.0.1:0").await?;
        let address = listener.local_addr()?;
        demo = Some(tokio::spawn(async move {
            loop {
                let Ok((mut stream, _)) = listener.accept().await else {
                    break;
                };
                let mut buf = [0; 512];
                let _ = stream.read(&mut buf).await;
                let _ = stream
                    .write_all(
                        b"HTTP/1.1 200 OK\r\nContent-Length: 2\r\nConnection: close\r\n\r\nOK",
                    )
                    .await;
            }
        }));
        addresses.push(address);
    }
    let (tx, rx) = watch::channel(false);
    let signal = tokio::spawn(async move {
        let _ = tokio::signal::ctrl_c().await;
        let _ = tx.send(true);
    });
    let result = p08_monitor::monitor(addresses, p08_monitor::Config::default(), rx).await;
    signal.abort();
    let _ = signal.await;
    if let Some(demo) = demo {
        demo.abort();
        let _ = demo.await;
    }
    let report = result?;
    // All async work is drained before taking the synchronous stdout lock.
    let mut output = io::stdout().lock();
    for row in report.rows {
        writeln!(
            output,
            "{} {:?} attempts={}",
            row.address, row.status, row.attempts
        )?;
    }
    writeln!(output, "peak_in_flight={}", report.peak_in_flight)?;
    output.flush()?;
    Ok(())
}

#[tokio::main]
async fn main() -> ExitCode {
    match run().await {
        Ok(()) => ExitCode::SUCCESS,
        Err(error) => {
            let _ = writeln!(io::stderr().lock(), "monitor: {error}");
            if error.kind() == io::ErrorKind::InvalidInput {
                ExitCode::from(2)
            } else {
                ExitCode::FAILURE
            }
        }
    }
}

Investigation: a valid first address followed by an invalid address could reveal a parse-while-spawning bug. Predict whether the first server should observe a connection. The process-level test owns a listening socket, runs this two-argument request, checks input-error status, and then observes no queued connection. Together with the control-flow review, this supports validation before external work for that boundary. Non-UTF-8 text is also rejected normally; std::env::args previously panicked during iteration. Run mise exec -- cargo test --manifest-path projects/Cargo.toml -p p08-monitor --test cli from the course root.

The OS still controls scheduling, and this finite test does not prove every future CLI revision preserves the ordering. For independent practice, add a named option while keeping the entire parse separate from runtime work; specify how unknown options behave. Review its ownership and task creation points, not only the final status code. Exact evidence; checked native-text conversion.

Output is an I/O boundary too. The CLI writes through a locked io::Write handle and propagates ordinary stdout failures, including a pipe whose consumer has closed. Final stderr diagnostics are best effort: a second write failure must not replace the original failure with a panic. The process tests create an anonymous pipe and close its reading end before launching the child, so this experiment does not depend on a race with a shell command.

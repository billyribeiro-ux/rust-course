Futures, waiting and cancellation

Understand async state, polling and deadlines before composing a health monitor.

Read with a terminal open. Predict before revealing. Verified source versions: version ledger.

Prerequisites and learning objectives
  • Bound memory and make concurrent results reproducible
  • Distinguish creating a future from executing its work
  • Explain what state survives an await point
  • Understand why blocking work defeats cooperative deadlines
  • State what cancellation can and cannot undo

Key terms: async · borrow · cancellation · closure · deadline · framing · future · mise

Purpose: wait for sockets without dedicating a thread to each wait

Our indexer used synchronous reads and a fixed number of operating-system threads. The health monitor has a different workload: many small operations spend most of their time waiting for sockets. Async Rust represents those operations as futures that a runtime polls. When an operation cannot progress, it can arrange to be woken when progress may be possible. This permits many waiting operations to share a smaller set of executor threads. It does not automatically parallelize CPU-heavy code, remove ownership requirements, or make an arbitrary blocking function cancellable.

Model: a future is a suspended computation with owned state

An async function returns a future. Its body progresses when that future is polled, typically through await or spawning on a runtime. Values needed after a suspension point become part of the future's stored state. In P08, the socket and a bounded status-line buffer live across reads. The runtime can stop polling one future while another becomes ready. An await is a potential suspension point, not a promise that suspension always occurs. If the awaited operation is immediately ready, execution can continue without handing another task a turn.

Predict the deadline boundary

Imagine a request that connects successfully but never receives a response byte. A timeout wrapping only connect would not protect the read. A timeout wrapping the whole request covers connect, request write and status-line read together. Now imagine a CPU loop inside that future which never awaits. A cooperative runtime cannot force that loop to yield merely because a timer deadline passes. Before running the reference, mark the exact expression covered by attempt_timeout and the larger expression covered by endpoint_timeout. Include retry backoff in the latter budget.

//! A bounded one-round HTTP health monitor for literal loopback socket addresses.
use std::{io, net::SocketAddr, time::Duration};
use tokio::{
    io::{AsyncReadExt, AsyncWriteExt},
    net::TcpStream,
    sync::watch,
    task::JoinSet,
    time::{sleep, timeout},
};

#[derive(Clone, Copy, Debug)]
pub struct Config {
    pub concurrency: usize,
    pub attempts: usize,
    pub attempt_timeout: Duration,
    pub endpoint_timeout: Duration,
    pub backoff: Duration,
}
impl Default for Config {
    fn default() -> Self {
        Self {
            concurrency: 4,
            attempts: 2,
            attempt_timeout: Duration::from_millis(300),
            endpoint_timeout: Duration::from_secs(1),
            backoff: Duration::from_millis(25),
        }
    }
}
#[derive(Clone, Debug, PartialEq, Eq)]
pub enum Status {
    Healthy(u16),
    Unhealthy(u16),
    TimedOut,
    Failed(io::ErrorKind),
    InvalidResponse,
    Cancelled,
}
#[derive(Clone, Debug)]
pub struct ResultRow {
    pub address: SocketAddr,
    pub status: Status,
    pub attempts: usize,
}
#[derive(Debug)]
pub struct Report {
    pub rows: Vec<ResultRow>,
    pub peak_in_flight: usize,
}

async fn cancelled(mut shutdown: watch::Receiver<bool>) {
    loop {
        if *shutdown.borrow() {
            return;
        }
        if shutdown.changed().await.is_err() {
            return;
        }
    }
}

async fn request(address: SocketAddr) -> io::Result<Status> {
    let mut stream = TcpStream::connect(address).await?;
    let request = format!("GET /health HTTP/1.1\r\nHost: {address}\r\nConnection: close\r\n\r\n");
    stream.write_all(request.as_bytes()).await?;
    let mut line = [0u8; 256];
    let mut used = 0;
    while used < line.len() {
        let n = stream.read(&mut line[used..used + 1]).await?;
        if n == 0 {
            return Ok(Status::InvalidResponse);
        }
        used += 1;
        if used >= 2 && &line[used - 2..used] == b"\r\n" {
            let Ok(text) = std::str::from_utf8(&line[..used - 2]) else {
                return Ok(Status::InvalidResponse);
            };
            let mut parts = text.split_ascii_whitespace();
            if !matches!(parts.next(), Some("HTTP/1.1" | "HTTP/1.0")) {
                return Ok(Status::InvalidResponse);
            }
            let Some(code) = parts
                .next()
                .filter(|s| s.len() == 3)
                .and_then(|s| s.parse::<u16>().ok())
            else {
                return Ok(Status::InvalidResponse);
            };
            return Ok(if (200..300).contains(&code) {
                Status::Healthy(code)
            } else if (100..600).contains(&code) {
                Status::Unhealthy(code)
            } else {
                Status::InvalidResponse
            });
        }
    }
    Ok(Status::InvalidResponse)
}

async fn probe(address: SocketAddr, config: Config, shutdown: watch::Receiver<bool>) -> ResultRow {
    let mut attempts = 0;
    let work = async {
        let mut status = Status::TimedOut;
        for attempt in 0..config.attempts {
            if attempt > 0 {
                sleep(config.backoff).await;
            }
            attempts += 1;
            status = match timeout(config.attempt_timeout, request(address)).await {
                Ok(Ok(status)) => status,
                Ok(Err(error)) => Status::Failed(error.kind()),
                Err(_) => Status::TimedOut,
            };
            if matches!(status, Status::Healthy(_)) {
                break;
            }
        }
        status
    };
    let status = tokio::select! {
        biased;
        () = cancelled(shutdown) => Status::Cancelled,
        result = timeout(config.endpoint_timeout, work) => result.unwrap_or(Status::TimedOut),
    };
    ResultRow {
        address,
        status,
        attempts,
    }
}

pub async fn monitor(
    addresses: Vec<SocketAddr>,
    config: Config,
    shutdown: watch::Receiver<bool>,
) -> io::Result<Report> {
    if addresses.len() > 128
        || addresses.iter().any(|a| !a.ip().is_loopback())
        || !(1..=32).contains(&config.concurrency)
        || !(1..=4).contains(&config.attempts)
        || config.attempt_timeout.is_zero()
        || config.attempt_timeout > Duration::from_secs(10)
        || config.endpoint_timeout.is_zero()
        || config.endpoint_timeout > Duration::from_secs(30)
        || config.backoff > Duration::from_secs(1)
    {
        return Err(io::Error::new(
            io::ErrorKind::InvalidInput,
            "literal loopback endpoints and bounded nonzero limits required",
        ));
    }
    let mut tasks = JoinSet::new();
    let mut next = 0;
    let mut peak = 0;
    let mut rows = vec![None; addresses.len()];
    loop {
        if *shutdown.borrow() || shutdown.has_changed().is_err() {
            tasks.abort_all();
            break;
        }
        while next < addresses.len() && tasks.len() < config.concurrency {
            let index = next;
            let address = addresses[index];
            let shutdown = shutdown.clone();
            tasks.spawn(async move { (index, probe(address, config, shutdown).await) });
            next += 1;
        }
        peak = peak.max(tasks.len());
        if tasks.is_empty() {
            break;
        }
        tokio::select! {
            biased;
            () = cancelled(shutdown.clone()) => { tasks.abort_all(); break; }
            result = tasks.join_next() => match result {
                Some(Ok((index, row))) => rows[index] = Some(row),
                Some(Err(error)) => { tasks.abort_all(); while tasks.join_next().await.is_some() {} return Err(io::Error::other(error)); },
                None => break,
            }
        }
    }
    // Await aborted tasks: no detached work remains after this function returns.
    while tasks.join_next().await.is_some() {}
    let rows = addresses
        .into_iter()
        .enumerate()
        .map(|(index, address)| {
            rows[index].take().unwrap_or(ResultRow {
                address,
                status: Status::Cancelled,
                attempts: 0,
            })
        })
        .collect();
    Ok(Report {
        rows,
        peak_in_flight: peak,
    })
}

#[cfg(test)]
mod tests {
    use super::*;
    use tokio::net::TcpListener;
    async fn server(responses: Vec<&'static [u8]>) -> (SocketAddr, tokio::task::JoinHandle<()>) {
        let listener = TcpListener::bind("127.0.0.1:0").await.unwrap();
        let address = listener.local_addr().unwrap();
        let task = tokio::spawn(async move {
            for response in responses {
                let (mut stream, _) = listener.accept().await.unwrap();
                let mut request = [0; 512];
                let _ = stream.read(&mut request).await;
                stream.write_all(response).await.unwrap();
            }
        });
        (address, task)
    }
    #[tokio::test]
    async fn retries_then_recovers() {
        let (address, task) = server(vec![
            b"HTTP/1.1 503 Unavailable\r\n\r\n",
            b"HTTP/1.1 200 OK\r\n\r\n",
        ])
        .await;
        let (_tx, rx) = watch::channel(false);
        let report = monitor(vec![address], Config::default(), rx).await.unwrap();
        assert_eq!(report.rows[0].status, Status::Healthy(200));
        assert_eq!(report.rows[0].attempts, 2);
        task.await.unwrap();
    }
    #[tokio::test]
    async fn malformed_response_is_bounded() {
        let (address, task) = server(vec![b"not-http\r\n"]).await;
        let (_tx, rx) = watch::channel(false);
        let report = monitor(
            vec![address],
            Config {
                attempts: 1,
                ..Config::default()
            },
            rx,
        )
        .await
        .unwrap();
        assert_eq!(report.rows[0].status, Status::InvalidResponse);
        task.await.unwrap();
    }
    #[tokio::test]
    async fn hung_endpoint_has_a_deadline() {
        let listener = TcpListener::bind("127.0.0.1:0").await.unwrap();
        let address = listener.local_addr().unwrap();
        let task = tokio::spawn(async move {
            let (_stream, _) = listener.accept().await.unwrap();
            std::future::pending::<()>().await;
        });
        let (_tx, rx) = watch::channel(false);
        let config = Config {
            attempts: 1,
            attempt_timeout: Duration::from_millis(30),
            ..Config::default()
        };
        let report = timeout(Duration::from_secs(3), monitor(vec![address], config, rx))
            .await
            .unwrap()
            .unwrap();
        assert_eq!(report.rows[0].status, Status::TimedOut);
        task.abort();
        let _ = task.await;
    }
    #[tokio::test]
    async fn concurrency_cap_and_input_order_hold() {
        let (a, one) = server(vec![b"HTTP/1.1 200 OK\r\n\r\n"]).await;
        let (b, two) = server(vec![b"HTTP/1.1 204 No Content\r\n\r\n"]).await;
        let (_tx, rx) = watch::channel(false);
        let report = monitor(
            vec![b, a],
            Config {
                concurrency: 1,
                ..Config::default()
            },
            rx,
        )
        .await
        .unwrap();
        assert_eq!(report.peak_in_flight, 1);
        assert_eq!(report.rows[0].address, b);
        assert_eq!(report.rows[1].address, a);
        one.await.unwrap();
        two.await.unwrap();
    }
    #[tokio::test]
    async fn shutdown_aborts_in_flight_and_unstarted_work() {
        let listener = TcpListener::bind("127.0.0.1:0").await.unwrap();
        let address = listener.local_addr().unwrap();
        let (accepted_tx, accepted_rx) = tokio::sync::oneshot::channel();
        let server = tokio::spawn(async move {
            let (_stream, _) = listener.accept().await.unwrap();
            let _ = accepted_tx.send(());
            std::future::pending::<()>().await;
        });
        let (tx, rx) = watch::channel(false);
        let work = tokio::spawn(monitor(
            vec![address; 3],
            Config {
                concurrency: 1,
                ..Config::default()
            },
            rx,
        ));
        accepted_rx.await.unwrap();
        tx.send(true).unwrap();
        let report = timeout(Duration::from_secs(3), work)
            .await
            .unwrap()
            .unwrap()
            .unwrap();
        assert!(
            report
                .rows
                .iter()
                .all(|row| row.status == Status::Cancelled)
        );
        server.abort();
        let _ = server.await;
    }
    #[tokio::test]
    async fn rejects_remote_addresses() {
        let (_tx, rx) = watch::channel(false);
        assert!(
            monitor(vec!["192.0.2.1:80".parse().unwrap()], Config::default(), rx)
                .await
                .is_err()
        );
    }
}

request performs one transport attempt and owns its TcpStream. probe loops over a bounded attempt count. Each attempt wraps request in timeout, converts transport and elapsed errors to explicit statuses, and stops after a healthy response. A separate timeout covers the full retry operation. tokio::select! races that operation against a cancellation future. When one branch completes, the losing future is dropped. Because request owns the socket, dropping it releases that local socket handle. Nothing in this structure says that bytes already transmitted are withdrawn or that a remote peer forgets the request.

Cancellation is a semantic decision

Canceling a read-only health probe is comparatively simple: the monitor abandons interest in a result and closes local work. Canceling a payment request or a database mutation would need a different story because remote side effects may already have occurred. Carry the uncertain-outcome lesson from storage into async programming. Dropping a future stops future polling of that computation; it does not travel backward in time. If a spawned task is detached by dropping only its handle, that task may continue. P08 retains task ownership in a JoinSet, aborts outstanding tasks on shutdown, and drains the set before returning.

The shutdown channel carries the latest boolean state. The cancellation helper checks the current value before waiting for changes, preventing an already-issued shutdown from being missed. A closed sender is also treated as cancellation so the monitor does not keep running without its owner. Be careful with borrowed watch values: a borrow guard should not accidentally be kept across an await. The reference checks the value in a short expression and then separately awaits change.

Playbook investigation: a timeout does not fire on time

Observation: a modified monitor returns much later than its configured timeout. Hypothesis A says Tokio's clock is broken. Hypothesis B says code blocks an executor thread or performs a long non-yielding loop. Hypothesis C says the timeout wraps only part of the operation. You choose the first experiment. One strong disproof of A is to run a timeout around a simple pending future in the same runtime and observe prompt completion. Then replace the suspect body with async sleep and compare. Inspect the placement of timeout separately so you do not conflate scheduling and coverage mistakes.

A fix may move blocking work to an appropriate bounded blocking facility or enlarge the timeout's lexical coverage. The evidence must show the stalled operation, not just an easy successful request. Its limits include scheduler delays and the fact that deadlines are cooperative rather than real-time guarantees. State what was canceled locally and what external side effects, if any, could already have happened.

Engineering decisions and evidence

Current scope and invariants. Only literal loopback endpoints are admitted. Input count, task count, attempts, status-line storage and deadlines are bounded. Every spawned task stays owned until joined or aborted and drained.

Why this is the current recommended shape. Tokio socket I/O yields while waiting; JoinSet bounds task creation directly. Per-attempt and total deadlines cover different scopes, and a watch channel carries shutdown state. Results retain input indices so scheduling does not change report order. Controlled local listeners make failure tests reproducible.

Reasonable alternative and tradeoff. A maintained HTTP client is the appropriate choice when TLS, redirects, connection pooling, complete framing or real HTTP interoperability is required. The tiny status-line parser is a deliberately scoped transport exercise. A semaphore is useful for shared permits but would not by itself bound the number of spawned waiting tasks.

Evidence and limits. Native reference tests were run through mise in the coordinated course verification; inspect the current verification record for exact results. 503 then healthy retry; malformed response; stalled read deadline; concurrency-one cap and input order; shutdown after a known acceptance signal; remote-address rejection. Cancellation stops local future work, not requests already sent. Aborted rows do not retain task-local attempt counts. Deadlines are cooperative rather than real-time guarantees. No TLS, redirects or response-body parser is implemented.

Requirement that would justify evolution. Replace the transport parser as soon as requirements exceed one bounded local status line. Add jitter, rate policy and observability only when operating requirements specify them. Accurate attempt counts for forcibly aborted tasks require explicit progress reporting.

In your review, explain this choice in your own words, preserve the behavioral contract during changes, and name the evidence that would make you choose the alternative. Deliberately broken variants above are diagnostic exercises, never recommended implementation stages.

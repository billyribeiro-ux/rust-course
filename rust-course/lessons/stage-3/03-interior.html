Cell and RefCell: shared ownership with checked access

Give two synchronous callbacks one bounded audit buffer, then investigate dynamic borrow conflicts, snapshots, and guard cleanup.

Read with a terminal open. Predict before revealing. Verified source versions: version ledger.

Prerequisites and learning objectives
  • Resource ownership and the failure path
  • Separate Rc shared ownership from Cell and RefCell mutation mechanisms.
  • Return ordinary errors for reachable dynamic borrow conflicts.
  • Trace RefCell guard lifetime through nested callbacks and unwinding.
  • Justify interior mutability against exclusive ownership and a new cross-thread requirement.
  • Distinguish strong and weak ownership, handle failed upgrades, and identify reference-count cycles in a proposed callback graph.

Key terms: allocation · async · atomic · borrow · cancellation · capacity · drop · future

Purpose: share one small state without hiding the ownership cost

Suppose two synchronous callbacks need to retain handles to the same local audit buffer. They record short messages and can temporarily disable recording. A single exclusive owner passing &mut Vec would be the simplest design if the callbacks did not need independently retained handles. Here that lifetime requirement is explicit, so the lab uses reference-counted ownership and controlled interior mutability. This is a single-threaded example; concurrency remains a separate design problem.

The buffer stores at most four messages, each one through 64 UTF-8 bytes with no control characters. Every call validates its message, even when recording is disabled. A valid disabled call returns Ok(false); an accepted record returns Ok(true). Invalid input, a full buffer, and a conflicting runtime borrow are distinct errors. These rules keep the example small while making the hard questions observable.

Plain model: ownership and permission to mutate are different

Rc supplies shared ownership within one thread. Cloning its handle adds another owner of the same allocation; it does not clone the inner vector of messages. The inner allocation remains alive while any strong owner remains. Shared ownership alone does not permit arbitrary mutation through a shared reference. That distinction matters: an ownership wrapper answers “who keeps this alive?” while a mutation mechanism answers “when may the contents change?”

Cell<bool> stores the enabled flag. Reading with get copies a small Boolean out; setting replaces that value. The API does not lend an ordinary reference to the inner Boolean that could be invalidated by a later replacement. This fits a small Copy value. RefCell<Vec<String>> instead provides checked temporary access to a larger non-Copy value. It tracks shared and exclusive borrows at runtime while preserving the essential rule that mutable access cannot coexist with another active access to the same contents.

This is called interior mutability: an API can mutate controlled contents through &self. It is not a compiler escape hatch. Safe standard-library APIs enforce the relevant rules, and the compiler still constrains how returned guards and references are used. RefCell does not become a thread-safe lock, and wrapping it in an atomic reference counter would not automatically fix that limitation. The lesson's compile-fail doctest makes the single-threaded boundary explicit.

projects/reference/p18-core-labs/src/interior.rs
use std::cell::{Cell, RefCell};
use std::fmt;
use std::rc::{Rc, Weak};

pub const MAX_MESSAGES: usize = 4;
pub const MAX_MESSAGE_BYTES: usize = 64;

#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub enum AuditError {
    InvalidMessage,
    Full,
    Borrowed,
}
impl fmt::Display for AuditError {
    fn fmt(&self, f: &mut fmt::Formatter<'_>) -> fmt::Result {
        f.write_str(match self {
            Self::InvalidMessage => "message must contain 1 to 64 bytes and no control characters",
            Self::Full => "audit buffer is full",
            Self::Borrowed => "audit buffer is already borrowed by an observer",
        })
    }
}
impl std::error::Error for AuditError {}

#[derive(Debug)]
struct Inner {
    enabled: Cell<bool>,
    messages: RefCell<Vec<String>>,
}

/// Two synchronous callbacks can retain handles to one bounded audit buffer.
/// This deliberately single-threaded handle is not a cross-thread synchronization primitive.
///
/// ```compile_fail
/// let audit = core_rust_labs::interior::SharedAudit::default();
/// std::thread::spawn(move || audit.record("moved to another thread"));
/// ```
#[derive(Debug, Clone)]
pub struct SharedAudit {
    inner: Rc<Inner>,
}

/// A non-owning observer: retaining this handle does not retain the messages.
#[derive(Debug, Clone)]
pub struct WeakAudit {
    inner: Weak<Inner>,
}
impl WeakAudit {
    /// A successful upgrade owns the buffer until the returned handle is dropped.
    pub fn upgrade(&self) -> Option<SharedAudit> {
        self.inner.upgrade().map(|inner| SharedAudit { inner })
    }
}
impl Default for SharedAudit {
    fn default() -> Self {
        Self {
            inner: Rc::new(Inner {
                enabled: Cell::new(true),
                messages: RefCell::new(Vec::new()),
            }),
        }
    }
}
impl SharedAudit {
    pub fn downgrade(&self) -> WeakAudit {
        WeakAudit {
            inner: Rc::downgrade(&self.inner),
        }
    }

    pub fn set_enabled(&self, enabled: bool) {
        self.inner.enabled.set(enabled);
    }

    /// Validate all calls, including disabled ones. Ok(false) means valid but disabled.
    /// Rejections do not add a message. No user callback runs while mutably borrowed.
    pub fn record(&self, message: &str) -> Result<bool, AuditError> {
        if message.is_empty()
            || message.len() > MAX_MESSAGE_BYTES
            || message.chars().any(char::is_control)
        {
            return Err(AuditError::InvalidMessage);
        }
        if !self.inner.enabled.get() {
            return Ok(false);
        }
        let mut messages = self
            .inner
            .messages
            .try_borrow_mut()
            .map_err(|_| AuditError::Borrowed)?;
        if messages.len() == MAX_MESSAGES {
            return Err(AuditError::Full);
        }
        messages.push(message.to_owned());
        Ok(true)
    }

    /// The observation callback runs under a shared borrow. Reentrant writes return Borrowed.
    /// Keep callbacks brief; this is synchronous observation, not an async lock.
    pub fn with_messages<R>(&self, inspect: impl FnOnce(&[String]) -> R) -> Result<R, AuditError> {
        let messages = self
            .inner
            .messages
            .try_borrow()
            .map_err(|_| AuditError::Borrowed)?;
        Ok(inspect(&messages))
    }

    /// An owned snapshot is bounded by MAX_MESSAGES and MAX_MESSAGE_BYTES.
    pub fn snapshot(&self) -> Result<Vec<String>, AuditError> {
        self.with_messages(|messages| messages.to_vec())
    }
}

#[cfg(test)]
mod tests {
    use super::*;

    #[test]
    fn handles_share_state_and_disabled_is_distinct_from_invalid() {
        let audit = SharedAudit::default();
        let other = audit.clone();
        assert_eq!(audit.record("opened"), Ok(true));
        other.set_enabled(false);
        assert_eq!(audit.record("paused"), Ok(false));
        assert_eq!(audit.record(""), Err(AuditError::InvalidMessage));
        other.set_enabled(true);
        drop(audit);
        assert_eq!(other.record("resumed"), Ok(true));
        assert_eq!(other.snapshot().unwrap(), ["opened", "resumed"]);
    }

    #[test]
    fn full_or_invalid_input_preserves_messages() {
        let audit = SharedAudit::default();
        for _ in 0..MAX_MESSAGES {
            audit.record("entry").unwrap();
        }
        let before = audit.snapshot().unwrap();
        assert_eq!(audit.record("extra"), Err(AuditError::Full));
        for bad in [
            String::new(),
            "x".repeat(MAX_MESSAGE_BYTES + 1),
            "bad\nline".into(),
        ] {
            assert_eq!(audit.record(&bad), Err(AuditError::InvalidMessage));
        }
        assert_eq!(audit.snapshot().unwrap(), before);
    }

    #[test]
    fn reentrant_write_is_an_error_then_guard_release_allows_progress() {
        let audit = SharedAudit::default();
        audit.record("before").unwrap();
        let observed = audit.with_messages(|messages| {
            assert_eq!(audit.record("during"), Err(AuditError::Borrowed));
            messages.len()
        });
        assert_eq!(observed, Ok(1));
        assert_eq!(audit.record("after"), Ok(true));
        assert_eq!(audit.snapshot().unwrap(), ["before", "after"]);
    }

    #[test]
    fn unwinding_releases_the_observer_guard() {
        let audit = SharedAudit::default();
        let failure = std::panic::catch_unwind(std::panic::AssertUnwindSafe(|| {
            let _ = audit.with_messages(|_| panic!("deliberate observer failure"));
        }));
        assert!(failure.is_err());
        assert_eq!(audit.record("after unwind"), Ok(true));
    }

    #[test]
    fn weak_observer_does_not_keep_the_buffer_alive() {
        let first = SharedAudit::default();
        first.record("retained by strong handles").unwrap();
        let second = first.clone();
        let observer = first.downgrade();
        drop(first);
        assert_eq!(observer.upgrade().unwrap().snapshot().unwrap().len(), 1);
        drop(second);
        assert!(observer.upgrade().is_none());
    }
}
projects/reference/p18-core-labs/examples/interior.rs
use core_rust_labs::interior::{AuditError, SharedAudit};

fn main() -> Result<(), AuditError> {
    let first_callback = SharedAudit::default();
    let second_callback = first_callback.clone();
    let observer = first_callback.downgrade();
    first_callback.record("first callback")?;
    second_callback.record("second callback")?;
    first_callback.with_messages(|messages| {
        println!("observed messages: {}", messages.len());
        println!(
            "reentrant write: {:?}",
            second_callback.record("while observing")
        );
    })?;
    first_callback.set_enabled(false);
    println!(
        "recorded while disabled: {}",
        second_callback.record("ignored")?
    );
    println!("snapshot: {:?}", first_callback.snapshot()?);
    drop(first_callback);
    drop(second_callback);
    println!(
        "observer can still upgrade: {}",
        observer.upgrade().is_some()
    );
    Ok(())
}

SharedAudit exposes methods while its Inner fields remain private. Default constructs a fresh enabled buffer. Deriving Clone for the outer handle clones the Rc, deliberately sharing the same Inner. The name “shared” therefore describes an actual observable relationship, verified by a test that disables recording through one handle and records through another. Dropping one handle does not invalidate the other owner.

record validates text before any buffer mutation. It then reads the Cell flag. If disabled, it returns without requesting a mutable vector borrow. Otherwise try_borrow_mut obtains a guard or reports a conflict. Mapping that conflict into AuditError::Borrowed makes it part of the method's normal Result contract. Only after checking capacity does the function allocate its owned message and push it. A rejected operation leaves the existing message list intact.

The local messages guard dereferences to the vector for its operations. Its Drop releases the runtime borrow when the scope ends, including an ordinary early return. This connects directly to the RAII lesson: a guard's lifetime is the permission interval. Keeping the guard alive longer than necessary can prevent useful work even though every operation remains memory-safe. Do not infer the interval only from where the programmer last thinks about the variable; inspect its actual scope and uses.

Observation, snapshots, and callback contracts

with_messages accepts impl FnOnce(&[String]) -> R. The caller supplies one computation over a borrowed view, and the method returns that computation's result. FnOnce is sufficient because the callback is invoked once. The shared borrow guard stays alive while it runs. Calling record inside that callback therefore cannot obtain the exclusive borrow, and our fallible API reports the conflict. The observer should be short and synchronous; this is not an async synchronization primitive.

snapshot uses the same observation boundary to clone the bounded messages into an owned vector. A snapshot costs allocations, but the caller can then process it after the shared borrow ends. That is a reasonable alternative when downstream work may call back into the logger. Avoid declaring either approach universally superior. Borrowed observation avoids the copy but constrains reentrancy; owned observation buys independent lifetime with an explicit bounded cost.

A callback panic is not one of record's ordinary error outcomes. The dedicated test deliberately panics inside observation, catches that unwind in the test harness, and then records successfully. This checks guard cleanup during unwinding. It does not promise rollback of every effect a callback performed before panicking, and a build configured to abort on panic would not continue. Production logic should not use caught panic as its routine borrowing-control protocol.

Weak observers and ownership cycles

Sometimes a callback registration should find a buffer only while another part of the program owns it. Retaining a strong SharedAudit would extend the buffer lifetime. WeakAudit instead holds Weak<Inner>: a non-owning link created with Rc::downgrade. Its upgrade method returns Option<SharedAudit>. Some gives the caller a new strong owner; None means all strong owners have already gone away. The weak allocation bookkeeping can remain until weak handles disappear, but the messages themselves are dropped when the final strong owner disappears. A weak handle is therefore not a borrowed reference that you can dereference indefinitely.

Predict the final line of the example before running it. Both callback handles are explicitly dropped, so the observer prints false. In the lifetime test, dropping the first owner still permits an upgrade because the second owner exists. The temporary upgraded handle is dropped at the end of its assertion statement. Only then do we drop the second owner and require None. If you save that upgraded handle in a local variable, you have introduced another strong owner; an unexpected successful later upgrade would be explained by that ownership fact. Record a diagram of live handles before concluding that Weak leaked the buffer.

A reference-count cycle arises when object A strongly owns B and B strongly owns A. Removing outside handles leaves each count nonzero; reference counting alone cannot infer that the cycle is unreachable. Our buffer contains strings, not stored callbacks or parent links, so this implementation has no such cycle. If a future observer registry stores callbacks that capture the buffer strongly, that new graph requires review. Prefer a clear owner and a weak back-reference when the observer must not extend the owner lifetime; require the callback to handle a failed upgrade. Weak is not a universal repair: an edge that represents real required ownership must remain strong. Draw the graph and state who is responsible for keeping each object alive.

Intentional mistake: replacing an ordinary error with a panic

In a disposable learner edit, replace try_borrow_mut and its error mapping with borrow_mut. Predict the reentrant-write test. The infallible-looking API panics on the conflicting borrow, so a caller expecting Err(Borrowed) no longer receives the promised outcome. Run that one test and restore the original fallible call. The lesson is not that borrow_mut is always forbidden; it is inappropriate where a reachable caller behavior is documented as an ordinary error.

A different deliberate mistake is holding a mutable guard and then invoking arbitrary user callbacks before releasing it. That enlarges the reentrancy surface and makes the permission interval harder to reason about. Our record method calls no user callback while mutably borrowed. Review this structural choice before proposing broad panic handling or a larger wrapper hierarchy.

Playbook investigation: “two owners copied my messages”

You see identical messages through two handles and suspect that Clone copied the vector. Competing hypotheses are independent copied storage and shared storage behind two ownership handles. Disable recording through the first handle, attempt a valid record through the second, then re-enable through the second. If the setting affects both handles and a later record is visible from both, the independent-copy explanation is disproved. A test that only compares their initial contents could not distinguish those designs.

Next investigate a Borrowed error. A plausible but incorrect diagnosis is that another operating-system thread still holds a lock. Reproduce it with one thread and a nested observation callback. The same error without spawning any thread disproves that diagnosis. The fix can shorten the observation scope or use a bounded snapshot before reentrant work. Record the chosen change and the cost it introduces, using the central playbook. Do not replace Rc with Arc without a genuine cross-thread ownership requirement.

Independent practice and tiered hints

Add a fallible drain operation that transfers all retained messages to an owned vector and leaves the live buffer empty. Decide whether draining while disabled is allowed; the flag currently controls recording, not observation. Require Borrowed when a shared observer is active, and require the old messages to remain intact after that rejection. Test an empty buffer, a full buffer, a blocked drain, a successful drain, and recording again afterward. This is an extension beyond the supplied baseline.

Hint 1: identify the permission needed

Moving messages out changes the vector, so a shared borrow is insufficient. Obtain a fallible mutable guard before changing the state. Disabled recording need not prevent an explicitly separate maintenance operation.

Hint 2: preserve ownership without cloning

Once exclusive access exists, consider std::mem::take on the vector. It replaces the stored vector with its default empty value and returns the previously owned one. No message-by-message clone is required.

Reference approach after your attempt

The operation can map try_borrow_mut failure to Borrowed, take the vector, and return it. Document the enabled-flag policy before testing. A rejected borrow does not execute the take, so the original buffer survives. Returning an owned vector also prevents callers from retaining a reference into a buffer that will later be reused. This direction still requires your own implementation and tests.

Engineering decisions, evidence, and mastery

One small Cell fits an independent Copy flag; one RefCell protects the vector; Rc satisfies the two-callback lifetime requirement; private fields keep validation and bounds centralized. Plain exclusive ownership is the preferable alternative when independently retained handles are unnecessary. A cross-thread requirement would call for a new ownership and synchronization design, with Send/Sync, contention, cancellation, and shutdown review. Merely exchanging wrapper names is not an architecture.

Four native tests exercise shared identity, bounds and rejection preservation, reentrancy, and guard cleanup on unwind. A compile-fail doctest rejects transferring this Rc-backed handle into a spawned thread. See the actual test evidence. Tests cover chosen traces; they do not prove every callback is well-behaved. Author verification and independent review are separate, and no browser behavior is claimed.

For mastery, explain which wrapper supplies ownership, which supplies access checking, and why a dynamic borrow conflict can happen in one thread. Implement drain under your stated flag policy, demonstrate rejected-state preservation, and compare an observation callback with an owned snapshot. Your review should defend the shared requirement itself, not only the syntax that made the compiler accept it.

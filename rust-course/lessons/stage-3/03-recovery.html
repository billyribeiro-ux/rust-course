Recovery and compaction without wishful guarantees

Specify restart policy, test torn tails, and reason through compaction failure windows.

Read with a terminal open. Predict before revealing. Verified source versions: version ledger.

Prerequisites and learning objectives
  • Design an append-only record protocol
  • Distinguish a valid prefix from arbitrary damaged data
  • Explain truncate-before-append recovery
  • Trace write/sync/rename/directory-sync ordering
  • State filesystem and power-loss limits precisely

Purpose: make restarting part of normal behavior

Durability is not a property you earn by adding one sync call. It is a protocol whose states include interruption. This lesson treats restart as a normal entry point and asks what the program can infer from each file shape. Recovery accepts a sequence of complete validated records and may discard an incomplete final record. A full header with bad magic or out-of-range lengths produces an error; a checksum mismatch produces an error only after the declared payload is fully available. This is a conservative policy: it avoids silently treating identifiable corruption as a successful recovery. Its recovery guarantee assumes an interrupted append following unchanged valid prior records. It cannot distinguish every form of damage from interruption.

Model: a validated prefix plus an uncertain suffix

During replay, valid_bytes advances only after a complete record has passed validation and affected the map. If the final header or payload ends early, replay returns that earlier boundary with torn_tail=true. Store::open truncates the file to that boundary and synchronizes it before allowing another append. Without truncation, a new valid record would follow the old incomplete bytes. A later replay could interpret those bytes together as one malformed record and lose access to the later append. Recovery is therefore not merely ignoring data in memory; it repairs the on-disk suffix before normal operation resumes.

Predict two interruption outcomes

Suppose the first record is intact and the next record is missing three payload bytes. Predict the recovered key set and resulting file length after open. Now suppose the second record is complete but one payload bit changed. The first case repairs an incomplete suffix; the second refuses to open. Explain why treating both as “last record bad, ignore it” would hide damage. Then predict whether deleting an old key reduces the log size. It does not: deletion adds a tombstone. Reclaiming historical records requires a separate compaction protocol.

//! Single-writer educational log store. CRC checks complete declared records, not tampering.
//! An incomplete declared suffix is discarded; bounded length damage can look incomplete.
//! Successful writes call sync_all; hardware/filesystem power-loss guarantees vary.
use std::{
    collections::BTreeMap,
    fs::{self, File, OpenOptions},
    io::{self, Read, Write},
    path::{Path, PathBuf},
};

const MAGIC: &[u8; 4] = b"KV01";
const HEADER: usize = 16;
pub const MAX_KEY: usize = 4096;
pub const MAX_VALUE: usize = 1_048_576;

fn invalid(message: &str) -> io::Error {
    io::Error::new(io::ErrorKind::InvalidData, message)
}

/// IEEE CRC-32, reflected polynomial; deliberately transparent rather than optimized.
pub fn crc32(bytes: &[u8]) -> u32 {
    let mut crc = !0u32;
    for &byte in bytes {
        crc ^= u32::from(byte);
        for _ in 0..8 {
            crc = (crc >> 1) ^ (0xedb8_8320 & (0u32.wrapping_sub(crc & 1)));
        }
    }
    !crc
}

fn encode(key: &[u8], value: Option<&[u8]>) -> io::Result<Vec<u8>> {
    if key.is_empty() || key.len() > MAX_KEY || value.is_some_and(|v| v.len() > MAX_VALUE) {
        return Err(io::Error::new(
            io::ErrorKind::InvalidInput,
            "key/value length outside bounds",
        ));
    }
    let mut record = Vec::with_capacity(HEADER + key.len() + value.map_or(0, <[u8]>::len));
    record.extend_from_slice(MAGIC);
    record.extend_from_slice(&(key.len() as u32).to_le_bytes());
    record.extend_from_slice(&value.map_or(u32::MAX, |v| v.len() as u32).to_le_bytes());
    record.extend_from_slice(&0u32.to_le_bytes());
    record.extend_from_slice(key);
    if let Some(value) = value {
        record.extend_from_slice(value);
    }
    let checksum = crc32(&[&record[..12], &record[16..]].concat());
    record[12..16].copy_from_slice(&checksum.to_le_bytes());
    Ok(record)
}

#[derive(Debug, Default, PartialEq, Eq)]
pub struct Recovery {
    pub entries: BTreeMap<Vec<u8>, Vec<u8>>,
    pub valid_bytes: u64,
    pub records: usize,
    pub torn_tail: bool,
}

/// Replay bounded individual records. The live key map itself grows with the data set.
/// An incomplete declared header/payload returns the validated prefix. Detected magic,
/// length-bound and checksum violations are errors. CRC is checked only after reading
/// the declared payload: a damaged but bounded length can resemble an interrupted append.
pub fn replay(mut input: impl Read) -> io::Result<Recovery> {
    let mut result = Recovery::default();
    loop {
        let mut header = [0u8; HEADER];
        let n = read_prefix(&mut input, &mut header)?;
        if n == 0 {
            return Ok(result);
        }
        if n != HEADER {
            result.torn_tail = true;
            return Ok(result);
        }
        if &header[..4] != MAGIC {
            return Err(invalid("bad record magic"));
        }
        let key_len = u32::from_le_bytes(header[4..8].try_into().unwrap()) as usize;
        let raw_value_len = u32::from_le_bytes(header[8..12].try_into().unwrap());
        let deleted = raw_value_len == u32::MAX;
        let value_len = if deleted { 0 } else { raw_value_len as usize };
        if key_len == 0 || key_len > MAX_KEY || value_len > MAX_VALUE {
            return Err(invalid("invalid record length"));
        }
        let mut payload = vec![0; key_len + value_len];
        if read_prefix(&mut input, &mut payload)? != payload.len() {
            result.torn_tail = true;
            return Ok(result);
        }
        let expected = u32::from_le_bytes(header[12..16].try_into().unwrap());
        if crc32(&[&header[..12], &payload].concat()) != expected {
            return Err(invalid("record checksum mismatch"));
        }
        let key = payload[..key_len].to_vec();
        if deleted {
            result.entries.remove(&key);
        } else {
            result.entries.insert(key, payload[key_len..].to_vec());
        }
        result.valid_bytes += (HEADER + payload.len()) as u64;
        result.records += 1;
    }
}

fn read_prefix(input: &mut impl Read, buf: &mut [u8]) -> io::Result<usize> {
    let mut used = 0;
    while used < buf.len() {
        match input.read(&mut buf[used..]) {
            Ok(0) => break,
            Ok(n) => used += n,
            Err(error) if error.kind() == io::ErrorKind::Interrupted => continue,
            Err(error) => return Err(error),
        }
    }
    Ok(used)
}

fn sibling(path: &Path, suffix: &str) -> PathBuf {
    let mut name = path.as_os_str().to_os_string();
    name.push(suffix);
    PathBuf::from(name)
}

fn sync_parent(path: &Path) -> io::Result<()> {
    #[cfg(unix)]
    {
        let parent = path
            .parent()
            .filter(|p| !p.as_os_str().is_empty())
            .unwrap_or(Path::new("."));
        File::open(parent)?.sync_all()
    }
    #[cfg(not(unix))]
    {
        let _ = path;
        Ok(())
    }
}

pub struct Store {
    path: PathBuf,
    file: File,
    _lock: File, // Separate inode: compaction replaces the data file, never this lock.
    entries: BTreeMap<Vec<u8>, Vec<u8>>,
    poisoned: bool,
    pub recovered_torn_tail: bool,
}

impl Store {
    pub fn open(path: impl AsRef<Path>) -> io::Result<Self> {
        // Freeze the opening cwd before retaining paths used by later compaction.
        // This does not resolve symlinks or protect against external path replacement.
        let path = std::path::absolute(path)?;
        let lock = OpenOptions::new()
            .read(true)
            .write(true)
            .create(true)
            .truncate(false)
            .open(sibling(&path, ".lock"))?;
        lock.try_lock().map_err(io::Error::other)?;
        let file = OpenOptions::new()
            .read(true)
            .append(true)
            .create(true)
            .open(&path)?;
        let recovery = replay(&file)?;
        if recovery.torn_tail {
            file.set_len(recovery.valid_bytes)?;
        }
        file.sync_all()?;
        sync_parent(&path)?;
        Ok(Self {
            path,
            file,
            _lock: lock,
            entries: recovery.entries,
            poisoned: false,
            recovered_torn_tail: recovery.torn_tail,
        })
    }
    pub fn get(&self, key: &[u8]) -> Option<&[u8]> {
        self.entries.get(key).map(Vec::as_slice)
    }
    pub fn len(&self) -> usize {
        self.entries.len()
    }
    pub fn is_empty(&self) -> bool {
        self.entries.is_empty()
    }
    pub fn put(&mut self, key: &[u8], value: &[u8]) -> io::Result<()> {
        self.change(key, Some(value))
    }
    pub fn delete(&mut self, key: &[u8]) -> io::Result<()> {
        self.change(key, None)
    }
    fn ready(&self) -> io::Result<()> {
        if self.poisoned {
            Err(io::Error::other(
                "store write failed; drop and reopen before further mutations",
            ))
        } else {
            Ok(())
        }
    }
    fn change(&mut self, key: &[u8], value: Option<&[u8]>) -> io::Result<()> {
        self.ready()?;
        let record = encode(key, value)?;
        if let Err(error) = self
            .file
            .write_all(&record)
            .and_then(|()| self.file.sync_all())
        {
            self.poisoned = true;
            return Err(error);
        }
        if let Some(value) = value {
            self.entries.insert(key.to_vec(), value.to_vec());
        } else {
            self.entries.remove(key);
        }
        Ok(())
    }
    /// Unix rename + parent sync protocol. Windows replacement semantics are not modeled.
    #[cfg(unix)]
    pub fn compact(&mut self) -> io::Result<()> {
        self.ready()?;
        let temporary = sibling(&self.path, ".compact");
        let mut next = OpenOptions::new()
            .read(true)
            .append(true)
            .create_new(true)
            .open(&temporary)?;
        for (key, value) in &self.entries {
            next.write_all(&encode(key, Some(value))?)?;
        }
        next.sync_all()?;
        fs::rename(&temporary, &self.path)?;
        self.file = next;
        if let Err(error) = sync_parent(&self.path) {
            self.poisoned = true;
            return Err(error);
        }
        Ok(())
    }
}

compact creates a sibling temporary file with create_new, writes one current put per live key, synchronizes the new file, renames it over the old data path, swaps the Store's open file handle, and synchronizes the containing directory. Keeping the temporary file in the same directory avoids an intended cross-filesystem move. The original lock uses a different inode, so it remains held across replacement. The new handle must replace the old handle: otherwise subsequent appends could go to the unlinked old file while new opens read the compacted file.

Failure windows deserve a table

Before rename, the original data path remains the authoritative log. A write or sync failure while constructing the temporary file may leave that temporary file behind. create_new deliberately refuses to overwrite an existing .compact file on the next attempt. Inspect and remove a stale temporary file only while no writer owns the store, after deciding which data path is authoritative. After rename, the current process points at the new file. If directory synchronization fails, namespace persistence across a crash is uncertain and the Store becomes poisoned. Reopening and inspecting is necessary; pretending that the failed call rolled the rename back would be wrong.

File synchronization asks the operating system to synchronize file data and relevant metadata. Synchronizing a directory after rename is the Unix protocol used here to address the directory-entry change. The exact persistence outcome still depends on filesystem, operating system, mount options and hardware behavior. Unit tests that truncate a file or flip bytes model parser inputs; they do not emulate every ordering of device writes. State those limits in the project's evidence record. Use “tested recovery from these constructed tails” rather than “crash-proof.”

Playbook investigation: new writes vanish after compaction

Observation: get succeeds in the existing process after compaction and a put, but reopening does not show that put. Hypothesis A says replay mishandles the new record. Hypothesis B says writes still target the old open file handle. Hypothesis C says compaction omitted an older key. Keep the test data small: put a, compact, put b, drop, reopen, inspect both. Then compare the path's file length before and after the second put. A map change without growth at the visible path supports B. Replay an explicitly concatenated compacted record plus b in memory; success disproves the broad parser hypothesis.

The corresponding fix is to replace the Store's file handle after rename while retaining the independent lock. Evidence includes reopening after an additional append, the resulting map, and a contention check after compaction. It does not prove every crash window is safe. For an advanced extension, introduce explicit failure points into a filesystem adapter and test the selected authoritative file after each one. Keep injection semantics honest: an injected error before rename is not evidence about an actual power loss during rename.

Engineering decisions and evidence

Current scope and invariants. One cooperating writer owns the separate lock; only a validated record changes the map or recovery boundary. A failed write leaves the last acknowledged map readable and blocks further mutations until reopen.

Why this is the current recommended shape. A small binary protocol and BTreeMap keep framing and replay visible. Bounds precede allocation, typed io::Result values preserve failures, and owned File handles tie cleanup to scope. write_all and sync_all precede acknowledgment; compaction uses a separate lock inode and replaces the active data handle.

Reasonable alternative and tradeoff. An embedded database would provide a broader tested storage contract and should be preferred when a real application needs transactions, indexing, migrations or concurrent readers. This implementation is appropriate for learning one explicit single-writer log protocol; adding a framework would conceal the decisions being studied.

Evidence and limits. Native reference tests were run through mise in the coordinated course verification; inspect the current verification record for exact results. CRC known vector; every truncated suffix of the tested record; checksum mismatch after a complete declared payload; invalid length; read failure; tombstones and empty values; tail repair; lock retention across compaction. Additional self-review regressions cover write-error poisoning and stale temporary files. The live map grows with the data set. CRC is not authentication. A bounded damaged length can resemble a torn tail and cause truncation of an originally complete record; the interrupted-append policy assumes earlier valid bytes were not damaged. Sync/rename tests do not reproduce every power-loss ordering. Unix compaction and cooperating advisory locks are explicit scope limits.

Requirement that would justify evolution. Adopt or evaluate an established storage engine when the requirements include multi-key atomicity, large state, coordinated concurrent readers or portable power-loss guarantees. Do not grow the current log by silently adding assumptions.

In your review, explain this choice in your own words, preserve the behavioral contract during changes, and name the evidence that would make you choose the alternative. Deliberately broken variants above are diagnostic exercises, never recommended implementation stages.

Keep path identity stable across the operation

Store::open now uses std::path::absolute before opening either the lock or data file. It records the opening current directory in an absolute path, returning an io::Error if resolving a relative path fails. Later compaction therefore uses the same pathname even if the process changes directories. This is not canonicalization: symlinks are not resolved, and an external rename, symlink retargeting, or another pathname alias can still defeat assumptions. Cooperating writers must use the same stable data and lock paths.

Our isolated child-process regression opens data in one directory, writes a, changes its directory, compacts, writes b, and reopens the original data path. Before this fix b disappeared from that reopened path because compaction created a second file in the new directory. The test now requires both keys to survive and no second data file to appear. Only the child changes its process-wide current directory; the parallel test runner remains untouched. Hypothesis A, a decoder error, is disproved by reading the two physical files. Hypothesis B, pathname interpretation changing over time, predicts exactly that split.

The existing stale-temporary regression also checks that a refused .compact file retains its original bytes. The store uses create_new and never deletes an unknown temporary file for the caller. These tests establish pathname and file-ownership behavior under the modeled operations; they do not simulate external directory interference or power loss.

Recovery cannot infer the cause of every short payload

Run the bounded_length_damage test from the prior lesson and compare its bytes with a truly interrupted append. KV01 has no independent header checksum, so a legal length changed from 3 to 4 can make a previously complete record look incomplete and eligible for truncation. Do not summarize this policy as rejecting all complete corruption. When the cause is uncertain, preserve the original file, inspect a copy, and document which records would be discarded before authorizing a real recovery.

Investigate the command boundary before opening storage

A rejected command must not create a database or repair its existing tail. Opening this particular store is a state-changing operation: Store::open can truncate an incomplete suffix. The CLI therefore first checks the complete command, its exact argument count, UTF-8 text fields, and byte-length limits. Only then does it open the native PathBuf. The small Command enum carries borrowed validated bytes; it adds no shared ownership or copies of key/value data.

use p06_kv::{MAX_KEY, MAX_VALUE, Store};
use std::{
    ffi::OsStr,
    io::{self, Write},
    path::PathBuf,
    process::ExitCode,
};

enum Command<'a> {
    Put(&'a [u8], &'a [u8]),
    Get(&'a [u8]),
    Delete(&'a [u8]),
    #[cfg(unix)]
    Compact,
}

fn invalid(message: &str) -> io::Error {
    io::Error::new(io::ErrorKind::InvalidInput, message)
}

fn key(input: &OsStr) -> io::Result<&[u8]> {
    let text = input
        .to_str()
        .ok_or_else(|| invalid("key must be valid UTF-8"))?;
    if text.is_empty() || text.len() > MAX_KEY {
        return Err(invalid("key must contain 1..=4096 UTF-8 bytes"));
    }
    Ok(text.as_bytes())
}

fn run() -> io::Result<()> {
    let args: Vec<_> = std::env::args_os().skip(1).collect();
    let [path, command, rest @ ..] = args.as_slice() else {
        return Err(invalid(
            "usage: p06-kv PATH put KEY VALUE | get KEY | delete KEY | compact (Unix)",
        ));
    };
    if path.is_empty() {
        return Err(invalid("path must not be empty"));
    }
    let path = PathBuf::from(path);
    let command = command
        .to_str()
        .ok_or_else(|| invalid("command must be valid UTF-8"))?;
    // Validate the whole request before open: open may create a file or repair a tail.
    let command = match (command, rest) {
        ("put", [k, value]) => {
            let k = key(k)?;
            let value = value
                .to_str()
                .ok_or_else(|| invalid("value must be valid UTF-8"))?;
            if value.len() > MAX_VALUE {
                return Err(invalid("value exceeds 1048576 UTF-8 bytes"));
            }
            Command::Put(k, value.as_bytes())
        }
        ("get", [k]) => Command::Get(key(k)?),
        ("delete", [k]) => Command::Delete(key(k)?),
        #[cfg(unix)]
        ("compact", []) => Command::Compact,
        _ => return Err(invalid("invalid command or argument count")),
    };
    let mut store = Store::open(path)?;
    if store.recovered_torn_tail {
        // Recovery already happened. A diagnostic failure cannot undo it.
        let _ = writeln!(io::stderr().lock(), "recovered an incomplete final record");
    }
    match command {
        Command::Put(key, value) => store.put(key, value)?,
        Command::Get(key) => {
            let mut output = io::stdout().lock();
            match store.get(key) {
                Some(value) => writeln!(output, "{}", String::from_utf8_lossy(value))?,
                None => writeln!(output, "(missing)")?,
            }
            output.flush()?;
        }
        Command::Delete(key) => store.delete(key)?,
        #[cfg(unix)]
        Command::Compact => store.compact()?,
    }
    Ok(())
}

fn main() -> ExitCode {
    match run() {
        Ok(()) => ExitCode::SUCCESS,
        Err(error) => {
            let _ = writeln!(io::stderr().lock(), "kv: {error}");
            if error.kind() == io::ErrorKind::InvalidInput {
                ExitCode::from(2)
            } else {
                ExitCode::FAILURE
            }
        }
    }
}

Prediction: run an unknown command against a disposable file containing only KV. Should its two bytes remain? The regression initially observed unwanted file creation before validation; the corrected process-level test checks both a missing path and an existing torn file, including absence of a new lock file. This disproves the tempting hypothesis that a nonzero exit status alone establishes that nothing changed. Inspect tests/cli.rs, then execute mise exec -- cargo test --manifest-path projects/Cargo.toml -p p06-kv --test cli from the course root.

Paths are operating-system values, while this CLI's keys and values are UTF-8 text. args_os preserves that distinction and to_str reports a text conversion failure. A native filename need not have a valid string representation; the host filesystem can also reject a name. On the author machine, a non-UTF-8 directory name produced a normal filesystem error rather than a panic; valid Unicode directory and file operations round-tripped. Library callers may store binary values, so CLI output uses lossy display only after reading, never to select or rewrite a path. A successful get can still repair a torn store because that is the declared open policy. It is not a forensic read-only inspector.

When stuck, first separate argument rejection from failure inside Store::open; preserve original bytes before investigating recovery. Add one rejected input to the regression and explain why it must be checked before opening. See the executed CLI boundary evidence and Rust 1.99 argument contract.

Output is an I/O boundary too. The CLI writes through a locked io::Write handle and propagates ordinary stdout failures, including a pipe whose consumer has closed. Final stderr diagnostics are best effort: a second write failure must not replace the original failure with a panic. The process tests create an anonymous pipe and close its reading end before launching the child, so this experiment does not depend on a race with a shell command.

A recovery warning is also best effort: the store may already have repaired its tail, and a broken stderr cannot undo that authorized operation. The test verifies this policy separately from rejecting an invalid command before opening.

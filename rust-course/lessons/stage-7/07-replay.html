Deterministic replay with exact domain values

Model events, fixed-point prices and bounded state so the same accepted stream reproduces the same result.

Read with a terminal open. Predict before revealing. Verified source versions: version ledger.

Prerequisites and learning objectives
  • Measure a claim before optimizing
  • Use distinct IDs and exact fixed-point prices
  • Validate before mutation so rejections are transactional
  • Bound active state while streaming an unbounded-looking workload
  • Distinguish deterministic state from weak digest evidence

Key terms: atomic · cancellation · capacity · compaction · deduplication · future · idempotency · lifetime

Keep the problem-solving playbook open. Record observations before explanations, and save the experiment that changed your mind.

Purpose: separate a domain state machine from its transport

P12 replays synthetic placement and cancellation events into a bounded map of resting orders. It is not an exchange simulator, matching engine, trading strategy or model of profitability. That narrow purpose lets us focus on exact representation, sequencing and failure semantics. The core API receives an Event and either accepts a transition or rejects it without changing state. A CLI generates a deterministic stream and prints the resulting summary. A separate benchmark measures that same core. Keeping generation, state transitions and measurement distinct makes it possible to test each claim without depending on a network feed.

Model: make invalid meanings harder to mix

OrderId and EventId are separate newtypes even though both wrap u64. An order identifier locates a live order; an event sequence identifies the required next transition. Mixing them is a semantic bug that primitive integers alone would not reveal. Price stores integer ticks at a scale of ten thousand, so 12.34 becomes exactly 123400 ticks. Decimal parsing checks grammar, precision and bounds using integer arithmetic. It rejects signs, exponents, non-digits, zero and excessive precision. Display reconstructs a four-place decimal string. This is a chosen domain scale, not a universal representation for every financial instrument.

Predict state and rejection behavior

Start with sequence one and place order seven. Submit sequence two with order seven again. Predict both the error and every state field afterward. The duplicate is rejected and the expected sequence remains two, allowing a corrected event with sequence two to be retried. Now cancel an absent order or exceed capacity. Those failures also leave state unchanged. Order IDs may be reused after their earlier order has been removed; the reference checks active duplicates rather than preserving a lifetime history of every ID. State this policy explicitly before extending the system.

//! Deterministic synthetic resting-order replay; no trading or execution model.
use std::{collections::BTreeMap, fmt};

pub mod ticks;

#[derive(Clone, Copy, Debug, PartialEq, Eq, PartialOrd, Ord)]
pub struct OrderId(pub u64);
#[derive(Clone, Copy, Debug, PartialEq, Eq)]
pub struct EventId(pub u64);
#[derive(Clone, Copy, Debug, PartialEq, Eq)]
pub struct Price(u64);
impl Price {
    pub const SCALE: u64 = 10_000;
    pub fn from_ticks(ticks: u64) -> Result<Self, Error> {
        if ticks == 0 || ticks > 1_000_000_000_000 {
            Err(Error::InvalidPrice)
        } else {
            Ok(Self(ticks))
        }
    }
    pub fn ticks(self) -> u64 {
        self.0
    }
    pub fn parse(input: &str) -> Result<Self, Error> {
        let (whole, fractional) = input.split_once('.').unwrap_or((input, ""));
        if whole.is_empty()
            || !whole.bytes().all(|b| b.is_ascii_digit())
            || fractional.len() > 4
            || !fractional.bytes().all(|b| b.is_ascii_digit())
        {
            return Err(Error::InvalidPrice);
        }
        let whole = whole.parse::<u64>().map_err(|_| Error::InvalidPrice)?;
        let mut fraction = if fractional.is_empty() {
            0
        } else {
            fractional.parse::<u64>().map_err(|_| Error::InvalidPrice)?
        };
        for _ in fractional.len()..4 {
            fraction *= 10;
        }
        Self::from_ticks(
            whole
                .checked_mul(Self::SCALE)
                .and_then(|n| n.checked_add(fraction))
                .ok_or(Error::InvalidPrice)?,
        )
    }
}
impl fmt::Display for Price {
    fn fmt(&self, f: &mut fmt::Formatter<'_>) -> fmt::Result {
        write!(f, "{}.{:04}", self.0 / Self::SCALE, self.0 % Self::SCALE)
    }
}
#[derive(Clone, Copy, Debug, PartialEq, Eq)]
pub enum Side {
    Buy,
    Sell,
}
#[derive(Clone, Debug, PartialEq, Eq)]
pub struct Order {
    pub side: Side,
    pub price: Price,
    pub quantity: u64,
}
#[derive(Clone, Debug, PartialEq, Eq)]
pub enum Action {
    Place { id: OrderId, order: Order },
    Cancel { id: OrderId },
}
#[derive(Clone, Debug, PartialEq, Eq)]
pub struct Event {
    pub sequence: EventId,
    pub action: Action,
}
#[derive(Clone, Debug, PartialEq, Eq)]
pub enum Error {
    InvalidPrice,
    InvalidQuantity,
    InvalidLimit,
    Sequence { expected: u64, received: u64 },
    Duplicate(OrderId),
    Missing(OrderId),
    Capacity,
    Overflow,
}
impl fmt::Display for Error {
    fn fmt(&self, f: &mut fmt::Formatter<'_>) -> fmt::Result {
        write!(f, "{self:?}")
    }
}
impl std::error::Error for Error {}

#[derive(Clone, Debug, PartialEq, Eq)]
pub struct Replay {
    orders: BTreeMap<OrderId, Order>,
    next_sequence: u64,
    capacity: usize,
    accepted: u64,
    /// Sum of submitted price ticks * quantity, not profit or traded volume.
    submitted_notional_ticks: u128,
}
impl Replay {
    pub fn new(capacity: usize) -> Result<Self, Error> {
        if capacity == 0 || capacity > 4096 {
            return Err(Error::InvalidLimit);
        }
        Ok(Self {
            orders: BTreeMap::new(),
            next_sequence: 1,
            capacity,
            accepted: 0,
            submitted_notional_ticks: 0,
        })
    }
    pub fn orders(&self) -> &BTreeMap<OrderId, Order> {
        &self.orders
    }
    pub fn accepted(&self) -> u64 {
        self.accepted
    }
    pub fn submitted_notional_ticks(&self) -> u128 {
        self.submitted_notional_ticks
    }
    /// Validation precedes mutation: a rejected event leaves the entire state unchanged.
    pub fn apply(&mut self, event: Event) -> Result<(), Error> {
        if event.sequence.0 != self.next_sequence {
            return Err(Error::Sequence {
                expected: self.next_sequence,
                received: event.sequence.0,
            });
        }
        let next = self.next_sequence.checked_add(1).ok_or(Error::Overflow)?;
        let accepted = self.accepted.checked_add(1).ok_or(Error::Overflow)?;
        match event.action {
            Action::Place { id, order } => {
                if order.quantity == 0 || order.quantity > 1_000_000_000 {
                    return Err(Error::InvalidQuantity);
                }
                if self.orders.contains_key(&id) {
                    return Err(Error::Duplicate(id));
                }
                if self.orders.len() == self.capacity {
                    return Err(Error::Capacity);
                }
                let notional = self
                    .submitted_notional_ticks
                    .checked_add(u128::from(order.price.0) * u128::from(order.quantity))
                    .ok_or(Error::Overflow)?;
                self.orders.insert(id, order);
                self.submitted_notional_ticks = notional;
            }
            Action::Cancel { id } => {
                if self.orders.remove(&id).is_none() {
                    return Err(Error::Missing(id));
                }
            }
        }
        self.next_sequence = next;
        self.accepted = accepted;
        Ok(())
    }
    /// Stable quick check, not a collision-free substitute for comparing complete states.
    pub fn digest(&self) -> u64 {
        let mut hash = 0xcbf2_9ce4_8422_2325u64;
        let mut feed = |number: u64| {
            for b in number.to_le_bytes() {
                hash = (hash ^ u64::from(b)).wrapping_mul(0x100_0000_01b3);
            }
        };
        feed(self.accepted);
        feed(self.submitted_notional_ticks as u64);
        feed((self.submitted_notional_ticks >> 64) as u64);
        for (id, order) in &self.orders {
            feed(id.0);
            feed(u64::from(order.side == Side::Sell));
            feed(order.price.0);
            feed(order.quantity);
        }
        hash
    }
}

pub fn synthetic(count: usize) -> Result<impl Iterator<Item = Event>, Error> {
    if count > 10_000_000 {
        return Err(Error::InvalidLimit);
    }
    Ok((0..count).map(|index| {
        let group = (index / 4) as u64;
        let first = group * 2 + 1;
        let action = match index % 4 {
            0 => Action::Place {
                id: OrderId(first),
                order: Order {
                    side: Side::Buy,
                    price: Price(1_000_000 + group % 97),
                    quantity: 10,
                },
            },
            1 => Action::Place {
                id: OrderId(first + 1),
                order: Order {
                    side: Side::Sell,
                    price: Price(1_000_100 + group % 97),
                    quantity: 12,
                },
            },
            2 => Action::Cancel { id: OrderId(first) },
            _ => Action::Cancel {
                id: OrderId(first + 1),
            },
        };
        Event {
            sequence: EventId(index as u64 + 1),
            action,
        }
    }))
}
pub fn run(count: usize) -> Result<Replay, Error> {
    let mut replay = Replay::new(4096)?;
    for event in synthetic(count)? {
        replay.apply(event)?;
    }
    Ok(replay)
}

        let mut r = Replay::new(1).unwrap();
        r.apply(place(1, 1)).unwrap();
        let before = r.clone();
        assert_eq!(r.apply(place(2, 2)), Err(Error::Capacity));
        assert_eq!(r, before);
        assert_eq!(
            r.apply(Event {
                sequence: EventId(2),
                action: Action::Cancel { id: OrderId(99) }
            }),
            Err(Error::Missing(OrderId(99)))
        );
        assert_eq!(r, before);
        r.apply(Event {
            sequence: EventId(2),
            action: Action::Cancel { id: OrderId(1) },
        })
        .unwrap();
        r.apply(place(3, 2)).unwrap();
    }
    #[test]
    fn injected_accounting_overflow_does_not_partially_insert() {
        let mut r = Replay::new(2).unwrap();
        r.submitted_notional_ticks = u128::MAX;
        let before = r.clone();
        assert_eq!(r.apply(place(1, 1)), Err(Error::Overflow));
        assert_eq!(r, before);
    }
    #[test]
    fn injected_counter_overflow_preserves_complete_state() {
        for overflow_sequence in [true, false] {
            let mut r = Replay::new(2).unwrap();
            r.apply(place(1, 7)).unwrap();
            if overflow_sequence {
                r.next_sequence = u64::MAX;
            } else {
                // This deliberately injected state exercises the defensive counter
                // check; public construction keeps accepted and sequence related.
                r.accepted = u64::MAX;
            }
            let before = r.clone();
            for event in [
                place(r.next_sequence, 8),
                Event {
                    sequence: EventId(r.next_sequence),
                    action: Action::Cancel { id: OrderId(7) },
                },
            ] {
                assert_eq!(r.apply(event), Err(Error::Overflow));
                assert_eq!(r, before);
            }
        }
    }
    #[test]
    fn synthetic_processing_keeps_live_state_bounded() {
        let mut r = Replay::new(2).unwrap();
        for event in synthetic(4000).unwrap() {
            r.apply(event).unwrap();
            assert!(r.orders.len() <= 2);
        }
        assert!(r.orders.is_empty());
    }

apply first compares the event sequence with next_sequence and computes checked increments. For a placement, it validates quantity, duplicate status and capacity, then checks the new accumulated notional before inserting. Only after the operation succeeds does it publish the next sequence and accepted count. The cancellation branch removes an existing order; removing a missing key changes nothing and returns an error. The test clones the whole Replay before a rejected event and compares the complete state afterward. That assertion is stronger than checking only the number of orders.

Exact arithmetic still needs overflow policy

Fixed-point integers avoid binary floating-point rounding for the chosen scale, but they do not make overflow impossible. Price and quantity have explicit limits. Their product is accumulated in u128 with checked_add. The submitted_notional_ticks field is a sum of submitted values, not executed volume or profit. The overflow test deliberately sets internal accounting to its maximum and attempts another placement. It asserts that overflow rejects the event without partially inserting the order or advancing sequence. This is failure injection aimed at a real boundary, even though the ordinary small synthetic workload will not approach it.

Determinism includes ordering and inputs

The map is a BTreeMap, so iteration uses a defined key order. The generator derives every event from its index and does not read wall-clock time or random operating-system state. The core uses no concurrent mutation, floating-point accumulation or external I/O. Those choices make identical input streams produce identical full states under the stated semantics. The digest summarizes accepted count, notional and sorted live orders using a stable byte order, but it can collide and does not include every internal field. Use full equality for correctness tests and treat the digest as a convenient quick check.

Playbook investigation: equal digests, unequal behavior

You receive a report saying two implementations are equivalent because their benchmark digests match. The report omits rejection behavior and uses a count divisible by four, which leaves no active orders. Observations are therefore weaker than the conclusion. Propose competing hypotheses: both implementations are correct, one skips an invalid transition, or the workload fails to exercise the changed path. Construct a short stream ending with live orders and include duplicate, missing-cancel and out-of-order events. If either implementation changes state after rejection, that disproves equivalence even if the original benchmark digest matched.

Choose another disproof experiment independently. One option is comparing complete state after every accepted prefix rather than only the final empty map. Another is changing an exact price by one tick and following its contribution through accounting. Record the earliest divergent transition so the investigation targets a small cause. The fix should restore the specified transition semantics and add a regression at that boundary; changing the digest until outputs match would merely hide the symptom.

Engineering decisions and evidence

Current scope and invariants. The next sequence is exact, live order count is capped, fixed-point prices are validated, and rejected events preserve the entire replay state. All fallible accounting is checked before a placement is committed.

Why this is the current recommended shape. Newtypes separate event and order IDs; a private Price representation prevents invalid ticks entering through safe constructors. Replay accounting stays private behind read-only getters, so callers cannot bypass transition validation by assigning metrics. Integer arithmetic expresses the chosen scale exactly. A BTreeMap gives stable iteration, generators stream events, and full-state comparisons accompany digest checks.

Reasonable alternative and tradeoff. A hash map can offer different lookup costs, but deterministic output would need a separate ordering step and measurement on a representative workload. A mature decimal type is appropriate when varying scales or richer decimal operations become requirements. Neither abstraction is needed to express this fixed four-place bounded exercise clearly.

Evidence and limits. Native reference tests were run through mise in the coordinated course verification; inspect the current verification record for exact results. Exact decimal grammar and limits; full-state deterministic replay; duplicate and sequence rejection; capacity and absent cancellation; injected accounting overflow; bounded generated live state. The supplied generator keeps only two live orders. A digest can collide and omits internal details; it is not an equivalence proof. Local benchmark samples include generation and exclude final digest/destruction. No universal timing claims are made.

Requirement that would justify evolution. Revisit representation and benchmark workload when active-state size, persistence, out-of-order arrival or domain rules expand. This is a state-transition exercise, not a matching engine. Add an amendment only after specifying its accounting and identity semantics.

In your review, explain this choice in your own words, preserve the behavioral contract during changes, and name the evidence that would make you choose the alternative. Deliberately broken variants above are diagnostic exercises, never recommended implementation stages.

A reproducible run starts with an exact CLI contract

The replay command accepts zero arguments for 100003 generated events, or exactly one event count parsed as usize. The count therefore fits this target's pointer-sized unsigned integer; it is not a floating-point quantity. Extra arguments are rejected. Previously, reading only nth(1) let 3 extra silently run three events, which could hide a mistyped benchmark or reproducibility command. The corrected parser checks arity before any replay work and handles non-UTF-8 text as an input error rather than panicking.

projects/reference/p12-replay/src/main.rs
use std::{
    io::{self, Write},
    process::ExitCode,
};

fn count() -> io::Result<usize> {
    let mut args = std::env::args_os().skip(1);
    let count = args.next();
    if args.next().is_some() {
        return Err(io::Error::new(
            io::ErrorKind::InvalidInput,
            "usage: p12-replay [EVENT_COUNT]",
        ));
    }
    let Some(count) = count else {
        return Ok(100_003);
    };
    let count = count.to_str().ok_or_else(|| {
        io::Error::new(
            io::ErrorKind::InvalidInput,
            "event count must be valid UTF-8",
        )
    })?;
    count.parse().map_err(|error| {
        io::Error::new(
            io::ErrorKind::InvalidInput,
            format!("invalid event count: {error}"),
        )
    })
}

fn run() -> io::Result<()> {
    let replay = p12_replay::run(count()?).map_err(io::Error::other)?;
    let mut output = io::stdout().lock();
    writeln!(
        output,
        "events={} active={} submitted_notional_ticks={} digest={:016x}",
        replay.accepted(),
        replay.orders().len(),
        replay.submitted_notional_ticks(),
        replay.digest()
    )?;
    for (id, order) in replay.orders() {
        writeln!(
            output,
            "order={} {:?} price={} quantity={}",
            id.0, order.side, order.price, order.quantity
        )?;
    }
    output.flush()?;
    Ok(())
}

fn main() -> ExitCode {
    match run() {
        Ok(()) => ExitCode::SUCCESS,
        Err(error) => {
            let _ = writeln!(io::stderr().lock(), "replay: {error}");
            if error.kind() == io::ErrorKind::InvalidInput {
                ExitCode::from(2)
            } else {
                ExitCode::FAILURE
            }
        }
    }
}

Read synthetic tick files through a bounded pipeline

The generated order-state exercise above isolates transition costs. Now cross a real file boundary. A tick here is one synthetic observed price and quantity, not an order instruction or an execution. Its output is a per-symbol summary. Keeping the tick adapter separate avoids pretending that the previous place/cancel events were market-data rows. Both remain local, reproducible exercises with no broker, credentials or live market connection.

Write the schema before the parser

The first line must be exactly event_id,timestamp_ms,symbol,price,quantity. Every data row has exactly five comma-separated fields. This deliberately narrow format has no quoted fields, comments, embedded commas, spaces or byte-order mark. LF and CRLF line endings are accepted; the final line may omit its terminator. A blank data row is an error, while a header with no rows is a valid empty replay. The file is UTF-8 even though its filesystem path remains a native operating-system path.

  • event_id: decimal digits parsed as u64. The first accepted ID is 1; each next ID must increase by exactly one. Duplicate, missing, zero and out-of-order IDs are rejected. This is rejection, not deduplication or reordering.
  • timestamp_ms: nonnegative u64 milliseconds since the Unix epoch in this synthetic data model. Values cannot move backwards. Equal timestamps are ordered by event ID. We do not convert these integers into calendar dates, consult a wall clock, infer exchange timing or claim to validate real feeds.
  • symbol: one through twelve ASCII uppercase letters. At most 64 distinct symbols are accepted by default.
  • price: positive ordinary decimal text with at most four fractional digits, at most 100000000.0000. No sign, exponent or bare trailing decimal point is accepted. Existing Price stores units of 1/10000 exactly.
  • quantity: decimal digits in 1..=1000000. It counts synthetic units. Notional is the exact sum of price ticks times quantity, not money earned or a trading return.

Every line is limited to 256 bytes including its LF or CRLF terminator. The default event budget is 1000000 and can be lowered through the library. Batches hold at most 1024 parsed ticks; the default is 64. The file CLI uses a 4096-byte input buffer. Count, volume and notional additions use checked arithmetic even though the present input limits keep valid totals well below the integer maxima.

//! Bounded synthetic CSV tick ingestion with exact, deterministic aggregates.
//! This is a synchronous staged pipeline, not a concurrent execution claim.
use crate::Price;
use std::{
    collections::BTreeMap,
    error::Error,
    fmt,
    io::{self, BufRead, Read},
};

pub const HEADER: &str = "event_id,timestamp_ms,symbol,price,quantity";
pub const MAX_LINE_BYTES: usize = 256;
pub const MAX_EVENTS: usize = 1_000_000;
pub const MAX_SYMBOLS: usize = 64;
pub const MAX_BATCH: usize = 1024;

#[derive(Debug)]
pub enum TickError {
    Io(io::Error),
    InvalidConfig,
    Header,
    LineTooLong,
    InvalidRow(&'static str),
    Sequence { expected: u64, received: u64 },
    TimestampBackwards,
    EventLimit,
    SymbolLimit,
    Overflow,
    AtLine { line: usize, source: Box<TickError> },
}
impl fmt::Display for TickError {
    fn fmt(&self, f: &mut fmt::Formatter<'_>) -> fmt::Result {
        match self {
            Self::Io(error) => write!(f, "input I/O failed: {error}"),
            Self::InvalidConfig => write!(
                f,
                "batch, event and symbol limits must be within supported nonzero bounds"
            ),
            Self::Header => write!(f, "expected exact CSV header: {HEADER}"),
            Self::LineTooLong => write!(
                f,
                "line exceeds {MAX_LINE_BYTES} bytes including its terminator"
            ),
            Self::InvalidRow(reason) => write!(f, "invalid tick: {reason}"),
            Self::Sequence { expected, received } => {
                write!(f, "expected event id {expected}, received {received}")
            }
            Self::TimestampBackwards => write!(f, "timestamp moved backwards"),
            Self::EventLimit => write!(f, "event budget exceeded"),
            Self::SymbolLimit => write!(f, "symbol budget exceeded"),
            Self::Overflow => write!(f, "aggregate overflow"),
            Self::AtLine { line, source } => write!(f, "line {line}: {source}"),
        }
    }
}
impl Error for TickError {
    fn source(&self) -> Option<&(dyn Error + 'static)> {
        match self {
            Self::Io(error) => Some(error),
            Self::AtLine { source, .. } => Some(source),
            _ => None,
        }
    }
}
impl From<io::Error> for TickError {
    fn from(error: io::Error) -> Self {
        Self::Io(error)
    }
}
fn at_line(line: usize, source: TickError) -> TickError {
    TickError::AtLine {
        line,
        source: Box::new(source),
    }
}

#[derive(Clone, Copy, Debug)]
pub struct Limits {
    pub batch: usize,
    pub events: usize,
    pub symbols: usize,
}
impl Default for Limits {
    fn default() -> Self {
        Self {
            batch: 64,
            events: MAX_EVENTS,
            symbols: MAX_SYMBOLS,
        }
    }
}
impl Limits {
    fn validate(self) -> Result<Self, TickError> {
        if !(1..=MAX_BATCH).contains(&self.batch)
            || !(1..=MAX_EVENTS).contains(&self.events)
            || !(1..=MAX_SYMBOLS).contains(&self.symbols)
        {
            return Err(TickError::InvalidConfig);
        }
        Ok(self)
    }
}

#[derive(Debug)]
struct Tick {
    id: u64,
    timestamp_ms: u64,
    symbol: String,
    price: Price,
    quantity: u64,
}

fn unsigned(text: &str) -> Result<u64, TickError> {
    if text.is_empty() || !text.bytes().all(|b| b.is_ascii_digit()) {
        return Err(TickError::InvalidRow(
            "integer fields require decimal digits only",
        ));
    }
    text.parse()
        .map_err(|_| TickError::InvalidRow("integer exceeds u64"))
}
fn parse(line: &str) -> Result<Tick, TickError> {
    let mut fields = line.split(',');
    let id = unsigned(
        fields
            .next()
            .ok_or(TickError::InvalidRow("missing event id"))?,
    )?;
    let timestamp_ms = unsigned(
        fields
            .next()
            .ok_or(TickError::InvalidRow("missing timestamp"))?,
    )?;
    let symbol = fields
        .next()
        .ok_or(TickError::InvalidRow("missing symbol"))?;
    if symbol.is_empty() || symbol.len() > 12 || !symbol.bytes().all(|b| b.is_ascii_uppercase()) {
        return Err(TickError::InvalidRow(
            "symbol requires 1..=12 ASCII uppercase letters",
        ));
    }
    let price = fields
        .next()
        .ok_or(TickError::InvalidRow("missing price"))?;
    if price.ends_with('.') {
        return Err(TickError::InvalidRow("fractional point requires digits"));
    }
    let price = Price::parse(price).map_err(|_| {
        TickError::InvalidRow(
            "price requires a positive decimal with at most four fractional digits",
        )
    })?;
    let quantity = unsigned(
        fields
            .next()
            .ok_or(TickError::InvalidRow("missing quantity"))?,
    )?;
    if !(1..=1_000_000).contains(&quantity) || fields.next().is_some() {
        return Err(TickError::InvalidRow(
            "quantity must be 1..=1000000 and exactly five fields are required",
        ));
    }
    Ok(Tick {
        id,
        timestamp_ms,
        symbol: symbol.to_owned(),
        price,
        quantity,
    })
}

#[derive(Clone, Debug, PartialEq, Eq)]
pub struct Aggregate {
    pub count: u64,
    pub volume: u64,
    /// Exact sum of price ticks (1/10000 price unit) multiplied by quantity.
    pub notional_ticks: u128,
    pub first: Price,
    pub last: Price,
    pub low: Price,
    pub high: Price,
}
#[derive(Clone, Debug, Default, PartialEq, Eq)]
pub struct Summary {
    events: u64,
    first_timestamp_ms: Option<u64>,
    last_timestamp_ms: Option<u64>,
    symbols: BTreeMap<String, Aggregate>,
}
impl Summary {
    pub fn events(&self) -> u64 {
        self.events
    }
    pub fn first_timestamp_ms(&self) -> Option<u64> {
        self.first_timestamp_ms
    }
    pub fn last_timestamp_ms(&self) -> Option<u64> {
        self.last_timestamp_ms
    }
    pub fn symbols(&self) -> &BTreeMap<String, Aggregate> {
        &self.symbols
    }

    fn apply(&mut self, tick: Tick, limits: Limits) -> Result<(), TickError> {
        let next = self.events.checked_add(1).ok_or(TickError::Overflow)?;
        if tick.id != next {
            return Err(TickError::Sequence {
                expected: next,
                received: tick.id,
            });
        }
        if self.events >= limits.events as u64 {
            return Err(TickError::EventLimit);
        }
        if self
            .last_timestamp_ms
            .is_some_and(|last| tick.timestamp_ms < last)
        {
            return Err(TickError::TimestampBackwards);
        }
        let prior = self.symbols.get(&tick.symbol);
        if prior.is_none() && self.symbols.len() >= limits.symbols {
            return Err(TickError::SymbolLimit);
        }
        let notional = u128::from(tick.price.ticks())
            .checked_mul(u128::from(tick.quantity))
            .ok_or(TickError::Overflow)?;
        let aggregate = match prior {
            None => Aggregate {
                count: 1,
                volume: tick.quantity,
                notional_ticks: notional,
                first: tick.price,
                last: tick.price,
                low: tick.price,
                high: tick.price,
            },
            Some(prior) => Aggregate {
                count: prior.count.checked_add(1).ok_or(TickError::Overflow)?,
                volume: prior
                    .volume
                    .checked_add(tick.quantity)
                    .ok_or(TickError::Overflow)?,
                notional_ticks: prior
                    .notional_ticks
                    .checked_add(notional)
                    .ok_or(TickError::Overflow)?,
                first: prior.first,
                last: tick.price,
                low: if tick.price.ticks() < prior.low.ticks() {
                    tick.price
                } else {
                    prior.low
                },
                high: if tick.price.ticks() > prior.high.ticks() {
                    tick.price
                } else {
                    prior.high
                },
            },
        };
        // All fallible domain checks precede mutation. No partial aggregate commits.
        self.symbols.insert(tick.symbol, aggregate);
        self.events = next;
        self.first_timestamp_ms.get_or_insert(tick.timestamp_ms);
        self.last_timestamp_ms = Some(tick.timestamp_ms);
        Ok(())
    }
}

fn line(reader: &mut impl BufRead) -> Result<Option<String>, TickError> {
    let mut bytes = Vec::with_capacity(MAX_LINE_BYTES + 1);
    // take bounds allocation even if the untrusted input never supplies a newline.
    (&mut *reader)
        .take((MAX_LINE_BYTES + 1) as u64)
        .read_until(b'\n', &mut bytes)?;
    if bytes.is_empty() {
        return Ok(None);
    }
    if bytes.len() > MAX_LINE_BYTES {
        return Err(TickError::LineTooLong);
    }
    if bytes.last() == Some(&b'\n') {
        bytes.pop();
        if bytes.last() == Some(&b'\r') {
            bytes.pop();
        }
    }
    String::from_utf8(bytes)
        .map(Some)
        .map_err(|_| TickError::InvalidRow("line must be valid UTF-8"))
}

/// Consume one exact-header, bounded CSV stream. Returns no summary on any error.
/// Peak retained state is at most batch parsed ticks plus symbols aggregates and
/// one line retaining at most 257 input bytes, excluding buffering inside the
/// supplied reader. Allocator overhead/capacity is not an exact physical RAM claim.
pub fn replay(mut reader: impl BufRead, limits: Limits) -> Result<Summary, TickError> {
    let limits = limits.validate()?;
    if line(&mut reader)
        .map_err(|error| at_line(1, error))?
        .as_deref()
        != Some(HEADER)
    {
        return Err(at_line(1, TickError::Header));
    }
    let mut summary = Summary::default();
    let mut batch = Vec::with_capacity(limits.batch);
    let mut line_number = 1;
    let mut eof = false;
    while !eof {
        while batch.len() < limits.batch {
            line_number += 1;
            match line(&mut reader).map_err(|error| at_line(line_number, error))? {
                None => {
                    eof = true;
                    break;
                }
                Some(text) => {
                    if summary.events as usize + batch.len() >= limits.events {
                        return Err(at_line(line_number, TickError::EventLimit));
                    }
                    batch.push((
                        line_number,
                        parse(&text).map_err(|error| at_line(line_number, error))?,
                    ));
                }
            }
        }
        for (number, tick) in batch.drain(..) {
            summary
                .apply(tick, limits)
                .map_err(|error| at_line(number, error))?;
        }
    }
    Ok(summary)
}

Limits::validate prevents zero or excessive budgets before reading. line wraps the reader in Read::take before calling read_until; a newline-free input can therefore supply at most 257 retained bytes to this operation before rejection. Checking length only after an unrestricted read_until would permit unbounded growth. This bound concerns retained input bytes; allocator capacity, metadata and operating-system buffering are not an exact RAM measurement.

parse validates the field count and each type before constructing a private Tick. The symbol becomes owned because its tick must survive reuse of the line buffer. This is a justified small ownership transfer. A borrowed symbol would require retaining the owning line across the batch, making that ownership structure more complex without serving this scope.

replay fills one reusable vector and drains it in input order into Summary::apply. Draining preserves vector capacity. This is a synchronous staged pipeline: the producer stops reading whenever the batch is full, and there are no channels or spawned tasks. It bounds work retained between ingestion and aggregation without claiming parallel speed. The BTreeMap limits state to the admitted symbols and gives deterministic sorted report order. For N events, B batch capacity and S symbols, retained domain state is O(B + S), and aggregation is O(N log S), plus reading and bounded parsing work.

apply checks the next ID, timestamp and symbol budget, computes a prospective aggregate with checked arithmetic, and only then mutates the map and counters. A rejected event leaves that summary unchanged. The public file replay returns either a whole successful summary or an error; the CLI prints no successful partial summary after an input error. It may have read and processed a prefix internally. Because batch parsing and application are distinct stages, malformed files can reveal different first diagnostics at different batch sizes; the contract promises rejection, not a batch-independent choice among multiple defects.

First and last refer to event order for that symbol. Low and high compare integer price ticks. A volume-weighted average would be the rational value notional_ticks / volume, still expressed in price ticks. This adapter retains the exact numerator and denominator rather than silently rounding a display value. A future display needs an explicit rounding rule.

//! Replay an explicitly bounded synthetic tick fixture; no live-market integration.
use p12_replay::ticks::{self, Limits};
use std::{
    fs::File,
    io::{self, BufReader, Write},
    path::PathBuf,
    process::ExitCode,
};

fn run() -> Result<(), Box<dyn std::error::Error>> {
    let args: Vec<_> = std::env::args_os().skip(1).collect();
    let [path, rest @ ..] = args.as_slice() else {
        return Err("usage: tick_replay PATH [BATCH_SIZE 1..=1024]".into());
    };
    let batch = match rest {
        [] => Limits::default().batch,
        [batch] => batch
            .to_str()
            .ok_or("batch size must be UTF-8 integer text")?
            .parse::<usize>()?,
        _ => return Err("usage: tick_replay PATH [BATCH_SIZE 1..=1024]".into()),
    };
    if !(1..=ticks::MAX_BATCH).contains(&batch) {
        return Err("batch size must be 1..=1024".into());
    }
    let file = File::open(PathBuf::from(path))?;
    let summary = ticks::replay(
        BufReader::with_capacity(4096, file),
        Limits {
            batch,
            ..Limits::default()
        },
    )?;
    let mut output = io::stdout().lock();
    writeln!(
        output,
        "SIMULATED TICKS: events={} first_timestamp_ms={:?} last_timestamp_ms={:?}",
        summary.events(),
        summary.first_timestamp_ms(),
        summary.last_timestamp_ms()
    )?;
    writeln!(
        output,
        "symbol,count,volume,notional_ticks,first,last,low,high"
    )?;
    for (symbol, a) in summary.symbols() {
        writeln!(
            output,
            "{symbol},{},{},{},{},{},{},{}",
            a.count, a.volume, a.notional_ticks, a.first, a.last, a.low, a.high
        )?;
    }
    output.flush()?;
    Ok(())
}
fn main() -> ExitCode {
    match run() {
        Ok(()) => ExitCode::SUCCESS,
        Err(error) => {
            // Errors are visible; a failed replay emits no successful partial report.
            let _ = writeln!(io::stderr().lock(), "tick replay: {error}");
            ExitCode::FAILURE
        }
    }
}

Deliberate mistake and playbook investigation

In the learner copy only, duplicate row 2. The intended result is a sequence error, not double-counted volume. Hypothesis A says equal timestamps make duplicates legitimate; hypothesis B says event identity controls admission independently of time. The original fixture already has tied timestamps and succeeds, while the duplicated ID is rejected. That comparison disproves A. Sorting rows by timestamp would hide neither a duplicate identity nor a gap, and silently dropping repeats would introduce a new idempotency contract the exercise has not specified.

The worked regression constructs one accepted tick and then tries a duplicate, a skipped ID, a backwards timestamp and a second symbol beyond a lowered limit. It compares the entire summary after every rejection. Separate fault-injection cases set internal counters near overflow and verify no partial mutation. Those injected states are intentionally outside normal bounded input; they exercise defensive arithmetic branches, not a claim that valid fixtures can reach them.

Independent practice and progressively revealed review

Add a VWAP display with an explicit tie-breaking rounding rule. Specify what happens for an empty replay. Then design, without implementing immediately, a deduplication policy that distinguishes an identical retried event from a conflicting event using the same ID. State how much history it retains and what happens after that history expires. Finally investigate whether batch size helps this file workload before changing its default.

Hint 1: keep domain arithmetic exact

Divide the integer notional by volume only at the display boundary. The remainder contains the information needed to decide rounding. Empty input has no symbol aggregate and therefore no VWAP.

Hint 2: identity is not payload equality

A set of IDs can reject repeats but cannot explain whether a repeated ID carries a changed symbol, price or quantity. Define conflict behavior before choosing retained data.

Reference reasoning

For a four-place display, compute quotient and remainder in price ticks. For round-half-up, increment the quotient when twice the remainder is at least the volume; use checked or sufficiently wide arithmetic and state that this differs from half-even. Return no value for zero volume. A bounded deduplication window requires a retained ID-to-content representation and a policy for older repeats; a digest alone adds a collision assumption. Benchmark equivalent successful inputs in release mode, compare complete aggregates and retain all samples. Larger batches add temporary owned values and may not improve throughput in a synchronous pipeline.

When you get stuck

Read the reported line and reduce the file to its header plus the smallest prefix that still fails. Keep event IDs and the intended timestamp policy in the report. Compare batch=1 with the failing batch size to locate parsing versus state transition, then inspect the test that challenges that boundary. Ask for review with the fixture bytes, expected full aggregate, exact command, actual error and one competing hypothesis. Do not request an optimization before confirming identical semantics.

Engineering decisions and evidence

The standard library and the existing exact Price type suffice for this restricted format. A maintained CSV parser would be appropriate if quoted fields or broad CSV interoperability were required; it would still need an outer byte budget. Concurrent stages would require a measured bottleneck plus explicit queue, cancellation and task-ownership policies. Sorting an unbounded file would violate this adapter's retained-state contract; supporting out-of-order ticks needs a defined bounded reorder window or external storage.

The tests cover exact aggregates, batch boundary equivalence, grammar, CRLF and final-line behavior, row/budget rejection, duplicate and out-of-order IDs, backwards timestamps, unchanged state on rejected events, checked-overflow injection, an infinite newline-free reader, I/O failure, and a generated 20000-row stream that does not retain the file. This is evidence for the concrete resource design and invariants, not a measured RSS bound or tick-throughput claim.

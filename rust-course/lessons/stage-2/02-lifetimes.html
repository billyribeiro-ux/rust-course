Borrowed views: describe the owner instead of fighting annotations

Explain Record lifetimes and choose when a view must become owned data.

Read with a terminal open. Predict before revealing. Verified source versions: version ledger.

Prerequisites and learning objectives
  • Layer configuration, then validate the effective state
  • Connect returned slices to the input that owns their bytes
  • Distinguish lifetime relationships from extending storage
  • Design streaming aggregation that does not retain stale line views

Key terms: allocation · borrow · edition · enum · lifetime · mise · ownership · slice

Purpose: parse text without copying every field

The log parser returns a Record containing a numeric timestamp, a copied Level, and borrowed service and message slices. Those slices point into the input line. This is efficient and easy to reason about while the analyzer uses the record immediately, updates counters, and then reuses its line buffer. The lifetime question becomes concrete: how long may a Record view remain valid relative to the String or byte buffer that owns its text?

A lifetime annotation describes a relationship between references. It does not allocate memory, delay destruction, or extend the life of a local variable. Record<'a> says that its borrowed fields remain valid for an appropriate lifetime 'a. parse_record(input: &str) -> Result<Record<'_>, ...> connects the returned view to the borrowed input through elision. The compiler checks that callers do not keep using the view after its backing text can change or disappear.

Prediction: which value must survive?

Predict whether a function can create a local String, parse a borrowed Record from it, and return that Record. Expected: no, because the String is dropped at the function's end while the returned fields would refer to its former allocation. Adding 'static to the return type cannot repair the ownership problem. A static string literal can support a static view; a String constructed inside the function does not become static by declaration.

Guided checkpoint: follow one borrowed record

Read parse_record and mark where splitn returns slices of its input. Parsing timestamp produces an owned u64 value. Matching level produces a small owned enum. service and message remain slices into the original line. No collection of newly allocated strings is required for these fields. Then read analyze: the record is consumed for counting within the current loop iteration, and no borrowed field is stored in Report. The next read may clear and reuse the line buffer only after those views are no longer needed.

//! Bounded-memory, line-oriented log analysis with borrowed record fields.
//! ```
//! use log_detective::{analyze, Limits};
//! let report = analyze(&b"10 INFO api ready\n11 ERROR api unavailable\n"[..], Limits::default())?;
//! assert_eq!(report.errors, 1);
//! assert_eq!(report.valid, 2);
//! # Ok::<(), std::io::Error>(())
//! ```
use std::io::{self, BufRead, Write};
#[derive(Clone, Copy, Debug, PartialEq, Eq)]
pub enum Level {
    Info,
    Warn,
    Error,
}
#[derive(Debug, PartialEq, Eq)]
pub struct Record<'a> {
    pub timestamp: u64,
    pub level: Level,
    pub service: &'a str,
    pub message: &'a str,
}
pub fn parse_record(input: &str) -> Result<Record<'_>, &'static str> {
    let mut fields = input.splitn(4, ' ');
    let timestamp = fields
        .next()
        .ok_or("timestamp missing")?
        .parse()
        .map_err(|_| "invalid timestamp")?;
    let level = match fields.next() {
        Some("INFO") => Level::Info,
        Some("WARN") => Level::Warn,
        Some("ERROR") => Level::Error,
        _ => return Err("invalid level"),
    };
    let service = fields.next().ok_or("service missing")?;
    if service.is_empty()
        || !service
            .bytes()
            .all(|b| b.is_ascii_alphanumeric() || b == b'-' || b == b'_')
    {
        return Err("invalid service");
    }
    let message = fields.next().ok_or("message missing")?;
    if message.trim().is_empty() || message.chars().any(char::is_control) {
        return Err("invalid message");
    }
    Ok(Record {
        timestamp,
        level,
        service,
        message,
    })
}
#[derive(Clone, Copy, Debug)]
pub struct Limits {
    pub max_line_bytes: usize,
    pub max_total_bytes: u64,
}
impl Default for Limits {
    fn default() -> Self {
        Self {
            max_line_bytes: 4096,
            max_total_bytes: 64 * 1024 * 1024,
        }
    }
}
#[derive(Default, Debug, PartialEq, Eq)]
pub struct Report {
    pub lines: u64,
    pub valid: u64,
    pub malformed: u64,
    pub oversized: u64,
    pub info: u64,
    pub warnings: u64,
    pub errors: u64,
}
enum Line {
    End,
    Data,
    Oversized,
}
fn read_bounded<R: BufRead>(
    reader: &mut R,
    output: &mut Vec<u8>,
    limit: usize,
    total: &mut u64,
    total_limit: u64,
) -> io::Result<Line> {
    output.clear();
    let mut seen = false;
    let mut oversized = false;
    loop {
        let available = match reader.fill_buf() {
            Ok(bytes) => bytes,
            Err(error) if error.kind() == io::ErrorKind::Interrupted => continue,
            Err(error) => return Err(error),
        };
        if available.is_empty() {
            return Ok(if !seen {
                Line::End
            } else if oversized {
                Line::Oversized
            } else {
                Line::Data
            });
        }
        let newline = available.iter().position(|&b| b == b'\n');
        let take = newline.map_or(available.len(), |n| n + 1);
        *total = total
            .checked_add(take as u64)
            .filter(|&n| n <= total_limit)
            .ok_or_else(|| {
                io::Error::new(io::ErrorKind::InvalidData, "input byte limit exceeded")
            })?;
        let payload = if newline.is_some() { take - 1 } else { take };
        if !oversized {
            if payload > limit.saturating_sub(output.len()) {
                oversized = true;
                output.clear();
            } else {
                output.extend_from_slice(&available[..payload]);
            }
        }
        reader.consume(take);
        seen = true;
        if newline.is_some() {
            if oversized {
                return Ok(Line::Oversized);
            }
            if output.last() == Some(&b'\r') {
                output.pop();
            }
            return Ok(Line::Data);
        }
    }
}
/// At most `max_line_bytes` retained per line; an oversized line is drained.
/// Reader buffering is additional memory controlled by the caller.
pub fn analyze<R: BufRead>(reader: R, limits: Limits) -> io::Result<Report> {
    scan(reader, limits, None, &mut io::sink()).map(|result| result.summary)
}

/// Search valid records with a case-sensitive literal UTF-8 substring.
///
/// The query covers the complete normalized record (including its fields).
/// There is no case folding or Unicode normalization. Matching lines are written
/// immediately, with one LF terminator; CRLF input is normalized to LF.
/// Malformed and oversized lines are counted but never emitted. All valid
/// records contribute to the summary, whether or not they match.
///
/// Input/output errors abort the scan: the destination may already contain a
/// prefix, but no successful report is returned. The caller owns flushing.
/// ```
/// use log_detective::{search, Limits};
/// let mut output = Vec::new();
/// let result = search(&b"1 INFO api ready\n2 ERROR api retry\n"[..],
///     Limits::default(), "retry", &mut output)?;
/// assert_eq!(result.matched, 1);
/// assert_eq!(result.summary.valid, 2);
/// assert_eq!(output, b"2 ERROR api retry\n");
/// # Ok::<(), std::io::Error>(())
/// ```
pub fn search<R: BufRead, W: Write>(
    reader: R,
    limits: Limits,
    query: &str,
    output: &mut W,
) -> io::Result<SearchReport> {
    if query.is_empty() || query.len() > 4096 || query.chars().any(char::is_control) {
        return Err(io::Error::new(
            io::ErrorKind::InvalidInput,
            "query must be 1..=4096 UTF-8 bytes without control characters",
        ));
    }
    scan(reader, limits, Some(query), output)
}

/// Fixed-cardinality counters: no collection grows with services or matches.
#[derive(Debug, PartialEq, Eq)]
pub struct SearchReport {
    pub summary: Report,
    pub matched: u64,
}

fn scan<R: BufRead, W: Write>(
    mut reader: R,
    limits: Limits,
    query: Option<&str>,
    output: &mut W,
) -> io::Result<SearchReport> {
    if limits.max_line_bytes == 0
        || limits.max_line_bytes > 1024 * 1024
        || limits.max_total_bytes == 0
    {
        return Err(io::Error::new(
            io::ErrorKind::InvalidInput,
            "line limit must be 1..=1048576 and total limit positive",
        ));
    }
    let mut report = Report::default();
    let mut matched = 0;
    let mut line = Vec::new();
    let mut total = 0;
    loop {
        match read_bounded(
            &mut reader,
            &mut line,
            limits.max_line_bytes,
            &mut total,
            limits.max_total_bytes,
        )? {
            Line::End => {
                return Ok(SearchReport {
                    summary: report,
                    matched,
                });
            }
            Line::Oversized => {
                report.lines += 1;
                report.oversized += 1;
            }
            Line::Data => {
                report.lines += 1;
                let text = std::str::from_utf8(&line).map_err(|_| "invalid UTF-8");
                match text.and_then(parse_record) {
                    Err(_) => report.malformed += 1,
                    Ok(record) => {
                        report.valid += 1;
                        match record.level {
                            Level::Info => report.info += 1,
                            Level::Warn => report.warnings += 1,
                            Level::Error => report.errors += 1,
                        }
                        // A valid record was parsed from this same UTF-8 line.
                        // Searching its full text never indexes into a character.
                        if let (Some(query), Ok(text)) = (query, text)
                            && text.contains(query)
                        {
                            output.write_all(text.as_bytes())?;
                            output.write_all(b"\n")?;
                            matched += 1;
                        }
                    }
                }
            }
        }
    }
}

mod tests {
    use super::*;
    use std::io::{BufReader, Cursor};
    #[test]
    fn tiny_buffers_and_final_line() {
        let input = b"1 INFO api ready\r\n2 WARN db slow\n3 ERROR api failed";
        let report = analyze(
            BufReader::with_capacity(1, Cursor::new(input)),
            Limits::default(),
        )
        .unwrap();
        assert_eq!(
            report,
            Report {
                lines: 3,
                valid: 3,
                info: 1,
                warnings: 1,
                errors: 1,
                ..Report::default()
            }
        );
    }
    #[test]
    fn drain_oversized_then_recover() {
        let bytes = b"aaaaaaaaaaaaaaaaaaaaaa\n1 INFO x ok\n\xff\n";
        let report = analyze(
            BufReader::with_capacity(3, Cursor::new(bytes)),
            Limits {
                max_line_bytes: 12,
                max_total_bytes: 100,
            },
        )
        .unwrap();
        assert_eq!(
            (
                report.lines,
                report.oversized,
                report.valid,
                report.malformed
            ),
            (3, 1, 1, 1)
        );
    }
    #[test]
    fn rejects_total_exhaustion_and_invalid_limits() {
        assert!(
            analyze(
                &b"12345"[..],
                Limits {
                    max_line_bytes: 2,
                    max_total_bytes: 4
                }
            )
            .is_err()
        );
        assert!(
            analyze(
                &b""[..],
                Limits {
                    max_line_bytes: 0,
                    max_total_bytes: 4
                }
            )
            .is_err()
        );
    }
    #[test]
    fn accounting_property_across_buffer_sizes() {
        let input = b"1 INFO x ok\nbad\n2 ERROR y no\n\n";
        for capacity in 1..=32 {
            let r = analyze(
                BufReader::with_capacity(capacity, Cursor::new(input)),
                Limits::default(),
            )
            .unwrap();
            assert_eq!(r.lines, r.valid + r.malformed + r.oversized);
            assert_eq!(r.valid, r.info + r.warnings + r.errors);
            assert_eq!((r.lines, r.valid), (4, 2));
        }
    }
}

This local-use pattern is a common way to make borrowing simple. Do not retain references merely to avoid all allocations. If the feature requires a list of error messages after the file has been read, those selected messages need storage that survives the reused buffer. One reasonable design allocates owned Strings only for retained errors. Another stores offsets into an immutable whole-file buffer, but that changes the memory contract. The correct ownership model follows the feature's retention requirements.

An explicit two-input relationship

Consider a helper that returns the longer of two borrowed service names. If it can return either argument, both inputs and the output need a common lifetime relationship, often written fn longer<'a>(left: &'a str, right: &'a str) -> &'a str. This does not force the original Strings to live equally long. It requires the returned view to be used within a period for which the selected inputs can support the relationship. The caller may use a shorter overlap even if one owner lives much longer.

If the function always returns left, a second independent lifetime or an elided right input can express that weaker relationship. This distinction matters: annotations should state the actual source of returned references, not tie everything together by habit. A compiler suggestion can make code compile while imposing a unnecessarily restrictive API. Read the function body and the caller's need before accepting a proposed lifetime signature.

Intentional mistake: collect views from a reusable buffer

In a learner analyzer, try pushing record.message into Vec<&str> while repeatedly clearing and refilling the same String. The desired Vec claims that all messages remain available, while the storage strategy keeps only one mutable line. The borrow checker exposes that contradiction. The fix is not a longer annotation or an unsafe pointer. Either own each retained message, retain the original backing storage, or change the output to aggregate information that does not need old text.

Cloning the entire file would technically provide durable storage but violate the streaming project's resource goal. Allocating every message may also violate the intended bounded report unless you impose a retention limit. A safe design must satisfy both ownership and resource requirements. Memory safety alone does not imply acceptable memory growth. State a maximum number or total bytes of retained examples if your report gains sample messages.

Playbook: the compiler rejects collected messages

Observation: the analyzer compiles when it counts errors but fails when it stores borrowed messages across iterations. Hypothesis A: Record<'_> needs a different spelling of its lifetime. Hypothesis B: retained views outlive the reusable line buffer's stable contents. Distinguishing experiment: replace the stored &str with an owned String for one selected message while leaving parsing unchanged. Expected result: the ownership conflict disappears. This supports B and disproves a missing-annotation explanation for this design.

That experiment does not automatically justify unbounded retention. Follow it with a second design question: what is the maximum retained data? Record both conclusions separately. Ask AI to draw owner/view lifetimes for the original and revised design, then ask for a counterexample to its memory-bound claim. A useful answer should mention the number of errors, not merely say that cloning is safe.

When you get stuck: independent work and tiered help

Extend Report with at most three owned example messages from malformed UTF-8-valid lines, truncating each example at a safe UTF-8 boundary under a documented byte limit. Decide how invalid UTF-8 input is represented without inventing text that was not present. Test a multibyte character at the truncation boundary. Your extension changes retention deliberately while keeping a bounded amount of additional memory. The supplied reference remains counters-only, so keep this experiment in your learner workspace.

Hint 2: narrow the experiment

Worked solution for selected valid text

use message.to_owned() only when retaining it, enforce a maximum retained count, and discard the temporary borrowed Record before reading again. For truncation, retreat to a char boundary rather than slicing at an arbitrary byte. A review request should include the ownership diagram and the proposed bound, not just the lifetime error text.

Review and mastery

The recommended approach chooses storage according to retention requirements, then describes the resulting reference relationships. Borrowed records are appropriate for immediate aggregation; bounded owned samples are appropriate when selected messages must survive buffer reuse. Elided lifetimes keep an unambiguous single-input relationship concise, while explicit annotations communicate relationships involving multiple possible input owners. Neither representation replaces the need to account for retained memory.

Mastery means explaining why parse_record can return borrowed fields, why a local-owner function cannot, and how to retain a small bounded sample without stale references. Compilation is evidence for safe-reference validity, while tests verify field parsing and retention policy. Neither establishes a benchmark advantage over owned strings. If you claim a performance benefit, measure realistic workloads separately rather than inferring speed from the absence of one visible clone.

Purpose: turn a string into a structure with meaning

The calculator accepted exactly one operator. The expression language accepts combinations such as 2 + 3 * 4 and (2 + 3) * 4. Reading characters from left to right and applying operations immediately cannot represent precedence correctly. A parser builds an abstract syntax tree, or AST, that makes grouping explicit. Evaluation later follows that structure. This separation lets you test whether the expression means the right thing independently of whether its arithmetic fits in i64.

The language supports nonnegative i64 literals, unary minus, parentheses, and four binary operators. Multiplication and division bind more tightly than addition and subtraction. Binary operators associate left, so 20 - 5 - 3 means (20 - 5) - 3. Unary minus binds more tightly than multiplication. There is no unary plus, floating-point syntax, identifier, assignment, or implicit multiplication. A grammar with explicit exclusions is easier to implement and review than one that guesses what every unfamiliar character might mean.

Prediction and a grammar trace

Predict these results and sketch a tree before running: 2 + 3 * 4 gives 14; (2 + 3) * 4 gives 20; 20 - 5 - 3 gives 12; -3 * -2 gives 6. The tree for the first has addition at its root and multiplication as its right child. The parenthesized version has multiplication at the root and addition inside its left subtree. The difference is structure, not a different evaluation rule for the same tree.

Guided checkpoint: lex with source positions

The lexer scans bytes, skips ASCII whitespace, combines consecutive ASCII digits into one number token, and recognizes punctuation. Each token carries a half-open Span with start and end byte offsets. A range start..end includes start and excludes end, matching Rust slicing conventions. Unknown characters produce an error spanning the whole Unicode scalar value, so the four-byte crab symbol in 2 + 🦀 receives bytes 4..8 rather than a misleading one-byte range.

These offsets are bytes, not terminal columns or user-perceived character counts. The CLI prints the textual range and original source instead of drawing a caret at a byte count and pretending it is a display column. A richer editor integration would convert offsets with a documented line/column convention. Preserving precise source coordinates at lexing time is much easier than reconstructing them after tokens have lost their origin.

//! An integer expression language with byte spans and explicit resource limits.
//! ```
//! assert_eq!(expression_language::evaluate("2 + 3 * 4")?, 14);
//! assert_eq!(expression_language::evaluate("(2 + 3) * 4")?, 20);
//! assert!(expression_language::evaluate("8 / 0").is_err());
//! # Ok::<(), expression_language::Error>(())
//! ```
use std::fmt;
pub const MAX_SOURCE_BYTES: usize = 4096;
pub const MAX_TOKENS: usize = 512;
pub const MAX_DEPTH: usize = 64;
#[derive(Clone, Copy, Debug, PartialEq, Eq)]
pub struct Span {
    pub start: usize,
    pub end: usize,
}
#[derive(Clone, Debug, PartialEq, Eq)]
pub struct Error {
    pub span: Span,
    pub message: &'static str,
}
impl fmt::Display for Error {
    fn fmt(&self, f: &mut fmt::Formatter<'_>) -> fmt::Result {
        write!(
            f,
            "{} at bytes {}..{}",
            self.message, self.span.start, self.span.end
        )
    }
}
impl std::error::Error for Error {}
fn error(span: Span, message: &'static str) -> Error {
    Error { span, message }
}
#[derive(Clone, Copy, Debug, PartialEq, Eq)]
enum Kind {
    Number(i64),
    Plus,
    Minus,
    Star,
    Slash,
    Open,
    Close,
}
#[derive(Clone, Copy, Debug)]
struct Token {
    kind: Kind,
    span: Span,
}
fn lex(source: &str) -> Result<Vec<Token>, Error> {
    if source.len() > MAX_SOURCE_BYTES {
        return Err(error(
            Span {
                start: 0,
                end: source.len(),
            },
            "source byte limit exceeded",
        ));
    }
    let bytes = source.as_bytes();
    let mut index = 0;
    let mut tokens = Vec::new();
    while index < bytes.len() {
        if bytes[index].is_ascii_whitespace() {
            index += 1;
            continue;
        }
        let start = index;
        let kind = match bytes[index] {
            b'0'..=b'9' => {
                while index < bytes.len() && bytes[index].is_ascii_digit() {
                    index += 1;
                }
                let value = source[start..index]
                    .parse()
                    .map_err(|_| error(Span { start, end: index }, "integer literal overflow"))?;
                Kind::Number(value)
            }
            byte => {
                index += 1;
                match byte {
                    b'+' => Kind::Plus,
                    b'-' => Kind::Minus,
                    b'*' => Kind::Star,
                    b'/' => Kind::Slash,
                    b'(' => Kind::Open,
                    b')' => Kind::Close,
                    _ => {
                        return Err(error(
                            Span {
                                start,
                                end: start
                                    + source[start..]
                                        .chars()
                                        .next()
                                        .expect("start is a remaining UTF-8 character boundary")
                                        .len_utf8(),
                            },
                            "unexpected character",
                        ));
                    }
                }
            }
        };
        if tokens.len() == MAX_TOKENS {
            return Err(error(Span { start, end: index }, "token limit exceeded"));
        }
        tokens.push(Token {
            kind,
            span: Span { start, end: index },
        });
    }
    Ok(tokens)
}
#[derive(Clone, Copy, Debug, PartialEq, Eq)]
pub enum Operator {
    Add,
    Subtract,
    Multiply,
    Divide,
}
#[derive(Debug)]
enum Node {
    Number(i64),
    Negate {
        operand: Box<Expr>,
        operator_span: Span,
    },
    Binary {
        left: Box<Expr>,
        op: Operator,
        right: Box<Expr>,
        operator_span: Span,
    },
}
/// Fields are private so callers cannot bypass the parser's depth invariant.
#[derive(Debug)]
pub struct Expr {
    node: Node,
    span: Span,
    depth: usize,
}
impl Expr {
    pub fn span(&self) -> Span {
        self.span
    }
    pub fn depth(&self) -> usize {
        self.depth
    }
    pub fn evaluate(&self) -> Result<i64, Error> {
        match &self.node {
            Node::Number(value) => Ok(*value),
            Node::Negate {
                operand,
                operator_span,
            } => operand
                .evaluate()?
                .checked_neg()
                .ok_or_else(|| error(*operator_span, "arithmetic overflow")),
            Node::Binary {
                left,
                op,
                right,
                operator_span,
            } => {
                let left = left.evaluate()?;
                let right = right.evaluate()?;
                let value = match op {
                    Operator::Add => left.checked_add(right),
                    Operator::Subtract => left.checked_sub(right),
                    Operator::Multiply => left.checked_mul(right),
                    Operator::Divide => {
                        if right == 0 {
                            return Err(error(*operator_span, "division by zero"));
                        }
                        left.checked_div(right)
                    }
                };
                value.ok_or_else(|| error(*operator_span, "arithmetic overflow"))
            }
        }
    }
}
struct Parser {
    tokens: Vec<Token>,
    cursor: usize,
    source_len: usize,
}
impl Parser {
    fn peek(&self) -> Option<Token> {
        self.tokens.get(self.cursor).copied()
    }
    fn next(&mut self) -> Option<Token> {
        let token = self.peek();
        if token.is_some() {
            self.cursor += 1;
        }
        token
    }
    fn current_span(&self) -> Span {
        self.peek().map_or(
            Span {
                start: self.source_len,
                end: self.source_len,
            },
            |t| t.span,
        )
    }
    fn expression(&mut self, minimum: u8, nesting: usize) -> Result<Expr, Error> {
        if nesting >= MAX_DEPTH {
            return Err(error(self.current_span(), "nesting limit exceeded"));
        }
        let token = self
            .next()
            .ok_or_else(|| error(self.current_span(), "expected an expression"))?;
        let mut left = match token.kind {
            Kind::Number(value) => Expr {
                node: Node::Number(value),
                span: token.span,
                depth: 1,
            },
            Kind::Minus => {
                let operand = self.expression(3, nesting + 1)?;
                let depth = operand.depth + 1;
                if depth > MAX_DEPTH {
                    return Err(error(token.span, "AST depth limit exceeded"));
                }
                Expr {
                    span: Span {
                        start: token.span.start,
                        end: operand.span.end,
                    },
                    depth,
                    node: Node::Negate {
                        operand: Box::new(operand),
                        operator_span: token.span,
                    },
                }
            }
            Kind::Open => {
                let mut inner = self.expression(0, nesting + 1)?;
                let close = self
                    .next()
                    .ok_or_else(|| error(self.current_span(), "expected closing parenthesis"))?;
                if close.kind != Kind::Close {
                    return Err(error(close.span, "expected closing parenthesis"));
                }
                inner.span = Span {
                    start: token.span.start,
                    end: close.span.end,
                };
                inner
            }
            _ => {
                return Err(error(
                    token.span,
                    "expected a number, minus, or opening parenthesis",
                ));
            }
        };
        while let Some(token) = self.peek() {
            let (precedence, op) = match token.kind {
                Kind::Plus => (1, Operator::Add),
                Kind::Minus => (1, Operator::Subtract),
                Kind::Star => (2, Operator::Multiply),
                Kind::Slash => (2, Operator::Divide),
                _ => break,
            };
            if precedence < minimum {
                break;
            }
            self.next();
            let right = self.expression(precedence + 1, nesting + 1)?;
            let depth = 1 + left.depth.max(right.depth);
            if depth > MAX_DEPTH {
                return Err(error(token.span, "AST depth limit exceeded"));
            }
            left = Expr {
                span: Span {
                    start: left.span.start,
                    end: right.span.end,
                },
                depth,
                node: Node::Binary {
                    left: Box::new(left),
                    op,
                    right: Box::new(right),
                    operator_span: token.span,
                },
            };
        }
        Ok(left)
    }
}
pub fn parse(source: &str) -> Result<Expr, Error> {
    let mut parser = Parser {
        tokens: lex(source)?,
        cursor: 0,
        source_len: source.len(),
    };
    let expression = parser.expression(0, 0)?;
    if parser.peek().is_some() {
        return Err(error(parser.current_span(), "unexpected trailing token"));
    }
    Ok(expression)
}
pub fn evaluate(source: &str) -> Result<i64, Error> {
    parse(source)?.evaluate()
}

mod tests {

    #[test]
    fn every_arithmetic_overflow_reports_its_operator() {
        // Form MIN by subtraction because unsigned integer tokens cannot hold 2^63.
        // These boundary checks must behave identically in debug and release builds.
        for (source, start) in [
            ("9223372036854775807 + 1", 20),
            ("(-9223372036854775807 - 1) - 1", 27),
            ("9223372036854775807 * 2", 20),
            ("-(-9223372036854775807 - 1)", 0),
            ("(-9223372036854775807 - 1) / -1", 27),
        ] {
            assert_eq!(
                evaluate(source),
                Err(Error {
                    span: Span {
                        start,
                        end: start + 1
                    },
                    message: "arithmetic overflow",
                }),
                "{source}"
            );
        }
        for (source, expected) in [
            ("9223372036854775807 + 0", i64::MAX),
            ("-9223372036854775807 - 1", i64::MIN),
            ("9223372036854775807 * 1", i64::MAX),
            ("(-9223372036854775807 - 1) / 1", i64::MIN),
            ("-(-9223372036854775807)", i64::MAX),
        ] {
            assert_eq!(evaluate(source), Ok(expected), "{source}");
        }
    }
    #[test]
    fn resource_limits_are_errors() {
        assert!(parse(&"(".repeat(100)).is_err());
        assert!(parse(&"-".repeat(100)).is_err());
        assert!(parse(&vec!["1"; 100].join("+")).is_err());
        assert!(parse(&vec!["1"; 300].join("+")).is_err());
        assert!(parse(&" ".repeat(MAX_SOURCE_BYTES + 1)).is_err());
    }
    #[test]
    fn exact_byte_and_token_limits_have_distinct_diagnostics() {
        let at_bytes = format!("1{}", " ".repeat(MAX_SOURCE_BYTES - 1));
        assert_eq!(evaluate(&at_bytes), Ok(1));
        let over_bytes = format!("{at_bytes} ");
        assert_eq!(
            parse(&over_bytes).unwrap_err(),
            error(
                Span {
                    start: 0,
                    end: MAX_SOURCE_BYTES + 1
                },
                "source byte limit exceeded"
            )
        );

        // 128 leaves give 127 operators and 254 parentheses: 509 tokens.
        // Three unary minuses reach 512 without approaching either depth limit.
        let mut balanced = "1".to_owned();
        for _ in 0..7 {
            balanced = format!("({balanced}+{balanced})");
        }
        let at_tokens = format!("---{balanced}");
        assert_eq!(lex(&at_tokens).unwrap().len(), MAX_TOKENS);
        assert_eq!(evaluate(&at_tokens), Ok(-128));
        let over_tokens = format!("-{at_tokens}");
        assert_eq!(
            parse(&over_tokens).unwrap_err(),
            error(
                Span {
                    start: 512,
                    end: 513
                },
                "token limit exceeded"
            )
        );
    }
    #[test]
    fn recursive_nesting_and_constructed_tree_depth_are_separate_limits() {
        // Top-level expression is recursion level one. 63 pairs use 64 calls,
        // but parentheses do not add AST nodes: the resulting tree has depth 1.
        let at_nesting = format!("{}1{}", "(".repeat(63), ")".repeat(63));
        assert_eq!(parse(&at_nesting).unwrap().depth(), 1);
        let over_nesting = format!("({at_nesting})");
        assert_eq!(
            parse(&over_nesting).unwrap_err(),
            error(Span { start: 64, end: 65 }, "nesting limit exceeded")
        );

        // A flat left-associative chain uses shallow parser recursion while its
        // result gets one level deeper per number. It exercises the other guard.
        let at_depth = vec!["1"; MAX_DEPTH].join("+");
        let tree = parse(&at_depth).unwrap();
        assert_eq!(tree.depth(), MAX_DEPTH);
        assert_eq!(tree.evaluate(), Ok(64));
        assert_eq!(
            parse(&format!("{at_depth}+1")).unwrap_err(),
            error(
                Span {
                    start: 127,
                    end: 128
                },
                "AST depth limit exceeded"
            )
        );
    }
    #[test]
    fn deterministic_exhaustive_small_integer_properties() {
        // Finite exhaustive domain, not randomized fuzzing and not a proof for all i64.
        for a in -8_i64..=8 {
            for b in -8_i64..=8 {
                for c in -4_i64..=4 {
                    assert_eq!(evaluate(&format!("({a})+({b})*({c})")).unwrap(), a + b * c);
                    assert_eq!(
                        evaluate(&format!("(({a})+({b}))*({c})")).unwrap(),
                        (a + b) * c
                    );
                    assert_eq!(
                        evaluate(&format!("({a})+({b})")).unwrap(),
                        evaluate(&format!("({b})+({a})")).unwrap()
                    );
                    // Subtraction distinguishes left from right associativity.
                    // Parenthesizing each operand does not group the operations.
                    assert_eq!(
                        evaluate(&format!("({a})-({b})-({c})")).unwrap(),
                        (a - b) - c
                    );
                }
            }
        }
    }

Guided checkpoint: precedence climbing

Parser::expression begins by parsing a prefix: number, unary minus, or a parenthesized expression. It then examines the following operator. If that operator's precedence meets the current minimum, it consumes the operator and parses the right-hand side with a higher minimum, precedence + 1. That increment makes operators of equal precedence stay for the outer loop, producing left associativity. Trace 20 - 5 - 3 and mark which recursive call is allowed to consume each minus.

Parentheses call expression with the lowest threshold and require a closing token afterward. Unary minus calls with a tighter threshold than multiplication. After the top-level expression returns, parse rejects any trailing token. Without that final check, input such as 1 2 could silently evaluate only the first number. Successful prefix parsing is not the same as successful whole-input parsing. Tests must include extra-token cases to enforce the boundary.

Resource limits are part of syntax handling

The parser limits source bytes to 4096, tokens to 512, recursive nesting to 64, and AST depth to 64. These are related but distinct protections. A long chain of additions can create a deep left-associated AST even when parentheses are shallow. Deep parentheses can create recursion without adding many AST nodes. Checking only one of these dimensions leaves another route to excessive stack use or work. The private Expr fields prevent external callers from constructing an arbitrarily deep tree that bypasses the parser's invariant.

An input can therefore be mathematically valid but rejected because it exceeds the resource contract. Return an explanatory error instead of panicking. The chosen limits are teaching defaults, not universal safe values for every platform. If you change them, test both acceptance just below the boundary and rejection above it, and reconsider recursive evaluation and destruction as well as parsing.

Intentional mistake and playbook investigation

Introduce a learner bug by parsing a binary right operand with the same minimum precedence instead of precedence + 1. Observation: 20 - 5 - 3 produces 18 rather than 12. Hypothesis A: subtraction arithmetic is wrong. Hypothesis B: equal-precedence operators grouped to the right. Distinguishing experiment: compare the unparenthesized input with both (20 - 5) - 3 and 20 - (5 - 3). Expected buggy result matches the right-grouped expression; a simple 20 - 5 still yields 15. This disproves basic subtraction as the cause and supports the grouping hypothesis.

The smallest fix is the binding threshold, followed by subtraction and division chain tests. Do not patch the evaluator to special-case consecutive subtraction. That would embed syntax repair in the wrong layer. Record the tree shape or a trace of token consumption as evidence. Ask AI to trace the parser calls with their minimum values; compare its trace against the actual code before accepting a claimed associativity fix.

Review and mastery evidence

The recommended parser uses tokens, preserved spans, and one explicit binding-threshold rule. This is a scope-appropriate implementation for four operators and unary negation. Separate recursive-descent functions can improve readability when grammar categories expand; a parser library may help with richer syntax or recovery. Choose those alternatives when the current representation makes actual language requirements difficult to state or verify.

Mastery means tracing token consumption, explaining left associativity, locating an error span in UTF-8 bytes, and showing how both a nested expression and a long flat chain are bounded. Passing the expression examples is evidence for those grammar cases. It does not prove every possible character sequence is handled correctly.

Purpose: a correct tree still needs correct execution

A parser establishes structure. Evaluation gives that structure a result or a runtime domain error. The expression 8 / 0 is syntactically valid but cannot produce an integer under our arithmetic contract. The expression 1 2 is syntactically invalid and never reaches evaluation. Keeping those failures separate helps users and tests identify the boundary that rejected the input. Your finished project should make successful results, syntax failures, arithmetic failures, and resource-limit failures all deliberate outcomes.

The evaluator recursively visits Expr nodes. A number returns its stored i64. Unary negation evaluates its operand and uses checked_neg. A binary node evaluates its left child, then its right child, and applies the corresponding checked operation. This order is observable when more than one subtree could fail: the first error stops evaluation through ?. The language has no side effects, but error ordering still affects diagnostics. Do not assume that pure arithmetic means evaluation order is irrelevant to every user-visible result.

Prediction: where should the error point?

Predict the error for 8 / 0. Expected: division by zero at bytes 2..3, the slash. The full expression span remains available on the AST, while operator_span identifies the failing operation. For 9223372036854775807 + 1, expected failure is arithmetic overflow at the plus. For the literal 9223372036854775808, overflow happens during lexing before an AST is built. The same broad word “overflow” refers to different boundaries in these cases.

A direct literal for i64::MIN is deliberately not supported by this grammar: unary minus applies to a nonnegative literal that must itself fit in i64. Write -9223372036854775807 - 1 to produce the minimum value. This limit is documented, not silently repaired in the lexer. If you later support the direct spelling, design how literal magnitudes and unary operations interact before changing parse types opportunistically.

Guided checkpoint: one recursive contract

Read Expr::evaluate and state its contract for each node variant. All successful values fit in i64. Division by zero gets its own message; checked_div still handles minimum divided by -1 as overflow. Negating the minimum similarly fails with checked_neg. The evaluator preserves the operator's source span when reporting arithmetic failure. The error payload is small and structured, allowing the CLI, tests, or a future editor to present it differently.

//! An integer expression language with byte spans and explicit resource limits.
//! ```
//! assert_eq!(expression_language::evaluate("2 + 3 * 4")?, 14);
//! assert_eq!(expression_language::evaluate("(2 + 3) * 4")?, 20);
//! assert!(expression_language::evaluate("8 / 0").is_err());
//! # Ok::<(), expression_language::Error>(())
//! ```
use std::fmt;
pub const MAX_SOURCE_BYTES: usize = 4096;
pub const MAX_TOKENS: usize = 512;
pub const MAX_DEPTH: usize = 64;
#[derive(Clone, Copy, Debug, PartialEq, Eq)]
pub struct Span {
    pub start: usize,
    pub end: usize,
}
#[derive(Clone, Debug, PartialEq, Eq)]
pub struct Error {
    pub span: Span,
    pub message: &'static str,
}
impl fmt::Display for Error {
    fn fmt(&self, f: &mut fmt::Formatter<'_>) -> fmt::Result {
        write!(
            f,
            "{} at bytes {}..{}",
            self.message, self.span.start, self.span.end
        )
    }
}
impl std::error::Error for Error {}
fn error(span: Span, message: &'static str) -> Error {
    Error { span, message }
}
#[derive(Clone, Copy, Debug, PartialEq, Eq)]
enum Kind {
    Number(i64),
    Plus,
    Minus,
    Star,
    Slash,
    Open,
    Close,
}
#[derive(Clone, Copy, Debug)]
struct Token {
    kind: Kind,
    span: Span,
}
fn lex(source: &str) -> Result<Vec<Token>, Error> {
    if source.len() > MAX_SOURCE_BYTES {
        return Err(error(
            Span {
                start: 0,
                end: source.len(),
            },
            "source byte limit exceeded",
        ));
    }
    let bytes = source.as_bytes();
    let mut index = 0;
    let mut tokens = Vec::new();
    while index < bytes.len() {
        if bytes[index].is_ascii_whitespace() {
            index += 1;
            continue;
        }
        let start = index;
        let kind = match bytes[index] {
            b'0'..=b'9' => {
                while index < bytes.len() && bytes[index].is_ascii_digit() {
                    index += 1;
                }
                let value = source[start..index]
                    .parse()
                    .map_err(|_| error(Span { start, end: index }, "integer literal overflow"))?;
                Kind::Number(value)
            }
            byte => {
                index += 1;
                match byte {
                    b'+' => Kind::Plus,
                    b'-' => Kind::Minus,
                    b'*' => Kind::Star,
                    b'/' => Kind::Slash,
                    b'(' => Kind::Open,
                    b')' => Kind::Close,
                    _ => {
                        return Err(error(
                            Span {
                                start,
                                end: start
                                    + source[start..]
                                        .chars()
                                        .next()
                                        .expect("start is a remaining UTF-8 character boundary")
                                        .len_utf8(),
                            },
                            "unexpected character",
                        ));
                    }
                }
            }
        };
        if tokens.len() == MAX_TOKENS {
            return Err(error(Span { start, end: index }, "token limit exceeded"));
        }
        tokens.push(Token {
            kind,
            span: Span { start, end: index },
        });
    }
    Ok(tokens)
}
#[derive(Clone, Copy, Debug, PartialEq, Eq)]
pub enum Operator {
    Add,
    Subtract,
    Multiply,
    Divide,
}
#[derive(Debug)]
enum Node {
    Number(i64),
    Negate {
        operand: Box<Expr>,
        operator_span: Span,
    },
    Binary {
        left: Box<Expr>,
        op: Operator,
        right: Box<Expr>,
        operator_span: Span,
    },
}
/// Fields are private so callers cannot bypass the parser's depth invariant.
#[derive(Debug)]
pub struct Expr {
    node: Node,
    span: Span,
    depth: usize,
}
impl Expr {
    pub fn span(&self) -> Span {
        self.span
    }
    pub fn depth(&self) -> usize {
        self.depth
    }
    pub fn evaluate(&self) -> Result<i64, Error> {
        match &self.node {
            Node::Number(value) => Ok(*value),
            Node::Negate {
                operand,
                operator_span,
            } => operand
                .evaluate()?
                .checked_neg()
                .ok_or_else(|| error(*operator_span, "arithmetic overflow")),
            Node::Binary {
                left,
                op,
                right,
                operator_span,
            } => {
                let left = left.evaluate()?;
                let right = right.evaluate()?;
                let value = match op {
                    Operator::Add => left.checked_add(right),
                    Operator::Subtract => left.checked_sub(right),
                    Operator::Multiply => left.checked_mul(right),
                    Operator::Divide => {
                        if right == 0 {
                            return Err(error(*operator_span, "division by zero"));
                        }
                        left.checked_div(right)
                    }
                };
                value.ok_or_else(|| error(*operator_span, "arithmetic overflow"))
            }
        }
    }
}
struct Parser {
    tokens: Vec<Token>,
    cursor: usize,
    source_len: usize,
}
impl Parser {
    fn peek(&self) -> Option<Token> {
        self.tokens.get(self.cursor).copied()
    }
    fn next(&mut self) -> Option<Token> {
        let token = self.peek();
        if token.is_some() {
            self.cursor += 1;
        }
        token
    }
    fn current_span(&self) -> Span {
        self.peek().map_or(
            Span {
                start: self.source_len,
                end: self.source_len,
            },
            |t| t.span,
        )
    }
    fn expression(&mut self, minimum: u8, nesting: usize) -> Result<Expr, Error> {
        if nesting >= MAX_DEPTH {
            return Err(error(self.current_span(), "nesting limit exceeded"));
        }
        let token = self
            .next()
            .ok_or_else(|| error(self.current_span(), "expected an expression"))?;
        let mut left = match token.kind {
            Kind::Number(value) => Expr {
                node: Node::Number(value),
                span: token.span,
                depth: 1,
            },
            Kind::Minus => {
                let operand = self.expression(3, nesting + 1)?;
                let depth = operand.depth + 1;
                if depth > MAX_DEPTH {
                    return Err(error(token.span, "AST depth limit exceeded"));
                }
                Expr {
                    span: Span {
                        start: token.span.start,
                        end: operand.span.end,
                    },
                    depth,
                    node: Node::Negate {
                        operand: Box::new(operand),
                        operator_span: token.span,
                    },
                }
            }
            Kind::Open => {
                let mut inner = self.expression(0, nesting + 1)?;
                let close = self
                    .next()
                    .ok_or_else(|| error(self.current_span(), "expected closing parenthesis"))?;
                if close.kind != Kind::Close {
                    return Err(error(close.span, "expected closing parenthesis"));
                }
                inner.span = Span {
                    start: token.span.start,
                    end: close.span.end,
                };
                inner
            }
            _ => {
                return Err(error(
                    token.span,
                    "expected a number, minus, or opening parenthesis",
                ));
            }
        };
        while let Some(token) = self.peek() {
            let (precedence, op) = match token.kind {
                Kind::Plus => (1, Operator::Add),
                Kind::Minus => (1, Operator::Subtract),
                Kind::Star => (2, Operator::Multiply),
                Kind::Slash => (2, Operator::Divide),
                _ => break,
            };
            if precedence < minimum {
                break;
            }
            self.next();
            let right = self.expression(precedence + 1, nesting + 1)?;
            let depth = 1 + left.depth.max(right.depth);
            if depth > MAX_DEPTH {
                return Err(error(token.span, "AST depth limit exceeded"));
            }
            left = Expr {
                span: Span {
                    start: left.span.start,
                    end: right.span.end,
                },
                depth,
                node: Node::Binary {
                    left: Box::new(left),
                    op,
                    right: Box::new(right),
                    operator_span: token.span,
                },
            };
        }
        Ok(left)
    }
}
pub fn parse(source: &str) -> Result<Expr, Error> {
    let mut parser = Parser {
        tokens: lex(source)?,
        cursor: 0,
        source_len: source.len(),
    };
    let expression = parser.expression(0, 0)?;
    if parser.peek().is_some() {
        return Err(error(parser.current_span(), "unexpected trailing token"));
    }
    Ok(expression)
}
pub fn evaluate(source: &str) -> Result<i64, Error> {
    parse(source)?.evaluate()
}

        // Form MIN by subtraction because unsigned integer tokens cannot hold 2^63.
        // These boundary checks must behave identically in debug and release builds.
        for (source, start) in [
            ("9223372036854775807 + 1", 20),
            ("(-9223372036854775807 - 1) - 1", 27),
            ("9223372036854775807 * 2", 20),
            ("-(-9223372036854775807 - 1)", 0),
            ("(-9223372036854775807 - 1) / -1", 27),
        ] {
            assert_eq!(
                evaluate(source),
                Err(Error {
                    span: Span {
                        start,
                        end: start + 1
                    },
                    message: "arithmetic overflow",
                }),
                "{source}"
            );
        }
        for (source, expected) in [
            ("9223372036854775807 + 0", i64::MAX),
            ("-9223372036854775807 - 1", i64::MIN),
            ("9223372036854775807 * 1", i64::MAX),
            ("(-9223372036854775807 - 1) / 1", i64::MIN),
            ("-(-9223372036854775807)", i64::MAX),

            assert_eq!(evaluate(source), Ok(expected), "{source}");
        }
    }
    #[test]
    fn resource_limits_are_errors() {
        assert!(parse(&"(".repeat(100)).is_err());
        assert!(parse(&"-".repeat(100)).is_err());
        assert!(parse(&vec!["1"; 100].join("+")).is_err());
        assert!(parse(&vec!["1"; 300].join("+")).is_err());
        assert!(parse(&" ".repeat(MAX_SOURCE_BYTES + 1)).is_err());
    }
    #[test]
    fn exact_byte_and_token_limits_have_distinct_diagnostics() {
        let at_bytes = format!("1{}", " ".repeat(MAX_SOURCE_BYTES - 1));
        assert_eq!(evaluate(&at_bytes), Ok(1));
        let over_bytes = format!("{at_bytes} ");
        assert_eq!(
            parse(&over_bytes).unwrap_err(),
            error(
                Span {
                    start: 0,
                    end: MAX_SOURCE_BYTES + 1
                },
                "source byte limit exceeded"
            )
        );

        // 128 leaves give 127 operators and 254 parentheses: 509 tokens.
        // Three unary minuses reach 512 without approaching either depth limit.
        let mut balanced = "1".to_owned();
        for _ in 0..7 {
            balanced = format!("({balanced}+{balanced})");
        }
        let at_tokens = format!("---{balanced}");
        assert_eq!(lex(&at_tokens).unwrap().len(), MAX_TOKENS);
        assert_eq!(evaluate(&at_tokens), Ok(-128));
        let over_tokens = format!("-{at_tokens}");
        assert_eq!(
            parse(&over_tokens).unwrap_err(),
            error(
                Span {
                    start: 512,
                    end: 513
                },
                "token limit exceeded"
            )
        );
    }
    #[test]
    fn recursive_nesting_and_constructed_tree_depth_are_separate_limits() {
        // Top-level expression is recursion level one. 63 pairs use 64 calls,
        // but parentheses do not add AST nodes: the resulting tree has depth 1.
        let at_nesting = format!("{}1{}", "(".repeat(63), ")".repeat(63));
        assert_eq!(parse(&at_nesting).unwrap().depth(), 1);
        let over_nesting = format!("({at_nesting})");
        assert_eq!(
            parse(&over_nesting).unwrap_err(),
            error(Span { start: 64, end: 65 }, "nesting limit exceeded")
        );

        // A flat left-associative chain uses shallow parser recursion while its
        // result gets one level deeper per number. It exercises the other guard.
        let at_depth = vec!["1"; MAX_DEPTH].join("+");
        let tree = parse(&at_depth).unwrap();
        assert_eq!(tree.depth(), MAX_DEPTH);
        assert_eq!(tree.evaluate(), Ok(64));
        assert_eq!(
            parse(&format!("{at_depth}+1")).unwrap_err(),
            error(
                Span {
                    start: 127,
                    end: 128
                },
                "AST depth limit exceeded"
            )
        );
    }
    #[test]
    fn deterministic_exhaustive_small_integer_properties() {
        // Finite exhaustive domain, not randomized fuzzing and not a proof for all i64.
        for a in -8_i64..=8 {
            for b in -8_i64..=8 {
                for c in -4_i64..=4 {
                    assert_eq!(evaluate(&format!("({a})+({b})*({c})")).unwrap(), a + b * c);
                    assert_eq!(
                        evaluate(&format!("(({a})+({b}))*({c})")).unwrap(),
                        (a + b) * c
                    );
                    assert_eq!(
                        evaluate(&format!("({a})+({b})")).unwrap(),
                        evaluate(&format!("({b})+({a})")).unwrap()
                    );
                    // Subtraction distinguishes left from right associativity.
                    // Parenthesizing each operand does not group the operations.
                    assert_eq!(
                        evaluate(&format!("({a})-({b})-({c})")).unwrap(),
                        (a - b) - c
                    );
                }
            }
        }
    }

The parser has already enforced AST depth and keeps Expr fields private, so evaluation receives a bounded tree from the public parse API. That is a cross-layer invariant worth documenting: evaluation relies on construction constraints. A future public constructor or deserializer could invalidate the argument unless it also checks depth. A good review traces not only each function body but also every route by which its inputs can be constructed.

Examples, properties, and independent expectations

An example test asserts one known result, such as 2 + 3 * 4 = 14. A property states a relationship over a set of inputs, such as addition commutativity. The reference loops over small finite integer domains and checks expressions against direct Rust arithmetic that is safe within those chosen bounds. This is deterministic exhaustive checking over the specified domain. It is not randomized property testing, fuzzing, or a proof over all i64 values and all source strings.

The oracle matters. If a test computes its expected result using the same parser under test, the two sides can share the same defect. Comparing a parsed expression with a straightforward host-language expression on small bounded integers provides a more independent expectation. Even that oracle has assumptions: keep values small enough that ordinary arithmetic cannot overflow, and account for the same integer division semantics. Write those assumptions near the test rather than relying on intuition.

Intentional mistake: a property outside its preconditions

A tempting property is (a / b) * b == a for every nonzero b. Integer division truncates, so it fails whenever a is not divisible by b. For a=7 and b=2, the left side is 6. A failing test can expose a false test assumption instead of an implementation bug. Refine the property to cases with exact divisibility, or assert the appropriate quotient-and-remainder relationship with carefully stated sign behavior. Never patch correct code merely to satisfy an incorrect property.

Another tempting claim is that addition associativity holds for every checked operation sequence. Mathematically it does over unbounded integers, but intermediate overflow can make one grouping fail while another succeeds. Distinguish mathematical identities from identities of a finite checked computation. Restrict the domain or compare success/error behavior under a precisely stated condition. Property tests require more specification, not less.

Playbook: a generated case fails

Observation: a proposed division property fails for 7 and 2 even though the evaluator returns the documented quotient 3. Hypothesis A: the parser groups division incorrectly. Hypothesis B: the property assumes exact division where the language truncates. Distinguishing experiment: evaluate 7 / 2 directly and compare with ordinary i64 division, then test 8 / 2 under the property. Expected results: both evaluators return 3 for the first, while the divisible case satisfies the proposed equation. This disproves a parser explanation for that reproduction and supports a missing property precondition.

Capture the minimized counterexample, the original claim, and the revised domain. Do not delete the failing case without explanation; preserve it as evidence of the semantic distinction. Ask AI to search for a counterexample to a property before generating hundreds of tests. Then verify its counterexample manually and through execution. This uses assistance to challenge assumptions rather than rubber-stamp a test suite.

Separate an evaluation result from its presentation

The evaluator remains a pure function. The executable writes its result with fallible writeln!, flushes normal output, and reports a closed sink as an ordinary failure. Error diagnostics are best effort if stderr is unavailable. The output regression forces a broken pipe before process startup; existing corpus tests continue to establish expression semantics separately. A nonzero exit is therefore not enough to diagnose invalid syntax: read the available error category and reproduce the output conditions.

When you get stuck: independent work and tiered help

Add a table of boundary expressions: maximum plus one, minimum minus one, minimum divided by -1, negated minimum, zero divisor, and a valid near-boundary result. Specify expected error category and operator span. Next extend the finite property domain with whitespace variations that preserve evaluation. Avoid generating inputs beyond the resource limits unless the property you are testing is predictable rejection. Keep arithmetic semantics and resource semantics separate in your assertions.

Engineering decisions and evidence

Requirements and invariants

The grammar specifies precedence, left associativity, unary minus, whole-input consumption, and UTF-8 byte spans. Arithmetic is checked. Source bytes, token count, parser nesting, and AST depth are bounded separately. Private Expr construction preserves the depth invariant used by recursive evaluation and destruction.

Chosen design and concrete habits

Lexing, parsing, and evaluation have distinct failure boundaries. The parser stores operator spans so runtime errors identify the responsible operation. Evaluation propagates typed errors with ? and uses checked operations for every arithmetic case. The lexer character expect documents a remaining nonempty valid-boundary invariant; no user syntax failure relies on panic. Doctests propagate errors rather than teaching routine unwrap.

Meaningful alternative and evolution threshold

An arena or explicit evaluation stack becomes useful for languages that must accept much deeper trees. A parser library can help when grammar recovery, many operators, or complex declarations become requirements. Direct i64 minimum literal support needs a magnitude design; it cannot be added honestly by changing one display rule. New constructors or deserializers must preserve resource invariants.

Actual checks and remaining uncertainty

Native precedence, associativity, Unicode spans, malformed input, arithmetic errors, limits, fixed corpus, documentation, and finite exhaustive small-integer properties passed in verification/native-tests.log and passed again in verification/patch001-foundations-tests.log after the patch audit. These properties use a bounded independent arithmetic oracle and are not randomized fuzzing or universal proofs. Independent review remains pending.

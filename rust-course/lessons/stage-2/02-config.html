Layer configuration, then validate the effective state

Build a typed configuration boundary with deterministic precedence and redacted secrets.

Read with a terminal open. Predict before revealing. Verified source versions: version ledger.

Prerequisites and learning objectives

  • Specify merge order separately from validation order
  • Represent validated values with constrained types
  • Prevent accidental secret exposure in formatting and errors

Key terms: authentication · enum · future · mise · panic · schema

Purpose: one effective configuration, one clear precedence

Applications often combine defaults, a configuration file, environment variables, and command-line overrides. Bugs arise when different parts of the program resolve precedence differently or parse the same raw text repeatedly. This project constructs one effective raw map, validates it once, and exposes a typed Config. Later code receives an IP address, a nonzero port, a Duration, a bounded connection count, and an optional Secret rather than a collection of unchecked strings.

The precedence is defaults, then file, then APP_* environment, then --set arguments. Later layers replace earlier values with the same recognized key. Structural checks occur within each layer: unknown keys and duplicates are rejected. Semantic validation occurs after merging. Therefore a higher-precedence valid port can repair a lower-precedence invalid port value. This policy is intentional; another application might validate every layer independently to catch stale mistakes, but that would yield different behavior.

Predict before running a layered case

The fixture sets port=9000. Predict the result when the environment sets APP_PORT=9001 and the command line sets port=9002. Expected: 9002. Then predict a file containing port=bad with a command-line port=9002. The reference accepts the effective value because validation occurs after resolution. Removing the command-line repair exposes the invalid final value and produces a configuration error.

Guided checkpoint: raw input becomes constrained state

Layer::parse accepts strict key=value lines, blank lines, and full-line comments beginning with #. It trims surrounding whitespace from keys and values. It does not implement inline comments or quoting. A token containing # therefore retains that character rather than silently losing a suffix. Clear grammar prevents configuration from becoming a collection of surprising heuristics. File size and individual value limits bound accepted text before it becomes stored state.

Resolve merges owned maps and validates the effective values. NonZeroU16 makes port zero unrepresentable in the resulting Config. IpAddr distinguishes actual IP addresses from arbitrary host strings; localhost is intentionally not a valid input here. Duration expresses seconds as time rather than a bare number that callers might interpret as milliseconds. The connection limit remains u16, protected by private fields and constructor validation. Types and privacy work together; not every useful constraint has a built-in standard-library type.

//! Resolve textual layers first, then validate into a typed configuration.
//! ```
//! use typed_config::{Config, Layer};
//! let file = Layer::parse("port=9000\ntimeout_seconds=20")?;
//! let override_layer = Layer::parse("port=9100")?;
//! let config = Config::resolve([file, override_layer])?;
//! assert_eq!(config.port().get(), 9100);
//! # Ok::<(), typed_config::ConfigError>(())
//! ```
use std::{collections::BTreeMap, fmt, net::IpAddr, num::NonZeroU16, time::Duration};
const KEYS: [&str; 5] = [
    "host",
    "port",
    "timeout_seconds",
    "max_connections",
    "token",
];
#[derive(Clone, Default)]
pub struct Layer {
    values: BTreeMap<String, String>,
}
#[derive(Debug, Clone, PartialEq, Eq)]
pub struct ConfigError {
    pub key: String,
    pub problem: &'static str,
}
impl fmt::Display for ConfigError {
    fn fmt(&self, f: &mut fmt::Formatter<'_>) -> fmt::Result {
        write!(f, "configuration key {}: {}", self.key, self.problem)
    }
}
impl std::error::Error for ConfigError {}
fn error(key: &str, problem: &'static str) -> ConfigError {
    ConfigError {
        key: key.into(),
        problem,
    }
}
// Debug intentionally redacts every value: even an unknown key might carry a secret.
impl fmt::Debug for Layer {
    fn fmt(&self, f: &mut fmt::Formatter<'_>) -> fmt::Result {
        f.debug_struct("Layer")
            .field("keys", &self.values.keys().collect::<Vec<_>>())
            .finish()
    }
}
impl Layer {
    /// Strict key=value lines, ASCII key names, full-line # comments only.
    /// Values are trimmed. Duplicate or unknown keys fail within a layer.
    pub fn parse(text: &str) -> Result<Self, ConfigError> {
        if text.len() > 16_384 {
            return Err(error("file", "configuration exceeds 16 KiB"));
        }
        let mut layer = Self::default();
        for line in text
            .lines()
            .map(str::trim)
            .filter(|s| !s.is_empty() && !s.starts_with('#'))
        {
            let (key, value) = line
                .split_once('=')
                .ok_or_else(|| error("file", "expected key=value"))?;
            layer.insert(key.trim(), value.trim())?;
        }
        Ok(layer)
    }
    pub fn insert(&mut self, key: &str, value: &str) -> Result<(), ConfigError> {
        if !KEYS.contains(&key) {
            return Err(error("unknown", "unknown configuration key"));
        }
        if self.values.contains_key(key) {
            return Err(error(key, "duplicate within one layer"));
        }
        if value.len() > 4096 {
            return Err(error(key, "value exceeds 4096 bytes"));
        }
        self.values.insert(key.into(), value.into());
        Ok(())
    }
    /// Accepts an injected iterator so tests never mutate process environment.
    pub fn environment<I, K, V>(pairs: I) -> Result<Self, ConfigError>
    where
        I: IntoIterator<Item = (K, V)>,
        K: AsRef<str>,
        V: AsRef<str>,
    {
        let mut layer = Self::default();
        for (name, value) in pairs {
            let key = match name.as_ref() {
                "APP_HOST" => "host",
                "APP_PORT" => "port",
                "APP_TIMEOUT_SECONDS" => "timeout_seconds",
                "APP_MAX_CONNECTIONS" => "max_connections",
                "APP_TOKEN" => "token",
                _ => continue,
            };
            layer.insert(key, value.as_ref())?;
        }
        Ok(layer)
    }
}
#[derive(Clone)]
pub struct Secret(String);
impl Secret {
    pub fn expose(&self) -> &str {
        &self.0
    }
}
impl fmt::Debug for Secret {
    fn fmt(&self, f: &mut fmt::Formatter<'_>) -> fmt::Result {
        f.write_str("[REDACTED]")
    }
}
#[derive(Clone, Debug)]
pub struct Config {
    host: IpAddr,
    port: NonZeroU16,
    timeout: Duration,
    max_connections: u16,
    token: Option<Secret>,
}
impl Config {
    pub fn host(&self) -> IpAddr {
        self.host
    }
    pub fn port(&self) -> NonZeroU16 {
        self.port
    }
    pub fn timeout(&self) -> Duration {
        self.timeout
    }
    pub fn max_connections(&self) -> u16 {
        self.max_connections
    }
    pub fn token(&self) -> Option<&Secret> {
        self.token.as_ref()
    }
    /// Later layers win. Only final effective values undergo semantic validation.
    pub fn resolve(layers: impl IntoIterator<Item = Layer>) -> Result<Self, ConfigError> {
        let mut raw: BTreeMap<String, String> = [
            ("host", "127.0.0.1"),
            ("port", "8080"),
            ("timeout_seconds", "30"),
            ("max_connections", "100"),
        ]
        .into_iter()
        .map(|(k, v)| (k.into(), v.into()))
        .collect();
        for layer in layers {
            raw.extend(layer.values);
        }
        let host = raw["host"]
            .parse::<IpAddr>()
            .map_err(|_| error("host", "expected an IPv4 or IPv6 address"))?;
        let port = raw["port"]
            .parse::<NonZeroU16>()
            .map_err(|_| error("port", "expected an integer in 1..=65535"))?;
        let seconds = raw["timeout_seconds"]
            .parse::<u64>()
            .map_err(|_| error("timeout_seconds", "expected an integer in 1..=300"))?;
        if !(1..=300).contains(&seconds) {
            return Err(error("timeout_seconds", "expected an integer in 1..=300"));
        }
        let max_connections = raw["max_connections"]
            .parse::<u16>()
            .map_err(|_| error("max_connections", "expected an integer in 1..=10000"))?;
        if !(1..=10_000).contains(&max_connections) {
            return Err(error("max_connections", "expected an integer in 1..=10000"));
        }
        let token = match raw.remove("token") {
            None => None,
            Some(token) => {
                if token.len() < 12
                    || token.chars().any(char::is_whitespace)
                    || token.chars().any(char::is_control)
                {
                    return Err(error(
                        "token",
                        "expected at least 12 bytes with no whitespace or controls",
                    ));
                }
                Some(Secret(token))
            }
        };
        Ok(Self {
            host,
            port,
            timeout: Duration::from_secs(seconds),
            max_connections,
            token,
        })
    }
}
#[cfg(test)]
mod tests {
    use super::*;
    #[test]
    fn later_layers_win_before_validation() {
        let file = Layer::parse("port=not-yet-valid\ntimeout_seconds=10").unwrap();
        let env = Layer::environment([("APP_PORT", "9001"), ("UNRELATED", "ignored")]).unwrap();
        let cli = Layer::parse("port=9002").unwrap();
        let c = Config::resolve([file, env, cli]).unwrap();
        assert_eq!(c.port().get(), 9002);
        assert_eq!(c.timeout(), Duration::from_secs(10));
    }
    #[test]
    fn errors_and_debug_do_not_include_secret_values() {
        let marker = "super-secret-token";
        let layer = Layer::parse(&format!("token={marker}")).unwrap();
        assert!(!format!("{layer:?}").contains(marker));
        let c = Config::resolve([layer]).unwrap();
        assert!(!format!("{c:?}").contains(marker));
        assert_eq!(c.token().unwrap().expose(), marker);
        let invalid = Layer::parse("token=bad secret").unwrap();
        let e = Config::resolve([invalid]).unwrap_err();
        assert!(!e.to_string().contains("bad secret"));
        assert!(Layer::parse("token=x\ntoken=y").is_err());
        assert!(Layer::parse("typo=x").is_err());
    }
    #[test]
    fn boundaries() {
        for port in ["0", "65536", "-1", "abc"] {
            assert!(Config::resolve([Layer::parse(&format!("port={port}")).unwrap()]).is_err());
        }
        for seconds in [1, 300] {
            assert!(
                Config::resolve([Layer::parse(&format!("timeout_seconds={seconds}")).unwrap()])
                    .is_ok()
            );
        }
        for seconds in [0, 301] {
            assert!(
                Config::resolve([Layer::parse(&format!("timeout_seconds={seconds}")).unwrap()])
                    .is_err()
            );
        }
    }
}

A missing token becomes None. An explicitly present empty token is invalid, not equivalent to missing. That distinction matters when an override accidentally erases a required value. The current reference makes tokens optional; do not infer authentication policy from the existence of a token field. It is a configuration teaching model, not a complete security system.

Redaction is observable behavior

Secret wraps a String and implements Debug with a fixed redaction marker. Config can then derive Debug without printing the token's contents. Layer's Debug prints keys only, because raw layers may contain invalid or unclassified sensitive values. ConfigError identifies a key and a problem without echoing the input value. These choices reduce accidental disclosure through routine debugging and error presentation.

The wrapper does not encrypt memory, zeroize allocations, or prevent a caller from deliberately invoking expose and printing the returned text. Its purpose is to make ordinary formatting safe by default and intentional access visible in code review. Do not claim more. The tests search output for a synthetic marker and verify redaction in both library formatting and a launched CLI process. They are behavioral evidence for those paths, not a guarantee about every future log statement.

Intentional mistake and playbook investigation

Introduce a learner bug by reversing the layer iteration order. Observation: the file value wins over a command-line override. Hypothesis A: the CLI parser failed to capture --set. Hypothesis B: the merge applies high-precedence values too early and then overwrites them. Distinguishing experiment: call Config::resolve directly with two layers setting different ports, then reverse just their order. Expected reference behavior: the second layer wins in each case. If the learner result follows the first layer instead, the CLI hypothesis is disproven for the direct reproduction.

The smallest fix belongs in merge ordering, followed by regression tests that preserve unrelated keys from lower layers. Do not “fix” it by special-casing port after validation; that creates a second precedence system. Record the input order, effective result, and expected result. Ask AI to propose a counterexample to the corrected merge, especially a layer that overrides one key while leaving another untouched. Evaluate the counterexample before accepting any generalized claim.

Redacted output can still fail

The CLI writes the already-redacted Debug representation through fallible writeln! and flush. A closed output pipe returns failure, and a second failure on stderr is handled as a best-effort diagnostic rather than a panic. These output checks preserve secret redaction; they do not make a terminal a confidential destination. The child-process regression closes the only pipe reader before execution to force the relevant I/O failure deterministically.

Recommended design and alternatives

The recommended design resolves precedence once and validates once, so application code receives stable typed values. A concrete map and constructor are appropriate for five keys and four sources. A configuration library can help when nested schemas, multiple file syntaxes, or source-location diagnostics become requirements. Your precedence, accepted values, and redaction policy remain explicit requirements even when syntax parsing moves into a dependency.

Mastery means predicting the effective configuration for three layers without running the program, explaining why zero cannot appear in a constructed port, and demonstrating that a token marker does not appear in tested output paths. State the limits: environment bytes that are not Unicode are skipped by this simple CLI adapter, and the secret wrapper does not provide memory erasure. A complete design note names such boundaries so a future production adaptation can decide which ones must change.

Engineering decisions and evidence

Requirements and invariants

Resolve defaults < file < environment < command line, reject unknown or duplicate keys within one layer, then validate effective values. Constructed ports are nonzero, timeouts and connection counts are bounded, hosts are IP addresses, and ordinary formatting/errors do not expose tokens. An explicitly empty token differs from an absent token.

Chosen design and concrete habits

Raw Layer and validated Config are separate types. Layer::environment takes injected pairs for parallel-safe tests instead of mutating process environment. Private fields and NonZeroU16 protect accepted state. Secret implements redacted Debug; errors identify keys and rules without echoing input. Normal parsing and IO failures use Result from the first recommended checkpoint, including documentation examples.

Meaningful alternative and evolution threshold

Validating each raw layer before merge is defensible when stale invalid configuration must be rejected even if overridden; it is a different policy and needs different tests. A schema library becomes useful for nested structures and source-location diagnostics. Required credentials, zeroization, or a real secret provider require explicit new guarantees; this redaction wrapper does not encrypt or erase memory.

Actual checks and remaining uncertainty

Native precedence, boundary, redaction, controlled-child-environment CLI, and documentation tests passed in verification/native-tests.log and passed again in verification/patch001-foundations-tests.log after the patch audit. Tested output paths omit synthetic token markers. The CLI skips non-Unicode environment pairs, and future hand-written logging can still expose values deliberately.

Traits as required capabilities, not decoration

Use generic readers and formatters to separate behavior from concrete storage and presentation choices.

Read with a terminal open. Predict before revealing. Verified source versions: version ledger.

Prerequisites and learning objectives
  • Stream logs with bounded lines and honest accounting
  • Read a trait bound as an explicit capability requirement
  • Choose static dispatch when one generic implementation suffices
  • Test behavior through injected inputs instead of global state

Key terms: borrow · edition · generic · iterator · mise · move · slice · trait

Purpose: reuse the algorithm without hiding its needs

The log analyzer accepts any type implementing BufRead. A file-backed BufReader, locked standard input, and a byte slice can all supply buffered bytes. The algorithm does not need to know which one it received; it needs the capability to inspect buffered data and consume it. A trait names that capability. A generic bound tells the compiler and the reader which operations a function is permitted to use on an otherwise unspecified type.

This is a better starting model than “traits are interfaces” alone. The important question is what behavior the function requires and who supplies it. analyze<R: BufRead> states a concrete requirement. It is not a promise that every possible input source is nonblocking, trustworthy, or equally fast. A capability boundary should be narrow enough to support reuse but honest about the remaining behavioral assumptions.

Prediction: same data, different source

Predict whether analyze receives the same report from a byte slice and from a BufReader around Cursor when both contain identical bytes. Expected: yes. Neither source changes the record grammar. The tiny-buffer tests already exercise this idea. They demonstrate how a generic API creates useful test seams: you can change the source implementation without changing the parser or introducing files solely for a unit test.

mise exec -- cargo test -p log-detective accounting_property_across_buffer_sizes
mise exec -- cargo test -p typed-config later_layers_win_before_validation

In the configuration project, Layer::environment accepts an iterator of name/value pairs. Tests pass a small array, while main supplies actual process environment pairs. This is dependency injection in plain Rust: make input explicit in a parameter. It avoids mutating global process environment during tests, which would complicate parallel execution and introduce cross-test interference. You do not need a container framework to get the important benefit.

Guided checkpoint: read the bounds literally

Read the environment signature. IntoIterator means the supplied value can produce an iterator. The item is a pair. Each name and value supports AsRef<str>, so the function can borrow text without insisting on one concrete owned-string type. Follow one iteration and identify when a borrowed name is matched and when a recognized value is copied into the layer's owned map. The bounds support the operations the body actually performs.

projects/reference/p04-config/src/lib.rs
//! Resolve textual layers first, then validate into a typed configuration.
//! ```
//! use typed_config::{Config, Layer};
//! let file = Layer::parse("port=9000\ntimeout_seconds=20")?;
//! let override_layer = Layer::parse("port=9100")?;
//! let config = Config::resolve([file, override_layer])?;
//! assert_eq!(config.port().get(), 9100);
//! # Ok::<(), typed_config::ConfigError>(())
//! ```
use std::{collections::BTreeMap, fmt, net::IpAddr, num::NonZeroU16, time::Duration};
const KEYS: [&str; 5] = [
    "host",
    "port",
    "timeout_seconds",
    "max_connections",
    "token",
];
#[derive(Clone, Default)]
pub struct Layer {
    values: BTreeMap<String, String>,
}
#[derive(Debug, Clone, PartialEq, Eq)]
pub struct ConfigError {
    pub key: String,
    pub problem: &'static str,
}
impl fmt::Display for ConfigError {
    fn fmt(&self, f: &mut fmt::Formatter<'_>) -> fmt::Result {
        write!(f, "configuration key {}: {}", self.key, self.problem)
    }
}
impl std::error::Error for ConfigError {}
fn error(key: &str, problem: &'static str) -> ConfigError {
    ConfigError {
        key: key.into(),
        problem,
    }
}
// Debug intentionally redacts every value: even an unknown key might carry a secret.
impl fmt::Debug for Layer {
    fn fmt(&self, f: &mut fmt::Formatter<'_>) -> fmt::Result {
        f.debug_struct("Layer")
            .field("keys", &self.values.keys().collect::<Vec<_>>())
            .finish()
    }
}
impl Layer {
    /// Strict key=value lines, ASCII key names, full-line # comments only.
    /// Values are trimmed. Duplicate or unknown keys fail within a layer.
    pub fn parse(text: &str) -> Result<Self, ConfigError> {
        if text.len() > 16_384 {
            return Err(error("file", "configuration exceeds 16 KiB"));
        }
        let mut layer = Self::default();
        for line in text
            .lines()
            .map(str::trim)
            .filter(|s| !s.is_empty() && !s.starts_with('#'))
        {
            let (key, value) = line
                .split_once('=')
                .ok_or_else(|| error("file", "expected key=value"))?;
            layer.insert(key.trim(), value.trim())?;
        }
        Ok(layer)
    }
    pub fn insert(&mut self, key: &str, value: &str) -> Result<(), ConfigError> {
        if !KEYS.contains(&key) {
            return Err(error("unknown", "unknown configuration key"));
        }
        if self.values.contains_key(key) {
            return Err(error(key, "duplicate within one layer"));
        }
        if value.len() > 4096 {
            return Err(error(key, "value exceeds 4096 bytes"));
        }
        self.values.insert(key.into(), value.into());
        Ok(())
    }
    /// Accepts an injected iterator so tests never mutate process environment.
    pub fn environment<I, K, V>(pairs: I) -> Result<Self, ConfigError>
    where
        I: IntoIterator<Item = (K, V)>,
        K: AsRef<str>,
        V: AsRef<str>,
    {
        let mut layer = Self::default();
        for (name, value) in pairs {
            let key = match name.as_ref() {
                "APP_HOST" => "host",
                "APP_PORT" => "port",
                "APP_TIMEOUT_SECONDS" => "timeout_seconds",
                "APP_MAX_CONNECTIONS" => "max_connections",
                "APP_TOKEN" => "token",
                _ => continue,
            };
            layer.insert(key, value.as_ref())?;
        }
        Ok(layer)
    }
}
#[derive(Clone)]
pub struct Secret(String);
impl Secret {
    pub fn expose(&self) -> &str {
        &self.0
    }
}
impl fmt::Debug for Secret {
    fn fmt(&self, f: &mut fmt::Formatter<'_>) -> fmt::Result {
        f.write_str("[REDACTED]")
    }
}
#[derive(Clone, Debug)]
pub struct Config {
    host: IpAddr,
    port: NonZeroU16,
    timeout: Duration,
    max_connections: u16,
    token: Option<Secret>,
}
impl Config {
    pub fn host(&self) -> IpAddr {
        self.host
    }
    pub fn port(&self) -> NonZeroU16 {
        self.port
    }
    pub fn timeout(&self) -> Duration {
        self.timeout
    }
    pub fn max_connections(&self) -> u16 {
        self.max_connections
    }
    pub fn token(&self) -> Option<&Secret> {
        self.token.as_ref()
    }
    /// Later layers win. Only final effective values undergo semantic validation.
    pub fn resolve(layers: impl IntoIterator<Item = Layer>) -> Result<Self, ConfigError> {
        let mut raw: BTreeMap<String, String> = [
            ("host", "127.0.0.1"),
            ("port", "8080"),
            ("timeout_seconds", "30"),
            ("max_connections", "100"),
        ]
        .into_iter()
        .map(|(k, v)| (k.into(), v.into()))
        .collect();
        for layer in layers {
            raw.extend(layer.values);
        }
        let host = raw["host"]
            .parse::<IpAddr>()
            .map_err(|_| error("host", "expected an IPv4 or IPv6 address"))?;
        let port = raw["port"]
            .parse::<NonZeroU16>()
            .map_err(|_| error("port", "expected an integer in 1..=65535"))?;
        let seconds = raw["timeout_seconds"]
            .parse::<u64>()
            .map_err(|_| error("timeout_seconds", "expected an integer in 1..=300"))?;
        if !(1..=300).contains(&seconds) {
            return Err(error("timeout_seconds", "expected an integer in 1..=300"));
        }
        let max_connections = raw["max_connections"]
            .parse::<u16>()
            .map_err(|_| error("max_connections", "expected an integer in 1..=10000"))?;
        if !(1..=10_000).contains(&max_connections) {
            return Err(error("max_connections", "expected an integer in 1..=10000"));
        }
        let token = match raw.remove("token") {
            None => None,
            Some(token) => {
                if token.len() < 12
                    || token.chars().any(char::is_whitespace)
                    || token.chars().any(char::is_control)
                {
                    return Err(error(
                        "token",
                        "expected at least 12 bytes with no whitespace or controls",
                    ));
                }
                Some(Secret(token))
            }
        };
        Ok(Self {
            host,
            port,
            timeout: Duration::from_secs(seconds),
            max_connections,
            token,
        })
    }
}
#[cfg(test)]
mod tests {
    use super::*;
    #[test]
    fn later_layers_win_before_validation() {
        let file = Layer::parse("port=not-yet-valid\ntimeout_seconds=10").unwrap();
        let env = Layer::environment([("APP_PORT", "9001"), ("UNRELATED", "ignored")]).unwrap();
        let cli = Layer::parse("port=9002").unwrap();
        let c = Config::resolve([file, env, cli]).unwrap();
        assert_eq!(c.port().get(), 9002);
        assert_eq!(c.timeout(), Duration::from_secs(10));
    }
    #[test]
    fn errors_and_debug_do_not_include_secret_values() {
        let marker = "super-secret-token";
        let layer = Layer::parse(&format!("token={marker}")).unwrap();
        assert!(!format!("{layer:?}").contains(marker));
        let c = Config::resolve([layer]).unwrap();
        assert!(!format!("{c:?}").contains(marker));
        assert_eq!(c.token().unwrap().expose(), marker);
        let invalid = Layer::parse("token=bad secret").unwrap();
        let e = Config::resolve([invalid]).unwrap_err();
        assert!(!e.to_string().contains("bad secret"));
        assert!(Layer::parse("token=x\ntoken=y").is_err());
        assert!(Layer::parse("typo=x").is_err());
    }
    #[test]
    fn boundaries() {
        for port in ["0", "65536", "-1", "abc"] {
            assert!(Config::resolve([Layer::parse(&format!("port={port}")).unwrap()]).is_err());
        }
        for seconds in [1, 300] {
            assert!(
                Config::resolve([Layer::parse(&format!("timeout_seconds={seconds}")).unwrap()])
                    .is_ok()
            );
        }
        for seconds in [0, 301] {
            assert!(
                Config::resolve([Layer::parse(&format!("timeout_seconds={seconds}")).unwrap()])
                    .is_err()
            );
        }
    }
}

Now read Display for CalcError or ConfigError. Display describes user-facing formatting; Debug is intended for developer-oriented inspection. Deriving Debug is convenient only when every displayed field is safe and appropriate to expose. Secret deliberately implements Debug to print a redaction marker. Choosing a trait implementation is part of observable program behavior, not a cosmetic annotation. A diagnostic path can leak sensitive text just as a normal output path can.

Intentional compiler mistake

The supplied 05-missing-trait.rs fixture defines fn render<T>(value: T) and tries to print it with {}. Predict the error before compiling: the body requires Display, but the signature promises no such capability. Adding T: std::fmt::Display is a sound repair because it states the real requirement. Replacing formatting with an unrelated conversion may only move the problem. Generic code must be valid for every type satisfying its declared bounds, not merely the type used by one call site today.

mise exec -- rustc --edition=2024 --emit=metadata --out-dir /tmp/rust-course-diagnostics 05-missing-trait.rs

Run that command from rust-course/exercises/foundations, where the fixture resides. Expected result is a nonzero exit including E0277. The command is intentionally outside the Cargo reference workspace. After you write a corrected scratch copy, compile it and explain why callers with non-Display types are now rejected at the boundary. The added bound narrows valid callers in exchange for a well-defined operation.

Static dispatch and deliberate restraint

A generic function is compiled for concrete types as needed. A trait object such as &mut dyn BufRead instead supports dynamic dispatch through a runtime interface. Both are useful; neither is automatically more idiomatic. This project uses a generic function because each call already has one concrete reader type and the implementation is straightforward. Introduce a trait object when you need heterogeneous values behind one runtime type, not merely because the word “abstraction” sounds desirable.

Do not create a custom trait with one method for every helper function. Traits pay for themselves when they describe a coherent capability, enable distinct implementations, or express a real generic relationship. Ordinary functions and structs are often clearer. In the config project, Layer is a concrete collection of text; making every layer source implement a custom repository trait would add ceremony without improving the current two test scenarios.

Playbook: a test passes alone and fails with others

Observation: configuration tests sometimes see another test's environment override. Hypothesis A: map iteration order changes precedence. Hypothesis B: tests share mutable process environment. A distinguishing experiment passes an explicit fixed array to Layer::environment and removes environment mutation from the test. Expected result: deterministic values regardless of neighboring tests. That disproves map order as the cause of this reproduction when the same merge order is retained and supports the shared-input explanation.

Keep the precedence logic unchanged during that experiment. If you reorder layers at the same time, you lose the ability to distinguish causes. Record the original global dependency and the new explicit input boundary. Ask AI to explain which dependency became injectable and which effects still occur in main. A sound explanation should not claim that a pure test proves operating-system environment encoding behavior.

When you get stuck: independent work and tiered help

Write a report function accepting impl std::io::Write and serialize the log counters into it. Test with a Vec<u8>, then call it with standard output. Add a controlled writer that returns an IO error after a chosen byte count and ensure the error is preserved. This connects a trait requirement to a concrete failure mode. Do not call flush automatically without deciding whether your function owns completion of the output stream.

Hint 1: choose the next observation

list the methods your function body calls on its parameter.

Hint 2: narrow the experiment

find the trait that provides those methods and use only that bound.

Worked solution

fn write_report(mut output: impl Write, report: &Report) -> io::Result<()> can use writeln! and return its Result; a Vec<u8> then serves as an in-memory sink. Ask for a review of the smallest sufficient bound and error contract. More bounds do not necessarily mean a better abstraction.

Review and mastery evidence

The recommended functions accept explicit input through standard capabilities and keep process environment or filesystem access in main. This supplies useful test seams with a small API. Concrete parameters remain a valid choice when a function has exactly one meaningful representation; a trait object becomes useful when runtime heterogeneity is required. Choose the least complex interface that expresses the real capability and preserves errors.

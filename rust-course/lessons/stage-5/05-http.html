HTTP contracts and authorization boundaries

Turn requests into validated domain operations and safe responses.

Read with a terminal open. Predict before revealing. Verified source versions: version ledger.

Purpose: an interface another program can trust

The issue tracker lets a client create, list, and close team issues. An HTTP API is a contract between programs, not merely a set of function names. The contract includes method, path, headers, body schema, status, error shape, and permission rules. A client must be able to distinguish invalid input, missing identity, forbidden action, stale revision, and temporarily unavailable storage without inspecting a Rust stack trace.

Plain-English model

HTTP adds request and response semantics over a transport. A request contains a method such as GET or POST, a target path, headers, and sometimes a body. JSON is a text serialization format that represents values; it does not by itself validate business meaning. A JSON number may be syntactically valid while being an impossible page size. TLS encrypts and authenticates the transport endpoint when configured correctly. Our localhost lab uses plain HTTP and public teaching identities, so it is not a deployed identity system.

Authentication establishes who a caller is. Authorization decides what that caller may do to this resource. The demo fixtures map three explicit bearer strings to two teams and reader/writer roles. They exist to test authorization branches deterministically. They are not passwords, not cryptographic tokens, and not a recommended login design. For a deployment, use a maintained identity integration with an established protocol such as OpenID Connect, validate its issuer and audience, and preserve the same resource checks. Do not replace this lab with a homemade signature or password scheme.

Predict the boundary

A team-one writer knows a team-two issue ID. Should possession of that ID allow closing it? Should hiding the close button in the UI be sufficient? Predict what the API should return.

Answer

The server must constrain the operation to the authenticated actor's team. This API returns not-found for an inaccessible issue, avoiding confirmation of another team's resource. UI controls improve usability but are not a security boundary. Reader permissions also need server enforcement even when the client sends a valid writer-shaped JSON body.

Read the handler shape

Axum's State extractor supplies shared application resources, HeaderMap supplies request headers, Path parses route values, and Json deserializes the body. Body-consuming extractors belong last in the handler arguments. The handler validates identity and title, awaits a parameterized database operation, then returns a typed status plus JSON. IntoResponse centralizes application error rendering. The public response says storage is unavailable; internal query details stay in the local service log.

The 4,096-byte body limit bounds deserialization input. The title rule independently limits meaningful title characters. Those are different constraints. Axum's built-in JSON rejection responses are framework responses; this reference does not claim one uniform custom error schema for every malformed transport request. A production API may wrap extractor rejections into its chosen problem format.

projects/reference/p10-issues/src/lib.rs
//! Local teaching API. Demo credentials are fixtures, NOT production authentication.
use axum::{
    Json, Router,
    extract::{DefaultBodyLimit, Path, Query, Request, State},
    http::{HeaderMap, StatusCode},
    middleware::{self, Next},
    response::{IntoResponse, Response},
    routing::{get, post},
};
use serde::{Deserialize, Serialize};
use sqlx::{PgPool, Row};
#[derive(Clone)]
pub struct App {
    pub pool: PgPool,
}
#[derive(Debug)]
pub struct ApiError(pub StatusCode, pub &'static str);
impl IntoResponse for ApiError {
    fn into_response(self) -> Response {
        (self.0, Json(serde_json::json!({"error":self.1}))).into_response()
    }
}
fn database(error: sqlx::Error) -> ApiError {
    eprintln!("database operation failed: {error}");
    ApiError(StatusCode::SERVICE_UNAVAILABLE, "storage unavailable")
}
#[derive(Clone, Copy)]
pub struct Actor {
    pub id: i64,
    pub team: i64,
    pub write: bool,
}
pub fn actor(headers: &HeaderMap, write: bool) -> Result<Actor, ApiError> {
    let token = headers.get("authorization").and_then(|h| h.to_str().ok());
    let actor = match token {
        Some("Bearer demo-team1-writer") => Actor {
            id: 1,
            team: 1,
            write: true,
        },
        Some("Bearer demo-team1-reader") => Actor {
            id: 2,
            team: 1,
            write: false,
        },
        Some("Bearer demo-team2-writer") => Actor {
            id: 3,
            team: 2,
            write: true,
        },
        _ => return Err(ApiError(StatusCode::UNAUTHORIZED, "demo identity required")),
    };
    if write && !actor.write {
        return Err(ApiError(StatusCode::FORBIDDEN, "write permission required"));
    }
    Ok(actor)
}
#[derive(Debug, Serialize, sqlx::FromRow)]
pub struct Issue {
    pub id: i64,
    pub team_id: i64,
    pub title: String,
    pub closed: bool,
    pub revision: i64,
}
#[derive(Deserialize)]
pub struct NewIssue {
    pub title: String,
}
#[derive(Deserialize)]
pub struct Page {
    pub after: Option<i64>,
    pub limit: Option<i64>,
}
#[derive(Deserialize)]
pub struct Close {
    pub expected_revision: i64,
}
pub fn validate_title(title: &str) -> Result<&str, ApiError> {
    let title = title.trim();
    if title.is_empty() || title.chars().count() > 200 {
        return Err(ApiError(
            StatusCode::UNPROCESSABLE_ENTITY,
            "title must contain 1..200 characters",
        ));
    }
    Ok(title)
}
async fn admission(
    State(permits): State<std::sync::Arc<tokio::sync::Semaphore>>,
    request: Request,
    next: Next,
) -> Response {
    let Ok(_permit) = permits.try_acquire_owned() else {
        return ApiError(StatusCode::TOO_MANY_REQUESTS, "request budget full").into_response();
    };
    match tokio::time::timeout(std::time::Duration::from_secs(5), next.run(request)).await {
        Ok(response) => response,
        Err(_) => ApiError(
            StatusCode::REQUEST_TIMEOUT,
            "deadline exceeded; reconcile operation outcome",
        )
        .into_response(),
    }
}
pub fn router(pool: PgPool) -> Router {
    Router::new()
        .route("/health", get(|| async { "ok" }))
        .route("/issues", get(list).post(create))
        .route("/issues/{id}/close", post(close))
        .layer(DefaultBodyLimit::max(4096))
        .layer(middleware::from_fn_with_state(
            std::sync::Arc::new(tokio::sync::Semaphore::new(16)),
            admission,
        ))
        .with_state(App { pool })
}
async fn list(
    State(app): State<App>,
    headers: HeaderMap,
    Query(page): Query<Page>,
) -> Result<Json<Vec<Issue>>, ApiError> {
    let who = actor(&headers, false)?;
    let limit = page.limit.unwrap_or(20);
    if !(1..=100).contains(&limit) || page.after.unwrap_or(0) < 0 {
        return Err(ApiError(StatusCode::BAD_REQUEST, "invalid page"));
    }
    let rows=sqlx::query_as::<_,Issue>("SELECT id,team_id,title,closed,revision FROM issues WHERE team_id=$1 AND id>$2 ORDER BY id LIMIT $3").bind(who.team).bind(page.after.unwrap_or(0)).bind(limit).fetch_all(&app.pool).await.map_err(database)?;
    Ok(Json(rows))
}
async fn create(
    State(app): State<App>,
    headers: HeaderMap,
    Json(input): Json<NewIssue>,
) -> Result<(StatusCode, Json<Issue>), ApiError> {
    let who = actor(&headers, true)?;
    let title = validate_title(&input.title)?;
    let issue=sqlx::query_as::<_,Issue>("INSERT INTO issues(team_id,title) VALUES($1,$2) RETURNING id,team_id,title,closed,revision").bind(who.team).bind(title).fetch_one(&app.pool).await.map_err(database)?;
    Ok((StatusCode::CREATED, Json(issue)))
}
async fn close(
    State(app): State<App>,
    headers: HeaderMap,
    Path(id): Path<i64>,
    Json(input): Json<Close>,
) -> Result<Json<Issue>, ApiError> {
    let who = actor(&headers, true)?;
    close_issue(&app.pool, who, id, input.expected_revision)
        .await
        .map(Json)
}
/// Update and audit are one transaction. Team predicate prevents cross-team access.
pub async fn close_issue(
    pool: &PgPool,
    who: Actor,
    id: i64,
    revision: i64,
) -> Result<Issue, ApiError> {
    if !who.write {
        return Err(ApiError(StatusCode::FORBIDDEN, "write permission required"));
    }
    let mut tx = pool.begin().await.map_err(database)?;
    let row =
        sqlx::query("SELECT revision,closed FROM issues WHERE id=$1 AND team_id=$2 FOR UPDATE")
            .bind(id)
            .bind(who.team)
            .fetch_optional(&mut *tx)
            .await
            .map_err(database)?
            .ok_or(ApiError(StatusCode::NOT_FOUND, "issue not found"))?;
    if row.get::<i64, _>("revision") != revision || row.get::<bool, _>("closed") {
        return Err(ApiError(StatusCode::CONFLICT, "revision conflict"));
    }
    let issue=sqlx::query_as::<_,Issue>("UPDATE issues SET closed=true,revision=revision+1 WHERE id=$1 RETURNING id,team_id,title,closed,revision").bind(id).fetch_one(&mut *tx).await.map_err(database)?;
    sqlx::query("INSERT INTO issue_audit(issue_id,revision,actor,action) VALUES($1,$2,$3,'close')")
        .bind(id)
        .bind(issue.revision)
        .bind(who.id)
        .execute(&mut *tx)
        .await
        .map_err(database)?;
    tx.commit().await.map_err(database)?;
    Ok(issue)
}
#[cfg(feature = "verified-query")]
pub async fn verified_count(pool: &PgPool) -> Result<i64, sqlx::Error> {
    let row = sqlx::query!("SELECT count(*) as \"count!\" FROM issues")
        .fetch_one(pool)
        .await?;
    Ok(row.count)
}

Deliberate mistake and practice

Intentionally remove the team predicate from the close lookup in your working copy. It still compiles. The cross-team integration test must now fail. Restore it before continuing. Next design a “reopen” operation: specify permissions, legal state transition, expected revision behavior, and whether retrying the same request is success or conflict. Decide those semantics before implementing the route.

Hint 1

Start with a table of actor role, owning team, current state, and expected revision.

Hint 2

A state transition is different from assigning a boolean. Decide whether reopening an already open issue is meaningful.

Reference approach

Keep a resource-scoped lookup and optimistic revision check inside the transaction. Give reopen its own operation with writer permission. Reject stale revisions consistently, update the audit row with the new revision, and test cross-team access independently from state conflicts. An idempotent command ID is an alternative contract, but requires persisted command results.

Review and evidence

A deliberate authorization defect is accepting team_id in the JSON body as authority. A clearer boundary derives team membership from server-side identity and ignores client claims of authority. Validation tests prove selected inputs are handled. The PostgreSQL route test proves actual reader and cross-team denials through the router. Neither proves a secure login flow because no such flow exists in the reference. Explain why TLS, authentication, authorization, CSRF protection for cookie-based clients, and input validation solve different problems.

Playbook investigation

Observation: a valid writer sees 404 for one issue while another writer can close it. A tempting guess is “the migration lost the row.” Query only the dedicated test database to confirm the row exists, then inspect its team and the fixture identity. Reproduce with both identities through HTTP. A row existing globally does not imply it belongs in this caller's visible set. The correct fix may be using the intended identity, not deleting authorization. Record that disproven hypothesis and retain a regression test for the boundary.

Complete earlier milestone source

The complete validation router stores no issues. Trace admission, JSON extraction, actor mapping, title validation, and the normalized response. The bounded service can be tested without a database.

projects/checkpoints/p10-issues/01-http-validation/src/lib.rs
//! Pure HTTP boundary checkpoint. No issue is stored; /issues/validate only validates.
//! Credentials are public local test fixtures, not deployable authentication.
use axum::{
    Json, Router,
    extract::{DefaultBodyLimit, Request, State},
    http::{HeaderMap, StatusCode},
    middleware::{self, Next},
    response::{IntoResponse, Response},
    routing::post,
};
use serde::{Deserialize, Serialize};
use std::sync::Arc;
#[derive(Deserialize)]
struct Input {
    title: String,
}
#[derive(Serialize)]
struct Validated {
    title: String,
}
async fn validate(
    headers: HeaderMap,
    Json(input): Json<Input>,
) -> Result<Json<Validated>, StatusCode> {
    match headers.get("authorization").and_then(|v| v.to_str().ok()) {
        Some("Bearer demo-team1-writer") => {}
        Some("Bearer demo-team1-reader") => return Err(StatusCode::FORBIDDEN),
        _ => return Err(StatusCode::UNAUTHORIZED),
    }
    let title = input.title.trim();
    if title.is_empty() || title.chars().count() > 200 {
        return Err(StatusCode::UNPROCESSABLE_ENTITY);
    }
    Ok(Json(Validated {
        title: title.to_owned(),
    }))
}
async fn admit(
    State(slots): State<Arc<tokio::sync::Semaphore>>,
    request: Request,
    next: Next,
) -> Response {
    let Ok(_permit) = slots.try_acquire_owned() else {
        return StatusCode::TOO_MANY_REQUESTS.into_response();
    };
    match tokio::time::timeout(std::time::Duration::from_secs(1), next.run(request)).await {
        Ok(response) => response,
        Err(_) => StatusCode::REQUEST_TIMEOUT.into_response(),
    }
}
pub fn router() -> Router {
    Router::new()
        .route("/issues/validate", post(validate))
        .layer(DefaultBodyLimit::max(4096))
        .layer(middleware::from_fn_with_state(
            Arc::new(tokio::sync::Semaphore::new(4)),
            admit,
        ))
}
#[cfg(test)]
mod tests {
    use super::*;
    use axum::{
        body::{Body, to_bytes},
        http::Request,
    };
    use tower::ServiceExt;
    async fn request(identity: &str, body: String) -> Response {
        router()
            .oneshot(
                Request::builder()
                    .method("POST")
                    .uri("/issues/validate")
                    .header("authorization", identity)
                    .header("content-type", "application/json")
                    .body(Body::from(body))
                    .unwrap(),
            )
            .await
            .unwrap()
    }
    #[tokio::test]
    async fn writer_normalizes_without_persistence() {
        let response = request("Bearer demo-team1-writer", r#"{"title":" fix "}"#.into()).await;
        assert_eq!(response.status(), StatusCode::OK);
        assert_eq!(
            to_bytes(response.into_body(), 4096).await.unwrap().as_ref(),
            br#"{"title":"fix"}"#
        );
    }
    #[tokio::test]
    async fn permission_is_a_server_boundary() {
        assert_eq!(
            request("Bearer demo-team1-reader", r#"{"title":"fix"}"#.into())
                .await
                .status(),
            StatusCode::FORBIDDEN
        );
        assert_eq!(
            request("unknown", r#"{"title":"fix"}"#.into())
                .await
                .status(),
            StatusCode::UNAUTHORIZED
        );
    }
    #[tokio::test]
    async fn expected_input_failure_is_explicit() {
        assert_eq!(
            request("Bearer demo-team1-writer", r#"{"title":" "}"#.into())
                .await
                .status(),
            StatusCode::UNPROCESSABLE_ENTITY
        );
        assert_eq!(
            request("Bearer demo-team1-writer", "{".into())
                .await
                .status(),
            StatusCode::BAD_REQUEST
        );
        assert_eq!(
            request("Bearer demo-team1-writer", "x".repeat(4097))
                .await
                .status(),
            StatusCode::PAYLOAD_TOO_LARGE
        );
    }
}

Purpose: protect the meaning of a task

A task is more than three fields. It has an identifier greater than zero, a title with useful content, and a status chosen from a known set. The journal has another invariant: identifiers are unique within the current stored collection. These claims are requirements that must hold wherever data enters or changes. If every caller can set every field freely, every caller must remember every rule. A small domain API makes the rules easier to preserve and easier to test.

The reference stores Task fields privately and exposes read-only getters. Status is an enum with Open and Done. Journal owns a Vec<Task>, but its tasks method returns a slice. Callers can inspect tasks without inserting malformed rows. add, complete, and remove describe permitted state changes. None of these choices prevents all bugs automatically. They reduce the number of places where the invariants can be violated, which makes review and testing more focused.

Predict transitions before implementing

Create an empty journal, add one task, complete it twice, then try to complete identifier 99. Predict the number of tasks, the final status of the first task, and the last result. Expected: one task, Done, and Error::NotFound(99). Completing an already-completed task is idempotent in this contract: the second call leaves the state unchanged and succeeds. Another application might reject the second completion, but that would be a different explicit rule.

mise exec -- cargo test -p task-journal round_trip_and_transitions
mise exec -- cargo test -p task-journal rejects_corruption_without_partial_success

Do not confuse a missing task with a false status flag. Option can represent a lookup with no result. Result represents an operation that might fail and carries a reason. The complete method turns a failed lookup into NotFound using ok_or. Returning a bool would lose the distinction between “already done,” “identifier absent,” and “operation succeeded,” unless the contract carefully assigned meanings to those booleans. A named error is easier to review.

Guided checkpoint: validate before mutation

Implement add in the learner scaffold. First reject titles whose trimmed form is empty, whose UTF-8 byte length exceeds 200, or whose characters include a control character. The reference stores the original nonempty text rather than trimming it automatically. This is a deliberate policy: validation and normalization are separate operations. If you choose normalization for your extension, state it and test it. The length bound counts bytes, so a non-ASCII character may use more than one byte.

Next enforce the maximum task count. Then compute the next identifier with checked_add. Finally push the newly built Task. The order matters because all ordinary validation failures occur before mutation. A caller receiving an error can rely on no task having been added. This is a small transaction-like property within memory, not a database transaction. Write an assertion that the collection remains empty after rejected input, instead of checking only that an error was returned.

projects/reference/p02-journal/src/lib.rs
//! A small versioned task journal. Titles are UTF-8, single-line, 1–200 bytes.
//! The storage format is `TASKS\t1` followed by tab-separated id/status/title rows.
//! ```
//! use task_journal::Journal;
//! let mut journal = Journal::default();
//! let id = journal.add("Learn borrowing")?;
//! journal.complete(id)?;
//! let restored = Journal::decode(&journal.encode())?;
//! assert_eq!(restored.tasks(), journal.tasks());
//! # Ok::<(), task_journal::Error>(())
//! ```
use std::{
    collections::HashSet,
    fmt,
    fs::{self, File, OpenOptions},
    io::{self, Read, Write},
    path::Path,
};
const MAX_FILE_BYTES: u64 = 1_048_576;
const MAX_TASKS: usize = 10_000;
#[derive(Clone, Copy, Debug, PartialEq, Eq)]
pub enum Status {
    Open,
    Done,
}
#[derive(Clone, Debug, PartialEq, Eq)]
pub struct Task {
    id: u64,
    title: String,
    status: Status,
}
impl Task {
    pub fn id(&self) -> u64 {
        self.id
    }
    pub fn title(&self) -> &str {
        &self.title
    }
    pub fn status(&self) -> Status {
        self.status
    }
}
#[derive(Clone, Debug, Default, PartialEq, Eq)]
pub struct Journal {
    tasks: Vec<Task>,
}
#[derive(Debug)]
pub enum Error {
    Invalid(String),
    NotFound(u64),
    Io(io::Error),
}
impl fmt::Display for Error {
    fn fmt(&self, f: &mut fmt::Formatter<'_>) -> fmt::Result {
        match self {
            Self::Invalid(s) => write!(f, "invalid journal: {s}"),
            Self::NotFound(id) => write!(f, "task {id} does not exist"),
            Self::Io(e) => write!(f, "storage: {e}"),
        }
    }
}
impl std::error::Error for Error {
    fn source(&self) -> Option<&(dyn std::error::Error + 'static)> {
        if let Self::Io(e) = self {
            Some(e)
        } else {
            None
        }
    }
}
impl From<io::Error> for Error {
    fn from(e: io::Error) -> Self {
        Self::Io(e)
    }
}
fn validate_title(title: &str) -> Result<(), Error> {
    if title.trim().is_empty() || title.len() > 200 || title.chars().any(char::is_control) {
        return Err(Error::Invalid(
            "title must contain 1–200 bytes and no control characters".into(),
        ));
    }
    Ok(())
}
impl Journal {
    pub fn tasks(&self) -> &[Task] {
        &self.tasks
    }
    pub fn add(&mut self, title: &str) -> Result<u64, Error> {
        validate_title(title)?;
        if self.tasks.len() >= MAX_TASKS {
            return Err(Error::Invalid("task limit reached".into()));
        }
        let id = self
            .tasks
            .iter()
            .map(|t| t.id)
            .max()
            .unwrap_or(0)
            .checked_add(1)
            .ok_or_else(|| Error::Invalid("identifier space exhausted".into()))?;
        self.tasks.push(Task {
            id,
            title: title.to_owned(),
            status: Status::Open,
        });
        Ok(id)
    }
    pub fn complete(&mut self, id: u64) -> Result<(), Error> {
        let task = self
            .tasks
            .iter_mut()
            .find(|t| t.id == id)
            .ok_or(Error::NotFound(id))?;
        task.status = Status::Done;
        Ok(())
    }
    pub fn remove(&mut self, id: u64) -> Result<(), Error> {
        let position = self
            .tasks
            .iter()
            .position(|t| t.id == id)
            .ok_or(Error::NotFound(id))?;
        self.tasks.remove(position);
        Ok(())
    }
    pub fn encode(&self) -> String {
        let mut output = String::from("TASKS\t1\n");
        for task in &self.tasks {
            let status = match task.status {
                Status::Open => "open",
                Status::Done => "done",
            };
            use std::fmt::Write;
            writeln!(output, "{}\t{status}\t{}", task.id, task.title)
                .expect("writing String cannot fail");
        }
        output
    }
    pub fn decode(input: &str) -> Result<Self, Error> {
        if input.len() as u64 > MAX_FILE_BYTES {
            return Err(Error::Invalid("file exceeds 1 MiB".into()));
        }
        let mut lines = input.lines();
        if lines.next() != Some("TASKS\t1") {
            return Err(Error::Invalid(
                "unsupported or missing format header".into(),
            ));
        }
        let mut journal = Self::default();
        let mut seen = HashSet::new();
        for (offset, row) in lines.enumerate() {
            let fail = || Error::Invalid(format!("malformed row {}", offset + 2));
            let columns: Vec<&str> = row.split('\t').collect();
            let [id, status, title] = columns.as_slice() else {
                return Err(fail());
            };
            let id: u64 = id.parse().map_err(|_| fail())?;
            if id == 0 || !seen.insert(id) || journal.tasks.len() >= MAX_TASKS {
                return Err(fail());
            }
            let status = match *status {
                "open" => Status::Open,
                "done" => Status::Done,
                _ => return Err(fail()),
            };
            validate_title(title)?;
            journal.tasks.push(Task {
                id,
                title: (*title).to_owned(),
                status,
            });
        }
        Ok(journal)
    }
    /// A missing path starts a new journal. Other read errors are preserved.
    pub fn load(path: &Path) -> Result<Self, Error> {
        let file = match File::open(path) {
            Ok(file) => file,
            Err(e) if e.kind() == io::ErrorKind::NotFound => return Ok(Self::default()),
            Err(e) => return Err(e.into()),
        };
        let mut bytes = Vec::new();
        file.take(MAX_FILE_BYTES + 1).read_to_end(&mut bytes)?;
        if bytes.len() as u64 > MAX_FILE_BYTES {
            return Err(Error::Invalid("file exceeds 1 MiB".into()));
        }
        let text =
            std::str::from_utf8(&bytes).map_err(|_| Error::Invalid("file is not UTF-8".into()))?;
        Self::decode(text)
    }
    /// Writes a sibling temporary file then renames it. Designed for one writer.
    /// No locking or parent-directory fsync: not a database durability guarantee.
    pub fn save(&self, path: &Path) -> Result<(), Error> {
        let bytes = self.encode();
        if bytes.len() as u64 > MAX_FILE_BYTES {
            return Err(Error::Invalid("file exceeds 1 MiB".into()));
        }
        let mut temporary_name = path.as_os_str().to_os_string();
        temporary_name.push(format!(".{}.tmp", std::process::id()));
        let temporary = std::path::PathBuf::from(temporary_name);
        let mut file = OpenOptions::new()
            .write(true)
            .create_new(true)
            .open(&temporary)?;
        let result = (|| -> io::Result<()> {
            file.write_all(bytes.as_bytes())?;
            file.sync_all()?;
            drop(file);
            fs::rename(&temporary, path)
        })();
        if result.is_err() {
            let _ = fs::remove_file(&temporary);
        }
        result.map_err(Error::from)
    }
}
#[cfg(test)]
mod tests {
    use super::*;
    #[test]
    fn round_trip_and_transitions() {
        let mut j = Journal::default();
        let a = j.add("read 🦀").unwrap();
        let b = j.add("write tests").unwrap();
        j.complete(a).unwrap();
        j.complete(a).unwrap();
        j.remove(b).unwrap();
        assert_eq!(Journal::decode(&j.encode()).unwrap(), j);
        assert_eq!(j.tasks()[0].status(), Status::Done);
        assert!(matches!(j.complete(99), Err(Error::NotFound(99))));
    }
    #[test]
    fn rejects_corruption_without_partial_success() {
        for input in [
            "TASKS\t2\n",
            "TASKS\t1\n1\topen\tx\n1\tdone\ty\n",
            "TASKS\t1\n0\topen\tx\n",
            "TASKS\t1\n1\tmaybe\tx\n",
            "TASKS\t1\n1\topen\t\n",
        ] {
            assert!(Journal::decode(input).is_err(), "{input}");
        }
        let mut j = Journal::default();
        assert!(j.add(" ").is_err());
        assert!(j.add("one\ntwo").is_err());
        assert!(j.tasks().is_empty());
    }
    #[test]
    fn id_overflow_is_an_error() {
        let mut j = Journal::decode("TASKS\t1\n18446744073709551615\topen\tx\n").unwrap();
        assert!(j.add("next").is_err());
    }
}

Intentional mistake: replacing an enum with an unrestricted string

In a scratch design, replace Status with String and allow callers to write any value. List the additional states you have now admitted: done, Done, complete, empty text, a typo, and arbitrary bytes representable as UTF-8. Every display and persistence branch must decide what those states mean. Restore the enum and observe that a match missing Done is rejected by the compiler. The supplied 04-nonexhaustive.rs exercise demonstrates this diagnostic. An exhaustive match is useful when adding a new state should force a review of existing behavior.

A wildcard arm can hide that pressure. Match arms ending in _ are appropriate when a fallback is the intended behavior, but adding them automatically just to satisfy the compiler can conceal forgotten business rules. For our status representation, handling both named variants explicitly is clearer. If you add Archived later, the compiler should direct you to the places that need a deliberate decision.

Playbook: a title looks short but is rejected

Observation: a title consisting of repeated emoji reaches the 200-byte limit before it reaches 200 visible symbols. Hypothesis A: the limit uses character count and contains an off-by-one bug. Hypothesis B: the specified limit counts UTF-8 bytes. A distinguishing experiment compares the same count of ASCII letters and a multibyte symbol, then measures each with .len() and .chars().count(). Expected result: byte lengths differ while the scalar-value counts match. That disproves A as the explanation for this case.

The correct fix is not automatically to replace len. Decide what the product limit is meant to protect. A storage byte limit directly bounds encoded data. A user-facing character limit raises additional questions about grapheme clusters and Unicode normalization. For this course the byte rule is documented and tested. Improve the error text if the observation shows it is confusing; changing semantics without a requirement would make the tests and file contract inconsistent.

When you get stuck: independent work and tiered help

Add rename(id, title) to your learner journal. Reuse the existing validation rule, return NotFound for an absent identifier, and guarantee that a failed rename leaves the old title intact. Decide and document which error wins if both the identifier is missing and the proposed title is invalid. Either ordering can be defensible; it should be consistent and covered by a test. This task forces you to reason about both validation boundaries and observable failure precedence.

Hint 1: choose the next observation

write before-and-after states before writing the method.

Hint 2: narrow the experiment

validate the new value into a temporary variable before assigning to the task.

Worked solution

call validate_title, find the task with iter_mut and ok_or, then replace the stored title with title.to_owned(). The borrowed input must become owned storage once, after acceptance. Ask for a review of the invariant and error ordering, not “make this more Rusty.” An AI can suggest alternatives, but you should reject any that silently alter the transition contract.

Review and mastery evidence

The recommended domain boundary enforces title rules for every construction route and exposes private fields through read-only views. The decoder separately enforces collection rules such as unique identifiers. A dedicated validated Title type would be a sound next step if several domain objects shared the same title invariant; for one Task model, a private validation helper keeps the requirement visible without unnecessary indirection. Keep per-value and collection invariants distinct in either design.

Mastery means you can enumerate valid states, identify every constructor or mutator, and provide a test for each rejection that must preserve old state. Passing the compiler's exhaustiveness check proves that your match covers the enum variants, not that the actions in those arms satisfy the requirements. Unit tests add behavioral evidence. A concise design note should connect each invariant to its enforcing boundary and acknowledge that identifier reuse after deleting the highest task is allowed by this reference's current-file model.

A versioned text format that rejects corruption

Persist task meaning without quietly accepting duplicate identifiers or unknown file versions.

Read with a terminal open. Predict before revealing. Verified source versions: version ledger.

Prerequisites and learning objectives
  • Model valid task states and make invalid transitions visible
  • Specify a file grammar and version policy
  • Separate parsing from file access
  • Test round trips and corrupt inputs independently

Key terms: durability · future · invariant · mise · schema · UTF-8

Keep the problem-solving playbook open. Record observations before explanations, and save the experiment that changed your mind.

Purpose: yesterday's bytes become today's input

A journal becomes useful when tasks survive process exit. Persistence introduces a new trust boundary: bytes on disk may be missing, truncated, edited by hand, or written by an older program. Treat loading as validation of external input, even if your program originally produced the file. Reusing in-memory assumptions without checking them can turn corrupted data into plausible task state. The goal is a format small enough to inspect and strict enough to reject ambiguity.

Our format starts with TASKS, a tab, and version 1. Each following row contains an unsigned identifier, a status word, and a title, separated by tabs. Titles cannot contain control characters, so tabs and newlines cannot escape into new fields or rows. UTF-8 text is allowed, and the title limit counts bytes. The decoder accepts the supported header and known status strings only. A future format version must have a deliberate migration; it must not be guessed from data that happens to look familiar.

Prediction: a round trip is not the whole contract

Predict what happens for each fixture: the valid tasks-v1.txt file, the duplicate-identifier fixture, an empty file, and a file with TASKS version 2. Expected: the valid file decodes; the other three fail. An empty file is different from a missing path. Missing can mean “new journal”; present but empty indicates a malformed stored journal. This distinction protects users from a damaged file silently appearing to erase all their tasks.

A round-trip assertion decode(encode(journal)) == journal verifies that the two functions agree for that journal. It does not prove that the format is unambiguous or that malformed input is rejected. Two functions can share the same bug and round-trip perfectly. Keep explicit fixtures with independently understood contents and separate rejection tests for missing fields, extra fields, duplicate IDs, invalid status, and unsupported versions.

Guided checkpoint: build a decoder that commits at the end

Start with a pure decode(&str) function so parsing tests need no filesystem. Check the byte limit and header before reading rows. For each row, require exactly three columns. Parse the identifier, reject zero, track previously seen IDs in a HashSet, decode status, and validate the title. Build a local Journal and return it only after all rows succeed. If row 40 fails, the caller receives an error instead of a partly loaded collection of 39 tasks.

The HashSet is not merely an optimization. It records a collection-wide invariant during decoding. Task alone cannot know whether its identifier duplicates another task. Keep that check at the journal boundary. Likewise, row numbers belong to the decoder because they describe source structure, while title validity belongs to the title-validation helper because both user input and persisted rows need the same rule.

//! A small versioned task journal. Titles are UTF-8, single-line, 1–200 bytes.
//! The storage format is `TASKS\t1` followed by tab-separated id/status/title rows.
//! ```
//! use task_journal::Journal;
//! let mut journal = Journal::default();
//! let id = journal.add("Learn borrowing")?;
//! journal.complete(id)?;
//! let restored = Journal::decode(&journal.encode())?;
//! assert_eq!(restored.tasks(), journal.tasks());
//! # Ok::<(), task_journal::Error>(())
//! ```
use std::{
    collections::HashSet,
    fmt,
    fs::{self, File, OpenOptions},
    io::{self, Read, Write},
    path::Path,
};
const MAX_FILE_BYTES: u64 = 1_048_576;
const MAX_TASKS: usize = 10_000;
#[derive(Clone, Copy, Debug, PartialEq, Eq)]
pub enum Status {
    Open,
    Done,
}
#[derive(Clone, Debug, PartialEq, Eq)]
pub struct Task {
    id: u64,
    title: String,
    status: Status,
}
impl Task {
    pub fn id(&self) -> u64 {
        self.id
    }
    pub fn title(&self) -> &str {
        &self.title
    }
    pub fn status(&self) -> Status {
        self.status
    }
}
#[derive(Clone, Debug, Default, PartialEq, Eq)]
pub struct Journal {
    tasks: Vec<Task>,
}
#[derive(Debug)]
pub enum Error {
    Invalid(String),
    NotFound(u64),
    Io(io::Error),
}
impl fmt::Display for Error {
    fn fmt(&self, f: &mut fmt::Formatter<'_>) -> fmt::Result {
        match self {
            Self::Invalid(s) => write!(f, "invalid journal: {s}"),
            Self::NotFound(id) => write!(f, "task {id} does not exist"),
            Self::Io(e) => write!(f, "storage: {e}"),
        }
    }
}
impl std::error::Error for Error {
    fn source(&self) -> Option<&(dyn std::error::Error + 'static)> {
        if let Self::Io(e) = self {
            Some(e)
        } else {
            None
        }
    }
}
impl From<io::Error> for Error {
    fn from(e: io::Error) -> Self {
        Self::Io(e)
    }
}
fn validate_title(title: &str) -> Result<(), Error> {
    if title.trim().is_empty() || title.len() > 200 || title.chars().any(char::is_control) {
        return Err(Error::Invalid(
            "title must contain 1–200 bytes and no control characters".into(),
        ));
    }
    Ok(())
}
impl Journal {
    pub fn tasks(&self) -> &[Task] {
        &self.tasks
    }
    pub fn add(&mut self, title: &str) -> Result<u64, Error> {
        validate_title(title)?;
        if self.tasks.len() >= MAX_TASKS {
            return Err(Error::Invalid("task limit reached".into()));
        }
        let id = self
            .tasks
            .iter()
            .map(|t| t.id)
            .max()
            .unwrap_or(0)
            .checked_add(1)
            .ok_or_else(|| Error::Invalid("identifier space exhausted".into()))?;
        self.tasks.push(Task {
            id,
            title: title.to_owned(),
            status: Status::Open,
        });
        Ok(id)
    }
    pub fn complete(&mut self, id: u64) -> Result<(), Error> {
        let task = self
            .tasks
            .iter_mut()
            .find(|t| t.id == id)
            .ok_or(Error::NotFound(id))?;
        task.status = Status::Done;
        Ok(())
    }
    pub fn remove(&mut self, id: u64) -> Result<(), Error> {
        let position = self
            .tasks
            .iter()
            .position(|t| t.id == id)
            .ok_or(Error::NotFound(id))?;
        self.tasks.remove(position);
        Ok(())
    }
    pub fn encode(&self) -> String {
        let mut output = String::from("TASKS\t1\n");
        for task in &self.tasks {
            let status = match task.status {
                Status::Open => "open",
                Status::Done => "done",
            };
            use std::fmt::Write;
            writeln!(output, "{}\t{status}\t{}", task.id, task.title)
                .expect("writing String cannot fail");
        }
        output
    }
    pub fn decode(input: &str) -> Result<Self, Error> {
        if input.len() as u64 > MAX_FILE_BYTES {
            return Err(Error::Invalid("file exceeds 1 MiB".into()));
        }
        let mut lines = input.lines();
        if lines.next() != Some("TASKS\t1") {
            return Err(Error::Invalid(
                "unsupported or missing format header".into(),
            ));
        }
        let mut journal = Self::default();
        let mut seen = HashSet::new();
        for (offset, row) in lines.enumerate() {
            let fail = || Error::Invalid(format!("malformed row {}", offset + 2));
            let columns: Vec<&str> = row.split('\t').collect();
            let [id, status, title] = columns.as_slice() else {
                return Err(fail());
            };
            let id: u64 = id.parse().map_err(|_| fail())?;
            if id == 0 || !seen.insert(id) || journal.tasks.len() >= MAX_TASKS {
                return Err(fail());
            }
            let status = match *status {
                "open" => Status::Open,
                "done" => Status::Done,
                _ => return Err(fail()),
            };
            validate_title(title)?;
            journal.tasks.push(Task {
                id,
                title: (*title).to_owned(),
                status,
            });
        }
        Ok(journal)
    }
    /// A missing path starts a new journal. Other read errors are preserved.
    pub fn load(path: &Path) -> Result<Self, Error> {
        let file = match File::open(path) {
            Ok(file) => file,
            Err(e) if e.kind() == io::ErrorKind::NotFound => return Ok(Self::default()),
            Err(e) => return Err(e.into()),
        };
        let mut bytes = Vec::new();
        file.take(MAX_FILE_BYTES + 1).read_to_end(&mut bytes)?;
        if bytes.len() as u64 > MAX_FILE_BYTES {
            return Err(Error::Invalid("file exceeds 1 MiB".into()));
        }
        let text =
            std::str::from_utf8(&bytes).map_err(|_| Error::Invalid("file is not UTF-8".into()))?;
        Self::decode(text)
    }
    /// Writes a sibling temporary file then renames it. Designed for one writer.
    /// No locking or parent-directory fsync: not a database durability guarantee.
    pub fn save(&self, path: &Path) -> Result<(), Error> {
        let bytes = self.encode();
        if bytes.len() as u64 > MAX_FILE_BYTES {
            return Err(Error::Invalid("file exceeds 1 MiB".into()));
        }
        let mut temporary_name = path.as_os_str().to_os_string();
        temporary_name.push(format!(".{}.tmp", std::process::id()));
        let temporary = std::path::PathBuf::from(temporary_name);
        let mut file = OpenOptions::new()
            .write(true)
            .create_new(true)
            .open(&temporary)?;
        let result = (|| -> io::Result<()> {
            file.write_all(bytes.as_bytes())?;
            file.sync_all()?;
            drop(file);
            fs::rename(&temporary, path)
        })();
        if result.is_err() {
            let _ = fs::remove_file(&temporary);
        }
        result.map_err(Error::from)
    }
}
#[cfg(test)]
mod tests {
    use super::*;
    #[test]
    fn round_trip_and_transitions() {
        let mut j = Journal::default();
        let a = j.add("read 🦀").unwrap();
        let b = j.add("write tests").unwrap();
        j.complete(a).unwrap();
        j.complete(a).unwrap();
        j.remove(b).unwrap();
        assert_eq!(Journal::decode(&j.encode()).unwrap(), j);
        assert_eq!(j.tasks()[0].status(), Status::Done);
        assert!(matches!(j.complete(99), Err(Error::NotFound(99))));
    }
    #[test]
    fn rejects_corruption_without_partial_success() {
        for input in [
            "TASKS\t2\n",
            "TASKS\t1\n1\topen\tx\n1\tdone\ty\n",
            "TASKS\t1\n0\topen\tx\n",
            "TASKS\t1\n1\tmaybe\tx\n",
            "TASKS\t1\n1\topen\t\n",
        ] {
            assert!(Journal::decode(input).is_err(), "{input}");
        }
        let mut j = Journal::default();
        assert!(j.add(" ").is_err());
        assert!(j.add("one\ntwo").is_err());
        assert!(j.tasks().is_empty());
    }
    #[test]
    fn id_overflow_is_an_error() {
        let mut j = Journal::decode("TASKS\t1\n18446744073709551615\topen\tx\n").unwrap();
        assert!(j.add("next").is_err());
    }
}

Read encode after decode. It emits a stable header, a known status spelling, and the original title. Writing into a String is an in-memory formatting operation; its expect call documents an invariant of that destination rather than dismissing ordinary disk failure. Actual File writes return IO errors elsewhere. Two operations both named “write” can have different failure models, which is why you should inspect the destination type before judging error handling.

Intentional mistake: silently skip malformed rows

In a scratch decoder, replace a malformed-row error with continue. The program may appear more resilient because it loads the remaining rows. But its success result now conceals data loss. If the user saves the loaded journal, the skipped task disappears permanently from the new file. Tolerant ingestion is sometimes appropriate for an analytics pipeline; it needs explicit rejected-row accounting and recovery policy. A personal task store should not silently reinterpret corruption as successful loading.

Another mistake is regenerating every identifier while loading. Titles and statuses may still look correct, while commands referring to saved IDs target different tasks. Identifiers are part of this file's meaning. Preserve and validate them. Our add operation chooses one more than the current maximum, so removing the highest ID permits reuse; that is documented as a current-collection identity model rather than a globally permanent event identity.

Playbook: tasks disappear after reopening

Observation: a learner decoder returns fewer tasks than the fixture contains. Hypothesis A: the file reader truncated the bytes. Hypothesis B: the decoder silently skips a malformed row. Distinguishing experiment: call decode directly on a small inline string containing one valid row and one invalid row. Expected result for the reference: an error, with no partial Journal returned. If the learner implementation returns one task from the inline string, filesystem truncation is disproven for that reproduction.

Capture the smallest input that demonstrates the behavior and the exact row rule it violates. Do not begin by rewriting save. The boundary under investigation is bytes-to-domain-state, and the direct test bypasses unrelated file access. Ask an AI assistant to list what an observed row count can and cannot establish. A good answer should distinguish bytes read, rows recognized, and tasks accepted, and propose a measurement at the first uncertain boundary.

Review and mastery evidence

The recommended parser treats persisted bytes as fallible input and returns a reason while leaving the original file intact. The hand-readable tab format is appropriate because titles exclude delimiters and the schema has three fields. A structured serialization library becomes worthwhile for nested data or external interoperability; it still would not choose duplicate-ID policy, migration behavior, or title rules. Those are domain requirements under either syntax.

Mastery means explaining how a file becomes a fully valid Journal, including what happens when the last row is corrupt. Demonstrate a round trip, an independently specified fixture, and an intentional rejection. State that these tests support the format contract but do not prove crash durability or safe concurrent access. Those are IO and coordination properties, addressed separately in the next checkpoint.

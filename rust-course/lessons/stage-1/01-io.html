File IO: preserve errors and replace data carefully

Complete a single-writer journal while explaining exactly what temporary-file replacement guarantees.

Read with a terminal open. Predict before revealing. Verified source versions: version ledger.

Prerequisites and learning objectives
  • A versioned text format that rejects corruption
  • Differentiate NotFound from other IO failures
  • Bound reads before allocation grows without limit
  • Implement and test a temporary-file replacement protocol

Key terms: allocation · durability · generic · idempotency · mise · schema · UTF-8

Purpose: storage is a protocol, not one write call

An in-memory journal can validate a title perfectly and still lose data through careless file handling. IO connects your process to resources whose behavior is not fully under its control: files can disappear, permissions can change, disks can fill, and another process may act concurrently. Your job is to choose a protocol and report its actual guarantees. This checkpoint implements a small single-writer store, not a database disguised as a text file.

The reference load operation opens the requested path. Only ErrorKind::NotFound becomes an empty Journal. PermissionDenied, invalid UTF-8, malformed content, and other failures remain errors. Treating all errors as “start fresh” turns a temporary access problem into an apparently empty task list. A subsequent save could overwrite data the program never read. Preserving the error protects both the user and your ability to diagnose the problem.

The CLI retains its file argument as an operating-system path. Task titles, commands, and identifiers are explicitly converted to UTF-8 text with recoverable errors when conversion fails. A filesystem path need not be valid Unicode, so converting every argument to String at process startup would impose an unnecessary assumption on file access.

Guided checkpoint: bounded loading

Before decoding, load reads at most one byte beyond the 1 MiB limit. The extra byte distinguishes a file exactly at the accepted limit from a larger file. Calling read_to_end without a take limit would allow allocation to grow with the entire file before checking its size. A check after unbounded ingestion does not enforce a memory-ingestion limit. The decoder also checks size because it is a public boundary that callers can use independently of File.

Convert the retained bytes to UTF-8 only after the read succeeds and the size is acceptable. A failed conversion means the file violates the format, not that invalid bytes should be silently removed. File::open and Read failures are wrapped as Error::Io, retaining the original error as a source. That source chain lets callers inspect the underlying failure while a display message supplies domain context. Stringifying every error too early would throw away that structure.

projects/reference/p02-journal/src/lib.rs
//! A small versioned task journal. Titles are UTF-8, single-line, 1–200 bytes.
//! The storage format is `TASKS\t1` followed by tab-separated id/status/title rows.
//! ```
//! use task_journal::Journal;
//! let mut journal = Journal::default();
//! let id = journal.add("Learn borrowing")?;
//! journal.complete(id)?;
//! let restored = Journal::decode(&journal.encode())?;
//! assert_eq!(restored.tasks(), journal.tasks());
//! # Ok::<(), task_journal::Error>(())
//! ```
use std::{
    collections::HashSet,
    fmt,
    fs::{self, File, OpenOptions},
    io::{self, Read, Write},
    path::Path,
};
const MAX_FILE_BYTES: u64 = 1_048_576;
const MAX_TASKS: usize = 10_000;
#[derive(Clone, Copy, Debug, PartialEq, Eq)]
pub enum Status {
    Open,
    Done,
}
#[derive(Clone, Debug, PartialEq, Eq)]
pub struct Task {
    id: u64,
    title: String,
    status: Status,
}
impl Task {
    pub fn id(&self) -> u64 {
        self.id
    }
    pub fn title(&self) -> &str {
        &self.title
    }
    pub fn status(&self) -> Status {
        self.status
    }
}
#[derive(Clone, Debug, Default, PartialEq, Eq)]
pub struct Journal {
    tasks: Vec<Task>,
}
#[derive(Debug)]
pub enum Error {
    Invalid(String),
    NotFound(u64),
    Io(io::Error),
}
impl fmt::Display for Error {
    fn fmt(&self, f: &mut fmt::Formatter<'_>) -> fmt::Result {
        match self {
            Self::Invalid(s) => write!(f, "invalid journal: {s}"),
            Self::NotFound(id) => write!(f, "task {id} does not exist"),
            Self::Io(e) => write!(f, "storage: {e}"),
        }
    }
}
impl std::error::Error for Error {
    fn source(&self) -> Option<&(dyn std::error::Error + 'static)> {
        if let Self::Io(e) = self {
            Some(e)
        } else {
            None
        }
    }
}
impl From<io::Error> for Error {
    fn from(e: io::Error) -> Self {
        Self::Io(e)
    }
}
fn validate_title(title: &str) -> Result<(), Error> {
    if title.trim().is_empty() || title.len() > 200 || title.chars().any(char::is_control) {
        return Err(Error::Invalid(
            "title must contain 1–200 bytes and no control characters".into(),
        ));
    }
    Ok(())
}
impl Journal {
    pub fn tasks(&self) -> &[Task] {
        &self.tasks
    }
    pub fn add(&mut self, title: &str) -> Result<u64, Error> {
        validate_title(title)?;
        if self.tasks.len() >= MAX_TASKS {
            return Err(Error::Invalid("task limit reached".into()));
        }
        let id = self
            .tasks
            .iter()
            .map(|t| t.id)
            .max()
            .unwrap_or(0)
            .checked_add(1)
            .ok_or_else(|| Error::Invalid("identifier space exhausted".into()))?;
        self.tasks.push(Task {
            id,
            title: title.to_owned(),
            status: Status::Open,
        });
        Ok(id)
    }
    pub fn complete(&mut self, id: u64) -> Result<(), Error> {
        let task = self
            .tasks
            .iter_mut()
            .find(|t| t.id == id)
            .ok_or(Error::NotFound(id))?;
        task.status = Status::Done;
        Ok(())
    }
    pub fn remove(&mut self, id: u64) -> Result<(), Error> {
        let position = self
            .tasks
            .iter()
            .position(|t| t.id == id)
            .ok_or(Error::NotFound(id))?;
        self.tasks.remove(position);
        Ok(())
    }
    pub fn encode(&self) -> String {
        let mut output = String::from("TASKS\t1\n");
        for task in &self.tasks {
            let status = match task.status {
                Status::Open => "open",
                Status::Done => "done",
            };
            use std::fmt::Write;
            writeln!(output, "{}\t{status}\t{}", task.id, task.title)
                .expect("writing String cannot fail");
        }
        output
    }
    pub fn decode(input: &str) -> Result<Self, Error> {
        if input.len() as u64 > MAX_FILE_BYTES {
            return Err(Error::Invalid("file exceeds 1 MiB".into()));
        }
        let mut lines = input.lines();
        if lines.next() != Some("TASKS\t1") {
            return Err(Error::Invalid(
                "unsupported or missing format header".into(),
            ));
        }
        let mut journal = Self::default();
        let mut seen = HashSet::new();
        for (offset, row) in lines.enumerate() {
            let fail = || Error::Invalid(format!("malformed row {}", offset + 2));
            let columns: Vec<&str> = row.split('\t').collect();
            let [id, status, title] = columns.as_slice() else {
                return Err(fail());
            };
            let id: u64 = id.parse().map_err(|_| fail())?;
            if id == 0 || !seen.insert(id) || journal.tasks.len() >= MAX_TASKS {
                return Err(fail());
            }
            let status = match *status {
                "open" => Status::Open,
                "done" => Status::Done,
                _ => return Err(fail()),
            };
            validate_title(title)?;
            journal.tasks.push(Task {
                id,
                title: (*title).to_owned(),
                status,
            });
        }
        Ok(journal)
    }
    /// A missing path starts a new journal. Other read errors are preserved.
    pub fn load(path: &Path) -> Result<Self, Error> {
        let file = match File::open(path) {
            Ok(file) => file,
            Err(e) if e.kind() == io::ErrorKind::NotFound => return Ok(Self::default()),
            Err(e) => return Err(e.into()),
        };
        let mut bytes = Vec::new();
        file.take(MAX_FILE_BYTES + 1).read_to_end(&mut bytes)?;
        if bytes.len() as u64 > MAX_FILE_BYTES {
            return Err(Error::Invalid("file exceeds 1 MiB".into()));
        }
        let text =
            std::str::from_utf8(&bytes).map_err(|_| Error::Invalid("file is not UTF-8".into()))?;
        Self::decode(text)
    }
    /// Writes a sibling temporary file then renames it. Designed for one writer.
    /// No locking or parent-directory fsync: not a database durability guarantee.
    pub fn save(&self, path: &Path) -> Result<(), Error> {
        let bytes = self.encode();
        if bytes.len() as u64 > MAX_FILE_BYTES {
            return Err(Error::Invalid("file exceeds 1 MiB".into()));
        }
        let mut temporary_name = path.as_os_str().to_os_string();
        temporary_name.push(format!(".{}.tmp", std::process::id()));
        let temporary = std::path::PathBuf::from(temporary_name);
        let mut file = OpenOptions::new()
            .write(true)
            .create_new(true)
            .open(&temporary)?;
        let result = (|| -> io::Result<()> {
            file.write_all(bytes.as_bytes())?;
            file.sync_all()?;
            drop(file);
            fs::rename(&temporary, path)
        })();
        if result.is_err() {
            let _ = fs::remove_file(&temporary);
        }
        result.map_err(Error::from)
    }
}
#[cfg(test)]
mod tests {
    use super::*;
    #[test]
    fn round_trip_and_transitions() {
        let mut j = Journal::default();
        let a = j.add("read 🦀").unwrap();
        let b = j.add("write tests").unwrap();
        j.complete(a).unwrap();
        j.complete(a).unwrap();
        j.remove(b).unwrap();
        assert_eq!(Journal::decode(&j.encode()).unwrap(), j);
        assert_eq!(j.tasks()[0].status(), Status::Done);
        assert!(matches!(j.complete(99), Err(Error::NotFound(99))));
    }
    #[test]
    fn rejects_corruption_without_partial_success() {
        for input in [
            "TASKS\t2\n",
            "TASKS\t1\n1\topen\tx\n1\tdone\ty\n",
            "TASKS\t1\n0\topen\tx\n",
            "TASKS\t1\n1\tmaybe\tx\n",
            "TASKS\t1\n1\topen\t\n",
        ] {
            assert!(Journal::decode(input).is_err(), "{input}");
        }
        let mut j = Journal::default();
        assert!(j.add(" ").is_err());
        assert!(j.add("one\ntwo").is_err());
        assert!(j.tasks().is_empty());
    }
    #[test]
    fn id_overflow_is_an_error() {
        let mut j = Journal::decode("TASKS\t1\n18446744073709551615\topen\tx\n").unwrap();
        assert!(j.add("next").is_err());
    }
}

Guided checkpoint: replacing a complete file

The save method encodes into memory, verifies its output limit, and creates a sibling temporary file using create_new. That option refuses to overwrite an existing temporary path. It writes all bytes, synchronizes the temporary file, closes it, and renames it onto the destination. On an error after temporary creation, it attempts to remove its own temporary file. A reader should not observe a half-written replacement produced by this process's ordinary write sequence.

The guarantee has limits. The implementation has no multi-process locking, and two writers can lose each other's updates. It does not fsync the containing directory, so do not claim a full power-loss durability guarantee. Rename replacement behavior and failures depend on the filesystem and operating system; test the target platform. A stale same-process-name temporary file causes a reported error rather than unsafe overwriting. These are concrete design limits, not generic warnings attached to every program.

Intentional mistake: truncate before you know you can finish

Sketch the simpler implementation File::create(destination), then write_all. Opening with truncation can erase the old contents before the new bytes have been fully written. If a later write fails, the old complete file is gone. The temporary-file protocol changes that ordering. Do not simulate disk-full failures by filling your machine. Instead, reason about the sequence and use a controlled failing writer abstraction in an extension if you want fault-injection tests.

Also avoid printing “saved” before save returns successfully. Process messages are part of the observable contract. The reference prints added only after persistence succeeds, so a success message does not claim an uncompleted storage operation. The in-memory object may have changed before save fails, but the short-lived CLI exits on that error; a long-lived UI would need an explicit unsaved-state policy.

Playbook: an existing journal appears empty

Observation: a learner program lists zero tasks when opening a protected or invalid path. Hypothesis A: decoding a valid empty journal is correct. Hypothesis B: an error was converted to an empty default by unwrap_or_default. Distinguishing experiment: load a known malformed file whose bytes are fixed and inspect the Result directly in a test. Expected reference result: Err. If the learner returns Ok(empty), the “valid empty file” explanation is disproven without relying on platform-specific permission behavior.

Trace the first place an error becomes success. The smallest fix is to special-case NotFound at the open boundary and propagate other errors, not to add retries everywhere. Record which failure you actually reproduced and which platform cases remain untested. Ask AI for the failure sequence under each proposed save protocol, then challenge it to identify what rename and sync_all do not guarantee together in this implementation.

A failed acknowledgement does not undo a save

The CLI saves an added task before writing added ID. Both output writing and its final flush are fallible, so a closed pipe exits with an I/O error instead of panicking. The save may already have succeeded. The output regression adds one task with stdout connected to a pipe whose read end is closed, observes failure, then reloads exactly one saved task. Repeating add blindly would create another task; inspect the journal after an uncertain acknowledgement. This is a local example of separating state change from delivery of its report, not a claim that the file format supports distributed idempotency.

When you get stuck: independent work and tiered help

Add a command that validates a journal without saving it. Return a nonzero exit for corrupted contents and preserve the file byte-for-byte. Next design, without claiming to implement it, how two simultaneous writers would coordinate. Name the lost-update scenario explicitly: each reads the same old state, each adds a different task, and the later save replaces the earlier update. A temporary filename alone does not solve this.

Review and mastery

The recommended design isolates pure parsing from file access and presentation, then tests each relevant boundary. A temporary replacement protocol is appropriate for this documented single-writer local journal. A transactional database is a meaningful alternative when concurrent writers, crash recovery, richer queries, or durable identity history become actual requirements. It adds operational and schema concerns, so it should be selected for those guarantees rather than as a status symbol.

Engineering decisions and evidence

Requirements and invariants

Tasks have private validated titles, nonzero unique current-file IDs, and one of two statuses. A failed domain validation leaves state unchanged. The versioned decoder rejects unknown headers, malformed rows, duplicate IDs, oversized files, and invalid UTF-8. Missing files start a journal; other load failures are retained.

Chosen design and concrete habits

Journal methods own state transitions, borrowed getters avoid incidental copies, and a pure decoder separates format checks from filesystem effects. load caps ingestion before decoding. save writes and syncs a sibling temporary file before rename, and success messages occur only after save returns. IO errors preserve their source. The String formatting expect is an internal infallibility assertion, not a policy for routine disk errors.

Meaningful alternative and evolution threshold

A database or explicit locking protocol is required when multiple writers must coordinate or stronger crash-recovery guarantees matter. The current rename sequence has no parent-directory fsync and no concurrency control. IDs may be reused after removing the current maximum; permanent external identity or audit history would justify a persisted monotonic allocator or event log. These changes follow concrete requirements.

Actual checks and remaining uncertainty

Native state-transition, malformed-format, fixture, filesystem replacement, and documentation tests passed in verification/native-tests.log and passed again in verification/patch001-foundations-tests.log after the patch audit. Tests show corrupt input is retained and valid state reloads on the tested local filesystem. They do not simulate power failure, all permission modes, or simultaneous writers.

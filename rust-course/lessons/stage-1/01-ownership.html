Ownership as an API decision: borrow, move, or clone

Use a task title to connect ownership rules to the actual lifetime of stored data.

Purpose: a journal must keep data after input disappears

A task journal accepts text from command-line arguments and keeps titles in a collection. The command argument buffer and the journal have different jobs and potentially different lifetimes. This makes ownership a practical design question: who is responsible for retaining the title's allocation after the function returns? Do not begin with “how can I satisfy the borrow checker?” Begin with “which part of the program must keep this data?” The signature should express that answer.

String owns a growable UTF-8 text buffer. &str borrows a view into existing UTF-8 text. Moving a String transfers ownership of its allocation; it does not normally duplicate all the characters. Cloning creates another owned buffer and copies its contents. Borrowing lets code inspect existing data while the owner remains responsible for it. These three operations have different semantics even when the printed text looks identical. Avoid the inaccurate rule that Rust “always copies on assignment” or “never copies anything.”

Predict the ownership transition

In an isolated learner file, predict whether this compiles: let title = String::from("learn"); let stored = title; println!("{title}");. Expected result: use-after-move error E0382. Ownership moved into stored, so title cannot then be used as an owner. The bytes did not disappear; the old binding lost permission to access the value. Replacing the move with let stored = &title permits both reads, provided the borrow does not outlive title.

Guided checkpoint: store one intentional copy

Read Journal::add. Its title argument is &str, which means callers can supply a string literal, a borrowed String, or another string slice without surrendering ownership. The method validates the text, chooses an identifier, and then uses to_owned when constructing Task. That allocation is intentional: the journal must retain its own title after add returns. A clone here has an explanation. Adding clones throughout the caller just to silence diagnostics would obscure the design.

Task::title returns &str borrowed from self. A reader can inspect the title without allocating another buffer. Journal::tasks returns a slice of tasks rather than the whole mutable Vec, preserving control over additions and state changes. Follow one title through these boundaries: borrowed incoming text, owned stored text, borrowed outgoing view. Draw the owners and views, and mark the point at which each view stops being used.

projects/reference/p02-journal/src/lib.rs
//! A small versioned task journal. Titles are UTF-8, single-line, 1–200 bytes.
//! The storage format is `TASKS\t1` followed by tab-separated id/status/title rows.
//! ```
//! use task_journal::Journal;
//! let mut journal = Journal::default();
//! let id = journal.add("Learn borrowing")?;
//! journal.complete(id)?;
//! let restored = Journal::decode(&journal.encode())?;
//! assert_eq!(restored.tasks(), journal.tasks());
//! # Ok::<(), task_journal::Error>(())
//! ```
use std::{
    collections::HashSet,
    fmt,
    fs::{self, File, OpenOptions},
    io::{self, Read, Write},
    path::Path,
};
const MAX_FILE_BYTES: u64 = 1_048_576;
const MAX_TASKS: usize = 10_000;
#[derive(Clone, Copy, Debug, PartialEq, Eq)]
pub enum Status {
    Open,
    Done,
}
#[derive(Clone, Debug, PartialEq, Eq)]
pub struct Task {
    id: u64,
    title: String,
    status: Status,
}
impl Task {
    pub fn id(&self) -> u64 {
        self.id
    }
    pub fn title(&self) -> &str {
        &self.title
    }
    pub fn status(&self) -> Status {
        self.status
    }
}
#[derive(Clone, Debug, Default, PartialEq, Eq)]
pub struct Journal {
    tasks: Vec<Task>,
}
#[derive(Debug)]
pub enum Error {
    Invalid(String),
    NotFound(u64),
    Io(io::Error),
}
impl fmt::Display for Error {
    fn fmt(&self, f: &mut fmt::Formatter<'_>) -> fmt::Result {
        match self {
            Self::Invalid(s) => write!(f, "invalid journal: {s}"),
            Self::NotFound(id) => write!(f, "task {id} does not exist"),
            Self::Io(e) => write!(f, "storage: {e}"),
        }
    }
}
impl std::error::Error for Error {
    fn source(&self) -> Option<&(dyn std::error::Error + 'static)> {
        if let Self::Io(e) = self {
            Some(e)
        } else {
            None
        }
    }
}
impl From<io::Error> for Error {
    fn from(e: io::Error) -> Self {
        Self::Io(e)
    }
}
fn validate_title(title: &str) -> Result<(), Error> {
    if title.trim().is_empty() || title.len() > 200 || title.chars().any(char::is_control) {
        return Err(Error::Invalid(
            "title must contain 1–200 bytes and no control characters".into(),
        ));
    }
    Ok(())
}
impl Journal {
    pub fn tasks(&self) -> &[Task] {
        &self.tasks
    }
    pub fn add(&mut self, title: &str) -> Result<u64, Error> {
        validate_title(title)?;
        if self.tasks.len() >= MAX_TASKS {
            return Err(Error::Invalid("task limit reached".into()));
        }
        let id = self
            .tasks
            .iter()
            .map(|t| t.id)
            .max()
            .unwrap_or(0)
            .checked_add(1)
            .ok_or_else(|| Error::Invalid("identifier space exhausted".into()))?;
        self.tasks.push(Task {
            id,
            title: title.to_owned(),
            status: Status::Open,
        });
        Ok(id)
    }
    pub fn complete(&mut self, id: u64) -> Result<(), Error> {
        let task = self
            .tasks
            .iter_mut()
            .find(|t| t.id == id)
            .ok_or(Error::NotFound(id))?;
        task.status = Status::Done;
        Ok(())
    }
    pub fn remove(&mut self, id: u64) -> Result<(), Error> {
        let position = self
            .tasks
            .iter()
            .position(|t| t.id == id)
            .ok_or(Error::NotFound(id))?;
        self.tasks.remove(position);
        Ok(())
    }
    pub fn encode(&self) -> String {
        let mut output = String::from("TASKS\t1\n");
        for task in &self.tasks {
            let status = match task.status {
                Status::Open => "open",
                Status::Done => "done",
            };
            use std::fmt::Write;
            writeln!(output, "{}\t{status}\t{}", task.id, task.title)
                .expect("writing String cannot fail");
        }
        output
    }
    pub fn decode(input: &str) -> Result<Self, Error> {
        if input.len() as u64 > MAX_FILE_BYTES {
            return Err(Error::Invalid("file exceeds 1 MiB".into()));
        }
        let mut lines = input.lines();
        if lines.next() != Some("TASKS\t1") {
            return Err(Error::Invalid(
                "unsupported or missing format header".into(),
            ));
        }
        let mut journal = Self::default();
        let mut seen = HashSet::new();
        for (offset, row) in lines.enumerate() {
            let fail = || Error::Invalid(format!("malformed row {}", offset + 2));
            let columns: Vec<&str> = row.split('\t').collect();
            let [id, status, title] = columns.as_slice() else {
                return Err(fail());
            };
            let id: u64 = id.parse().map_err(|_| fail())?;
            if id == 0 || !seen.insert(id) || journal.tasks.len() >= MAX_TASKS {
                return Err(fail());
            }
            let status = match *status {
                "open" => Status::Open,
                "done" => Status::Done,
                _ => return Err(fail()),
            };
            validate_title(title)?;
            journal.tasks.push(Task {
                id,
                title: (*title).to_owned(),
                status,
            });
        }
        Ok(journal)
    }
    /// A missing path starts a new journal. Other read errors are preserved.
    pub fn load(path: &Path) -> Result<Self, Error> {
        let file = match File::open(path) {
            Ok(file) => file,
            Err(e) if e.kind() == io::ErrorKind::NotFound => return Ok(Self::default()),
            Err(e) => return Err(e.into()),
        };
        let mut bytes = Vec::new();
        file.take(MAX_FILE_BYTES + 1).read_to_end(&mut bytes)?;
        if bytes.len() as u64 > MAX_FILE_BYTES {
            return Err(Error::Invalid("file exceeds 1 MiB".into()));
        }
        let text =
            std::str::from_utf8(&bytes).map_err(|_| Error::Invalid("file is not UTF-8".into()))?;
        Self::decode(text)
    }
    /// Writes a sibling temporary file then renames it. Designed for one writer.
    /// No locking or parent-directory fsync: not a database durability guarantee.
    pub fn save(&self, path: &Path) -> Result<(), Error> {
        let bytes = self.encode();
        if bytes.len() as u64 > MAX_FILE_BYTES {
            return Err(Error::Invalid("file exceeds 1 MiB".into()));
        }
        let mut temporary_name = path.as_os_str().to_os_string();
        temporary_name.push(format!(".{}.tmp", std::process::id()));
        let temporary = std::path::PathBuf::from(temporary_name);
        let mut file = OpenOptions::new()
            .write(true)
            .create_new(true)
            .open(&temporary)?;
        let result = (|| -> io::Result<()> {
            file.write_all(bytes.as_bytes())?;
            file.sync_all()?;
            drop(file);
            fs::rename(&temporary, path)
        })();
        if result.is_err() {
            let _ = fs::remove_file(&temporary);
        }
        result.map_err(Error::from)
    }
}
#[cfg(test)]
mod tests {
    use super::*;
    #[test]
    fn round_trip_and_transitions() {
        let mut j = Journal::default();
        let a = j.add("read 🦀").unwrap();
        let b = j.add("write tests").unwrap();
        j.complete(a).unwrap();
        j.complete(a).unwrap();
        j.remove(b).unwrap();
        assert_eq!(Journal::decode(&j.encode()).unwrap(), j);
        assert_eq!(j.tasks()[0].status(), Status::Done);
        assert!(matches!(j.complete(99), Err(Error::NotFound(99))));
    }
    #[test]
    fn rejects_corruption_without_partial_success() {
        for input in [
            "TASKS\t2\n",
            "TASKS\t1\n1\topen\tx\n1\tdone\ty\n",
            "TASKS\t1\n0\topen\tx\n",
            "TASKS\t1\n1\tmaybe\tx\n",
            "TASKS\t1\n1\topen\t\n",
        ] {
            assert!(Journal::decode(input).is_err(), "{input}");
        }
        let mut j = Journal::default();
        assert!(j.add(" ").is_err());
        assert!(j.add("one\ntwo").is_err());
        assert!(j.tasks().is_empty());
    }
    #[test]
    fn id_overflow_is_an_error() {
        let mut j = Journal::decode("TASKS\t1\n18446744073709551615\topen\tx\n").unwrap();
        assert!(j.add("next").is_err());
    }
}

Mutation and the useful exclusivity rule

A mutable reference grants exclusive access for the duration of that borrow. You cannot keep two active mutable references to the same collection and use both later. The crucial word is active: the compiler often ends a borrow at its last use rather than at the enclosing closing brace. Read the actual sequence of uses instead of assuming every reference lasts to the end of a function. The second supplied fixture deliberately overlaps two mutable views of the same Vec.

In Journal::complete, iter_mut finds one task and gives exclusive access to that task while its status changes. The method then returns, ending that access before another caller can mutate the journal. This is a small, local ownership story. If an implementation instead returns a mutable Task and then tries to push another task while holding it, Vec reallocation and overlapping access become part of the problem. Prefer completing the mutation inside the method when the caller does not need a long-lived view.

Playbook: a borrow error after adding a task

Observation: code that saves a borrowed title, pushes a new task, and then prints the saved title is rejected. Hypothesis A: Rust forbids printing borrowed text. Hypothesis B: the saved view overlaps mutation of its owning collection. Distinguishing experiment: print the title before the push, leaving the same borrowed type and the same push. Expected result: the borrow ends at its last use, and the reordered sequence can compile. That disproves A and supports B for this control flow.

The smallest sound fix depends on the requirement. If the output must occur before mutation, reordering is enough. If a snapshot must survive mutation, an intentional owned copy is appropriate. If the caller only needs an identifier, store that small value and look up the task again afterward. There is no universal “always clone” or “never clone” repair. Ask an AI reviewer to compare these three requirements and explain the allocation and lifetime tradeoffs before accepting a patch.

When you get stuck: independent work and tiered help

Add a search method in your learner journal that returns borrowed titles containing a query. Decide whether the result should be a Vec of borrowed slices or an iterator. Either can be clear at this stage. Write a test that keeps the journal alive while reading results. Then intentionally try to return those views from a function that constructs a local journal. Explain why the returned references would have no living owner. Repair that second function by returning owned strings if the caller really needs independent results.

Worked solution

accept title: &str, validate it, construct title: title.to_owned(), and expose fn title(&self) -> &str. This creates ownership exactly where persistence is required. A focused review request is “Does this allocation serve a storage requirement, or can the borrow end earlier?” Include the call site because signatures alone may hide the lifetime conflict.

Recommended design and alternatives and mastery

Accepting String and storing it is sound when the API intentionally transfers ownership. The reference accepts &str because callers may keep their input and the storage boundary can make one explicit owned copy. A generic Into<String> constructor can later support both transfer and conversion, but it should be introduced for demonstrated caller needs. Judge these alternatives by allocation, retention, and call-site clarity rather than by the number of generic parameters.

Mastery is the ability to repair both a move error and an overlapping borrow error while explaining the resulting data lifetime. Compiler acceptance establishes that the checked ownership rules hold for safe code in that program. It does not prove task validation, file durability, or performance. Keep those concerns separate so memory safety becomes a reliable foundation rather than an excuse to skip other evidence.
